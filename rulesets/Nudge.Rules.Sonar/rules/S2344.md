# S2344 — Enumeration type names should not have "Flags" or "Enum" suffixes

## Why
`ColorEnum` / `FileAccessFlags` bake the *kind* of type into its name — noise
the `[Flags]` attribute and the declaration already convey. Names should say
what the values represent, not which language construct declares them.

## Do this
1. Rename `XxxEnum` to `Xxx` and `XxxFlags` to `Xxx` (or a meaningful
   singular/plural name for the concept).
2. Let the IDE rename all references mechanically.
3. Check serialization names and stringly-typed consumers (config files, JSON)
   that may depend on the old type name.

## AVOID
- Do not keep the old name alive as a type alias "for compatibility" unless it
   is genuinely public API with external consumers — internal code should just
   be renamed.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S5334 — Dynamic code execution should not be vulnerable to injection attacks

## Why
The analyzer found untrusted data (request input, config values, file contents) flowing into a dynamic code execution sink — a C# snippet compiled at runtime (Roslyn scripting, CSScript), an assembly loaded by attacker-influenced name, or script text executed by the host. Whoever controls that string controls the code that runs, with the full privileges of your process. This is arbitrary code execution, not just a crash.

## Do this
1. Find the flagged sink and trace where its string argument comes from; mark exactly which parts are attacker-influenced.
2. Eliminate the dynamic execution if you can — call a compiled method instead of generating one at runtime.
3. If the dynamic part is a small enumerable set (a template name, a type name), validate it against an explicit allowlist and reject everything else.
4. If free-form text must be embedded, pass it as data through a parameter/variable binding — never concatenate it into the code text.

## AVOID
- Do not "sanitize" by stripping a few keywords (removing `DROP`, `System.`, `;`) — denylists are bypassed trivially; use allowlists or parameterization.
- Do not move the concatenation into a helper or switch to `$""` interpolation — the injection survives string building regardless of syntax.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6608 — Prefer indexing instead of "Enumerable" methods on types implementing "IList"

## Why
Calling `list.First()`, `list.Count()`, or `list.ElementAt(i)` on an
`IList<T>` pays for iterator machinery and interface dispatch to do what
`list[0]`, the `Count` property, and `list[i]` do directly — slower, and it
hides the O(1) random access the type already offers.

## Do this
1. Replace `source.First()` with `source[0]`, `source.Last()` with
   `source[source.Count - 1]`, `source.ElementAt(i)` with `source[i]`, and
   `source.Count()` with the `Count` property.
2. Make the swap only where the static type is `IList<T>` (or otherwise
   indexable), so the semantics stay identical.

## AVOID
- Do not cast or convert to `IEnumerable<T>` first
  (`((IEnumerable<T>)list).First()`) to dodge the rule. That keeps the slow
  path and deliberately throws away the random access the type provides.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

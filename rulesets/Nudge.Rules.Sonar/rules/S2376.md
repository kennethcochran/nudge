# S2376 — Write-only properties should not be used

## Why
A property with only a setter (`public string Password { set; }`) promises
object-like state access but delivers a one-way slot — callers can't read back
what they wrote, which breaks the property idiom. A method communicates
"action" honestly.

## Do this
1. Replace the write-only property with a method whose name says what the
   write does: `SetPassword(string value)`,
   `Configure(Action<Options> configure)`.
2. Only add a getter if the value is genuinely readable state — not a getter
   that throws.

## AVOID
- Do not add a getter that throws `NotImplementedException` (or returns a
  dummy value) to make the property read-write. The property is still
  write-only in practice, and now it also lies about being readable.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

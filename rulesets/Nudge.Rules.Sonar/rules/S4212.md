# S4212 — Serialization constructors should be secured

## Why
**This rule is deprecated and will be removed.** It demanded `SecurityPermission`
demands on deserialization constructors, a Code Access Security mechanism
that .NET Core and .NET 5+ removed entirely. The guidance is for a security
model that no longer exists in the runtime you are targeting.

## Do this
1. Nothing. `SecurityPermission` demands do not compile meaningfully on
   modern targets; adding them to satisfy this rule is cargo-culting a dead
   security model.
2. If you are doing binary deserialization of untrusted data, the real
   issue is the deserialization itself — prefer a safe serializer — but that
   is a different rule's concern, not this one's.
3. If the rule fires in CI, remove S4212 from the active profile.

## AVOID
- Do not add `SecurityPermission` attributes to satisfy this rule. On modern
  .NET they are inert decorations that imply a protection that does not exist —
  worse than no annotation, because the next reader will believe the demand
  is enforced.
- Do not suppress per-occurrence; fix the rule profile once.

# S5445 — Insecure temporary file creation methods should not be used

## Why
Creating temp files with predictable names (`Path.GetTempPath() +
"myapp.tmp"`, `File.Create` on a fixed name) is vulnerable to symlink/TOCTOU
attacks: an attacker pre-creates the path as a symlink to a victim file,
and your process — possibly elevated — writes attacker-influenced data into
it, or reads back attacker-planted content. It's CRITICAL because temp
directories are world-writable by design.

## Do this
1. Use `Path.GetTempFileName()` (or `FileOptions.DeleteOnClose` on a
   `GetTempFileName` path) so the OS generates an unpredictable,
   exclusively-created name.
2. For temp directories, create with a random component and set restrictive
   ACLs immediately after creation.
3. Open with `FileMode.CreateNew` (fails if the path already exists) rather
   than `Create` / `OpenOrCreate` wherever you control the name.

## AVOID
- Do not generate "random" names with `System.Random` or a timestamp and
  concatenate them yourself — predictable randomness is exactly what the
  attack exploits; use the OS facility.
- Do not check `File.Exists` before creating ("check then create") — the
  check and the create are two separate operations and the attacker acts
  between them; that's the TOCTOU the rule is about.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S9415 — Local functions should be marked "static" when they don't capture variables

## Why
A non-static local function implicitly captures the enclosing scope, which
forces the compiler to allocate a closure object on every invocation — even
when the function uses nothing from outside itself. Marking it `static` both
skips that allocation and documents at a glance that the function is
self-contained: it can only touch what is passed in.

## Do this
1. Add the `static` modifier to the local function declaration.
2. If the compiler then reports that the function references an outer
   variable, pass that value as an explicit parameter — the dependency becomes
   visible in the signature.
3. If the function genuinely needs ongoing access to outer mutable state,
   leave it non-static deliberately; the diagnostic only fires when nothing is
   captured.

## AVOID
- Do not "satisfy" the rule by passing the enclosing instance (`this`) as a
  parameter to the static local function just to keep reaching outer state.
  That recreates the hidden coupling as an explicit one and gains nothing —
  pass only the values the function actually needs.
- Do not convert the local function into a lambda stored in a delegate
  (`Func<...>`) to dodge the diagnostic. A delegate allocation is exactly the
  cost the rule is trying to remove.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

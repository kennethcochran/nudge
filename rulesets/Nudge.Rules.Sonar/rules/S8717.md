# S8717 — Multiple "[Key]" attributes should not be used to define a composite key

## Why
Stacking `[Key]` on several properties does not define a composite key in EF
Core — the model builder sees multiple competing keys, so the resulting key
definition is ambiguous or wrong, producing broken migrations and queries.

## Do this
1. Remove the `[Key]` attributes from the entity's properties.
2. Define the composite key once in `OnModelCreating` with the Fluent API:
   `modelBuilder.Entity<OrderLine>().HasKey(e => new { e.OrderId, e.LineNumber })`,
   listing the properties in the correct column order.

## AVOID
- Do not keep the attributes and add `[Column(Order = n)]` to "make it work".
  Column-ordering attributes do not turn multiple `[Key]` attributes into a
  composite key; only the Fluent API `HasKey` call defines one.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

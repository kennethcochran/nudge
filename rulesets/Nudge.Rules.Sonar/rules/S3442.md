# S3442 — "abstract" classes should not have "public" constructors

## Why
An abstract class can never be instantiated directly, so a `public`
constructor promises something impossible. It misleads readers about the API
and suggests to subclass authors that external code can call it — it can't.
The honest accessibility is `protected`: callable by derived classes, by
nobody else.

## Do this
1. Change the constructor's accessibility from `public` to `protected`.
2. If the constructor was public so some factory or test could call it — it
   never could; move that construction logic into a protected constructor or a
   static factory on the abstract class.
3. Check sibling constructors in the same class for the same mistake.

## AVOID
- Do not add a `public static Create()` factory that news up a throwaway
   derived stub just to "use" the public constructor; the constructor remains
   misleading.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

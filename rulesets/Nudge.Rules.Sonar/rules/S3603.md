# S3603 — Methods with "Pure" attribute should return a value

## Why
`[Pure]` declares that a method has no observable side effects and that its
return value is the whole point of calling it. A `void` pure method is a
contradiction — and a pure method whose return value is discarded at every
call site is either mis-annotated or misused. The attribute misleads every
reader and every analyzer about what the method does.

## Do this
1. If the method genuinely has no side effects and computes something, give it
   a return type and return the value; update callers to use it.
2. If the method does have side effects (mutates state, performs I/O), remove
   the `[Pure]` attribute — the annotation is the lie, not the code.
3. Rebuild and run the tests for the affected call sites.

## AVOID
- Do not keep `[Pure]` on a side-effecting method and "use" the return value
   by discarding it (`_ = M();`) — the attribute still misstates the method's
   contract to every reader and tool. Remove the attribute or remove the side
   effects.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

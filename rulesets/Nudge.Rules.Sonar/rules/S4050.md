# S4050 — Operators should be overloaded consistently

## Why
Overloading `==` without `!=` (or `<` without `>`) leaves the type with half a
vocabulary: `a == b` compiles with value semantics while `a != b` silently
falls back to reference inequality, contradicting the equality you just
defined.

## Do this
1. Implement the complementary operators together: `==` with `!=`, `<` with
   `>`, `<=` with `>=`.
2. Override `Equals(object)` and `GetHashCode()` to agree with `==` — the
   compiler warns otherwise, and hash-based collections depend on the
   agreement.

## AVOID
- Do not implement the missing operator as
  `throw new NotImplementedException()`. A "complete set" that explodes at
  runtime is worse than the missing overload — callers get a crash instead of
  a compile-time signal that the operation isn't supported.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

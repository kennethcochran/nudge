# S6667 — Logging in a catch clause should pass the caught exception as a parameter.

## Why
`logger.LogError("operation failed")` inside a `catch` discards the
exception's type, message, and stack trace — the log line records that
*something* failed but never *what* or *where*. The exception object is the
diagnostic payload; logging without it is an incident report with the details
redacted.

## Do this
1. Pass the exception as the first argument:
   `logger.LogError(ex, "Failed to process order {OrderId}", orderId);`
2. Keep the message template static (no string interpolation) so log
   aggregation groups occurrences correctly.
3. Put operation context in structured parameters, not in the message text.

## AVOID
- Do not log `ex.Message` or `ex.ToString()` interpolated into the message
  string — that flattens the exception into unstructured text and loses the
  structured exception data (type, stack frames) the sink could index and
  search.
- Do not log only the exception with an empty message — future readers of the
  log still need to know which operation was being attempted.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1192 — String literals should not be duplicated

## Why
The same string literal repeated in several places is a
silent coupling: changing the value in one place but not the others
introduces bugs, and a reader can't tell whether two identical literals
mean the same thing or just happen to match. A named constant documents
the intent.

## Do this
1. Confirm the duplicated literals represent the same concept (not a
   coincidence — `"OK"` as a status vs `"OK"` as a button label are
   different concepts and deserve different constants).
2. Introduce one `private const string` (or `static readonly` if it must
   be computed) with a name that says what the string means.
3. Replace every occurrence with the constant.

## AVOID
- Do not make the duplicates "different" by tweaking one copy (`"OK"`
  vs `"Ok"`) — the duplication and the coupling remain.
- Do not define the constant separately at each use site; one
  declaration, referenced everywhere.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

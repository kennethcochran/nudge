# S2187 — Test classes should contain at least one test case

## Why
A test class with no tests is dead weight that still gets discovered,
instantiated, and reported by the runner — and it almost always means tests
were deleted, never written, or accidentally left behind in a refactor. An
empty fixture silently claims coverage it doesn't provide.

## Do this
1. Write the missing test(s) covering the class's subject — that's the usual
   story behind an empty fixture.
2. If the class is genuinely obsolete, delete it rather than leaving the
   husk.
3. If it's a base class for other fixtures, make it `abstract` so the runner
   stops treating it as a fixture of its own.

## AVOID
- Do not add a vacuous `Assert.Pass()` / `Assert.That(true)` test "so the
  suite is green" — a test that cannot fail is not a test, it's a
  participation trophy for the build.
- Do not comment out the class "until we write tests" — commented-out code
  rots; delete it and let source control remember it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1125 — Boolean Literals Should Not Be Redundant

## Why
`if (x == true)` says in four tokens what `if (x)` says in two. The
redundancy isn't just noise — it invites the worse bug, `if (x = true)`
in languages where assignment is an expression, and it signals the author
wasn't sure `x` was already a boolean. Clean boolean expressions read as
assertions: `if (connected)`.

## Do this
1. Drop the comparison: `x == true` → `x`, `x == false` → `!x`.
2. If the operand isn't obviously boolean, that's the real problem — make
   the type clear rather than papering over it with `== true`.

## AVOID
- Do not "fix" by extracting `x == true` into a helper like `IsTrue(x)`.
  You've moved the redundancy, not removed it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

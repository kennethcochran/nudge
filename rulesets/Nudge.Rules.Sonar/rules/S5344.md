# S5344 — Passwords should not be stored in plaintext or with a fast hashing algorithm

## Why
Plaintext passwords leak on any database read; fast hashes (MD5, SHA-1,
SHA-256) are brute-forced at billions of guesses per second on commodity GPUs.
Password storage needs a slow, salted, memory-hard function so that each guess
costs the attacker real time and memory.

## Do this
1. Hash with bcrypt, scrypt, Argon2id, or PBKDF2 with a high iteration count,
   each password with its own unique random salt.
2. Verify with the library's constant-time verify routine — never compare hash
   strings yourself.
3. Re-hash on successful login when the stored parameters are below current
   recommendations, so old hashes migrate forward.

## AVOID
- Do not use `SHA256(password)` or `SHA256(salt + password)` — salting a fast
  hash still leaves a fast hash; GPUs don't care about your salt.
- Do not "strengthen" it by hashing twice or appending a global pepper and
  declaring victory — iteration count and memory hardness must come from the
  algorithm, not from home-grown layering.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

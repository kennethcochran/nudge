# S1215 — "GC.Collect" should not be called

## Why
An explicit `GC.Collect()` disrupts the garbage collector's tuned generational
heuristics — it typically makes throughput and pause times *worse*, not
better. Worse, it masks the real problem: a leak (undisposed resources, event
handler roots, pinned buffers) that a forced collection merely postpones.

## Do this
1. Delete the `GC.Collect()` call.
2. If memory pressure is real, find the root cause with a profiler:
   undisposed `IDisposable`s, leaked event subscriptions, pinned or large
   buffers, LOH fragmentation.
3. Measure before and after — memory fixes without numbers are superstition.

## AVOID
- Do not replace it with `GC.Collect(2, GCCollectionMode.Forced)` — more
  forceful is not more correct; it's the same interference with extra
  ceremony.
- Do not move the call into a finalizer, a timer, or a background thread "so
  it's less visible" — hiding the interference doesn't remove it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

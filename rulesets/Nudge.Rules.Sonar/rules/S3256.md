# S3256 — "string.IsNullOrEmpty" should be used

## Why
Hand-rolled null-or-empty checks (`s == null || s ==
""`, `s.Length == 0` without a null check) are verbose, easy to get
subtly wrong (the `Length` version throws on null), and signal "I didn't
know the framework method exists". `string.IsNullOrEmpty` is the
canonical, null-safe check.

## Do this
1. Replace the manual check with `string.IsNullOrEmpty(s)`.
2. If blank/whitespace-only strings should also count as empty for your
   logic, use `string.IsNullOrWhiteSpace(s)` — but decide deliberately;
   the two are not interchangeable.
3. Check the surrounding logic: code that tested `s == ""` separately
   from null often has a branch that can now be simplified.

## AVOID
- Do not rewrite `s == null || s == ""` as `s is null || s ==
  string.Empty` — that's the same manual check with new syntax. Use
  `string.IsNullOrEmpty`.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6419 — Azure Functions should be stateless

## Why
Azure Functions instances are reused across
invocations and scaled out unpredictably. Mutable static state — or
instance fields on the function class, which the host also reuses —
leaks data between invocations, between users, and between scale-out
instances that don't share memory at all. The result is
cross-request contamination that only appears under load.

## Do this
1. Keep per-invocation data in locals and parameters only.
2. Move durable or shared state to external storage: queues, tables,
   blobs, or a database — never in-memory statics.
3. Configuration and genuinely immutable shared data can be static
   `readonly`, initialized once; anything mutated per invocation must
   go.

## AVOID
- Do not move the static field onto the function class as an instance
  field — the host reuses instances, so instance state leaks between
  invocations too.
- Do not hide the mutable state in a singleton "to make it thread-safe"
  — shared mutable state is still shared state; locks don't fix the
  cross-invocation contamination.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

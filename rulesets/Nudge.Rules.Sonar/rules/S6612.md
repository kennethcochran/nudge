# S6612 — The lambda parameter should be used instead of capturing arguments in "ConcurrentDictionary" methods

## Why
In `dict.GetOrAdd(key, k => CreateValue(k))`, the factory lambda already
receives the key as its parameter. Capturing the outer `key` variable instead
(`_ => CreateValue(key)`) allocates a closure on every call for a value that
was being handed to you for free — and it obscures which value the factory
actually depends on.

## Do this
1. Use the lambda's parameter instead of the captured variable:
   `dict.GetOrAdd(key, static k => CreateValue(k))`.
2. Prefer `static` lambdas so the compiler itself enforces that nothing is
   captured.

## AVOID
- Do not keep the capture and merely discard the parameter
  (`_ => CreateValue(key)`). Discarding the parameter while capturing the
  outer variable is exactly the flagged pattern with the evidence renamed —
  the closure allocation and the obscured dependency both remain.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6664 — The code block contains too many logging calls

## Why
A block dense with log calls is usually logging *mechanics* instead of
*decisions* — every loop iteration, every branch entry, every assignment
gets a line, burying the two logs that actually matter for diagnosis.
Beyond noise, excessive logging in hot paths costs real CPU and I/O, and in
production it inflates storage and drowns alerts.

## Do this
1. Keep the logs that mark decisions and state changes (branch taken,
   operation started/finished, errors with context); delete logs that merely
   narrate sequential code.
2. Demote noisy-but-occasionally-useful logs to `Debug` / `Trace` level
   instead of deleting them outright.
3. If a loop logs per iteration, log a summary (count, duration) after the
   loop instead — one line carries the same operational information.

## AVOID
- Do not delete logging indiscriminately to get under the threshold —
  removing the error-path logs that diagnose real failures trades noise for
  blindness.
- Do not concatenate five log calls into one giant interpolated string to
  dodge the count; the fix is fewer, better logs, not one unreadable one.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

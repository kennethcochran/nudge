# S3880 — Finalizers should not be empty

## Why
A finalizer (`~Foo() {}`) — even an empty one — puts every instance on the
finalization queue, delaying collection by a full GC generation for zero
benefit. It's pure GC cost with no cleanup to show for it.

## Do this
1. Delete the empty finalizer.
2. If the type owns unmanaged resources, implement the full dispose pattern:
   `IDisposable` + `Dispose(bool)` + a finalizer that actually releases the
   unmanaged resource.
3. If it only owns managed `IDisposable`s, a plain `Dispose()` with no
   finalizer suffices.

## AVOID
- Do not "fix" it by adding a comment or a no-op statement inside — a
  finalizer empty of *work* still queues every instance; delete it or fill it
  with real cleanup.
- Do not add `GC.SuppressFinalize(this)` in `Dispose` as the "fix" while
  keeping the empty finalizer — the queue cost on the never-disposed path
  remains.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6350 — System command arguments constructed from user input should be validated

## Why
A system-command argument built from user input is the precondition for
argument and command injection: whatever validation the value skipped is
exactly the attacker's room to maneuver. This rule fires on user-controlled
values used as command arguments without prior validation.

## Do this
1. Validate every user-derived argument before it reaches the process: map the input to a fixed set of known-good values, or check it against a strict character allow-list.
2. Pass the validated arguments via ProcessStartInfo.ArgumentList with UseShellExecute = false so no shell ever parses them.
3. Reject non-conforming input outright — fail closed rather than attempting to repair it.

## AVOID
- Do not 'validate' by stripping quotes or trimming whitespace — sanitizing is not validating, and stripped input can still carry metacharacters.
- Do not validate one copy of the value and then pass the raw original to the process; validate the exact string that gets executed.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3949 — Calculations should not overflow

## Why
Integer arithmetic that overflows silently wraps
around in an unchecked context: `int.MaxValue + 1` becomes
`int.MinValue`, and a size/count computation that wraps negative can
turn into a buffer overrun or an infinite loop downstream. The wrap is
silent — no exception, no warning at runtime.

## Do this
1. Find the operation the diagnostic flags and determine the true
   range of the operands.
2. Widen the type *before* operating: cast an operand first
   (`(long)a * b`), not the result — `(long)(a * b)` overflows in `int`
   before the cast runs.
3. Alternatively, do the arithmetic in a `checked` block so overflow
   throws instead of wrapping, or validate operand ranges up front and
   reject/handle values that would overflow.

## AVOID
- Do not cast after the arithmetic — `(long)(a * b)` is the classic
  too-late cast; the overflow already happened.
- Do not wrap the calculation in `unchecked` to silence the analyzer —
  that stamps the wraparound as intentional while the logic still
  assumes the true value.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

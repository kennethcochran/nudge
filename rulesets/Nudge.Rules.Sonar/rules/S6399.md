# S6399 — XML operations should not be vulnerable to injection attacks

## Why
The flagged code builds XML by concatenating strings, so a value containing `<`, `>`, `&`, or quotes breaks out of its intended element or attribute and injects arbitrary markup. Depending on the consumer, that means forged elements, broken signatures, or payloads aimed at downstream parsers. `XElement` and `XmlWriter` escape content automatically; raw string building never does.

## Do this
1. Replace the string-concatenated XML with `XElement`/`XDocument` construction or `XmlWriter`.
2. Let the framework escape user-supplied values; never pre-escape and then concatenate.
3. If the XML comes from object graphs, use `XmlSerializer` with safe settings instead of hand-built XML.

## AVOID
- Do not write your own escaping helper (replacing `<` with `&lt;`) — attribute contexts, quotes, and CDATA sections each need different escaping, and hand-rolled escapers get one of them wrong; the framework already does this correctly.
- Do not split the concatenation across statements or rename variables to dodge the taint tracker — the injection path is unchanged.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2386 — Mutable fields should not be "public static"

## Why
A `public static` mutable field is process-wide global state that anyone can write from anywhere: invisible coupling, race conditions, and untestable code. The rule flags the exposure, not the static lifetime — the problem is that mutation is uncontrolled and unobservable.

## Do this
1. If the value never changes after initialization, make it `public static readonly`.
2. If it must change, expose a property with a private setter (with proper synchronization) — or better, move the state into an instance owned by whoever actually needs it.
3. For collections, expose `IReadOnlyList<T>` or an immutable type rather than a mutable `List<T>` field.

## AVOID
- Do not convert it to an auto-property with a public setter over a mutable static backing field — same global, new syntax.
- Do not mark it `[ThreadStatic]` to dodge the thread-safety angle — that changes semantics to per-thread copies and doesn't fix the global-mutability design problem.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

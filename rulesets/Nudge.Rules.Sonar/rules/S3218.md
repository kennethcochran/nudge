# S3218 — Inner class members should not shadow outer class "static" or type members

## Why
A nested type member with the same name as an outer `static` or type member silently hides it inside the nested scope. Readers — and overload resolution — resolve the name to the inner one, producing bugs that look correct at every glance.

## Do this
1. Rename the inner member so the names no longer collide.
2. If the inner member was meant to expose the outer one, delete it and qualify the reference to the outer member instead.

## AVOID
- Do not add `new` to the inner member to "acknowledge" the shadowing — the confusion remains for every reader.
- Do not fully qualify usages at each call site while keeping the shadow — the trap stays set for the next person who touches the code.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

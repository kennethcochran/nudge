# S5332 — Clear-text protocols should not be used

## Why
Clear-text protocols (HTTP, FTP, Telnet) send
credentials, tokens, and data unencrypted, readable by anyone on the
path. Hard-coding an `http://` or `ftp://` URI bakes the insecure
transport into the code where it's easy to miss in review.

## Do this
1. Change the URI/scheme to the encrypted equivalent (`https://`,
   `sftp://`, SSH-based alternatives) at the flagged site.
2. Verify the server side actually serves the encrypted protocol and
   that redirects don't bounce back to plain HTTP (enable HSTS where
   you control the server).
3. Remove any fallback logic that silently retries over the clear-text
   protocol when the encrypted connection fails.

## AVOID
- Do not just change the port (e.g. plain HTTP on :443) — a different
  port is not encryption.
- Do not keep a "try HTTPS, fall back to HTTP" path; the fallback
  defeats the fix the moment an attacker triggers it.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3443 — Type should not be examined on "System.Type" instances

## Why
The rule fires on code like `someType.GetType()` or
`typeof(Foo).GetType()` — calling `GetType()` on something that's already a
`System.Type`. It's always a logic error: `GetType()` on a `Type` instance
returns `typeof(RuntimeType)`, never the type you were inspecting, so any
comparison built on it (`someType.GetType() == typeof(Foo)`) is silently,
permanently false.

## Do this
1. Drop the `GetType()` call and work with the `Type` instance directly:
   `someType == typeof(Foo)`, or `typeof(Foo).IsAssignableFrom(someType)`
   when inheritance matters.
2. If the intent was "is this object of type Foo", call `GetType()` on the
   *object*, not on its `Type`: `obj.GetType() == typeof(Foo)`.
3. Search for sibling occurrences — this pattern usually comes from copying
   a `GetType()` comparison between object-typed and Type-typed variables.

## AVOID
- Do not cast the `Type` to `object` first (`((object)someType).GetType()`)
  to dodge the analyzer — it still returns `RuntimeType`, just without the
  warning.
- Do not compare `.GetType().Name` strings; the fix is removing the
  spurious call, not stringifying around it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

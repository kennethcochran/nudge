# S2346 — Flags enumerations zero-value members should be named "None"

## Why
In a `[Flags]` enum, the zero value means "no flags set" — the conventional name is `None`, and flag APIs (`default(T)`, `HasFlag`, `ToString`) are written against that convention. Any other name (`Zero`, `Default`, or worse, a real flag name) misleads readers and breaks the `default == None` expectation.

## Do this
1. Rename the zero-valued member to `None`.
2. Update all references to the old name.
3. If the enum has no zero member at all, add `None = 0`.

## AVOID
- Do not add a second zero-valued member named `None` alongside the old one — duplicate values make `ToString`/parsing ambiguous; rename, don't duplicate.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6670 — "Trace.Write" and "Trace.WriteLine" should not be used

## Why
`System.Diagnostics.Trace` writes go to whatever listeners happen to be
attached — in production usually nowhere, in development a debugger window.
Like `Console` logging, it's unlevelled, unfilterable, and invisible to the
logging pipeline; diagnostics written this way are lost exactly when you need
them.

## Do this
1. Replace the `Trace.Write`/`Trace.WriteLine` calls with the project's logging
   abstraction (`ILogger<T>`), at the appropriate level.
2. Preserve any genuinely useful context from the message text; drop
   console-style formatting the logger handles itself.
3. Remove the now-unused `using System.Diagnostics;` if nothing else needs it.

## AVOID
- Do not wrap `Trace.WriteLine` in a static `Diagnostics` helper class and keep
   calling it — the sink is still the trace listeners; use the logging
   abstraction.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

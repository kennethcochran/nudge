# S6421 — Azure Functions should use Structured Error Handling

## Why
In Azure Functions, swallowing exceptions — a catch-all that logs and returns
success — hides failures from the Functions runtime: no retry, no
dead-lettering, no alerting. Poison messages vanish silently while the
dashboard stays green and data is lost.

## Do this
1. Catch only the specific exceptions you can actually handle; let anything
   else propagate so the runtime's retry and poison-queue handling kicks in.
2. If you catch to add context, log and rethrow with a bare `throw;`
   (preserving the stack) rather than returning success.
3. For expected failure modes, use the structured patterns for your trigger
   (e.g. returning a proper error result type) instead of throwing for control
   flow.

## AVOID
- Do not wrap the function body in `catch (Exception) { log; }` and return a
  success result. That converts every failure — including transient ones the
  runtime would have retried — into silent data loss, which is exactly what the
  rule flags.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

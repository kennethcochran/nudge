# S3397 — "base.Equals" should not be used to check for reference equality in "Equals" if "base" is not "object"

## Why
Inside Equals, base.Equals(obj) doesn't mean reference equality unless
base is exactly object — a mid-hierarchy base may override Equals with value
semantics, so the 'reference check' silently becomes a value comparison (or
worse, recurses). This rule flags base.Equals used as a reference-equality
test when base isn't object.

## Do this
1. Use ReferenceEquals(this, obj) — it says exactly what it means and cannot be overridden.
2. Keep the fast-path shape: if (ReferenceEquals(this, obj)) return true; before the type check.
3. Audit the other Equals overrides in the hierarchy for the same pattern.

## AVOID
- Do not 'fix' it with this == obj — == can be overloaded and may itself call Equals; ReferenceEquals is the only unambiguous spelling.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2933 — Field Should Be Readonly

## Why
A field that's only ever assigned in the constructor (or at declaration) but
isn't marked `readonly` is a promise the code doesn't keep. Readers must
consider the possibility that it changes later — every method becomes a
suspect. `readonly` turns "I think this never changes" into a compiler-checked
fact, and it documents the object's immutable shape.

## Do this
1. Add the `readonly` modifier to the field.
2. If the compiler then complains about an assignment elsewhere, that
   assignment is the real finding — decide whether the field is truly meant
   to be mutable (then the rule is a false positive for this case) or the
   assignment is a bug.

## AVOID
- Do not "fix" it by adding a meaningless write somewhere to make the field
  "used as mutable." That's vandalism against the type's design.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3376 — Attribute, EventArgs, and Exception type names should end with the type being extended

## Why
The `...Attribute`, `...EventArgs`, and `...Exception` suffixes are .NET
convention that every consumer relies on: tooling, `catch` readability, and
framework behavior (attribute name resolution strips the `Attribute` suffix)
all assume them. A `Foo` that is really an attribute surprises everyone who
reads or reflects over the code.

## Do this
1. Rename the type to add the suffix (`FooAttribute`, `BarEventArgs`,
   `BazException`) using IDE rename so all references update.
2. For exceptions, take the opportunity to add the standard constructor
   overloads while you're renaming.
3. Rebuild and run the tests.

## AVOID
- Do not "fix" it by adding a second suffixed type that aliases or inherits
   the old unsuffixed name — now there are two names for one concept and the
   old one still violates the convention. Rename the type.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6610 — "StartsWith" and "EndsWith" overloads that take a "char" should be used instead of the ones that take a "string"

## Why
`s.StartsWith("x")` performs a full string comparison — with culture and
comparison-type semantics to get right — where `s.StartsWith('x')` is a single
character check. The char overload states the intent exactly and avoids the
overhead and ambiguity of the string overload.

## Do this
1. Change single-character string literals to char literals:
   `s.StartsWith("/")` becomes `s.StartsWith('/')`,
   `s.EndsWith(";")` becomes `s.EndsWith(';')`.
2. Confirm the literal is exactly one character first; multi-character
   prefixes legitimately stay on the string overload.

## AVOID
- Do not keep the string overload and add an explicit `StringComparison`
  argument (`StartsWith("x", StringComparison.Ordinal)`) to look intentional.
  It still doesn't take the char overload the rule asks for — and for a single
  character, the char overload is both faster and unambiguous.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

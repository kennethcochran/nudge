# S4426 — Cryptographic keys should be robust

## Why
Keys generated with `System.Random`, derived directly from short passwords, or
shorter than the algorithm requires (a 64-bit "AES key") fall to brute force
or are reproducible by anyone who knows the seed. A key is only as strong as
its generation and its length.

## Do this
1. Generate keys with `RandomNumberGenerator.GetBytes` (or the algorithm's own
   `GenerateKey()`), at the full key size the algorithm expects — 128, 192, or
   256 bits for AES.
2. If the key comes from a password, run it through a proper KDF (PBKDF2 via
   `Rfc2898DeriveBytes`, Argon2, or scrypt) with a random salt and a real
   iteration cost — never use the password bytes directly as the key.
3. Remove any hardcoded key material from source; load keys from a vault,
   environment variable, or key store.

## AVOID
- Do not seed `System.Random` with a constant (or `Environment.TickCount`) and
  treat its output as a key. Deterministic output is reproducible by the
  attacker; only a cryptographic RNG produces a key they cannot recompute.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

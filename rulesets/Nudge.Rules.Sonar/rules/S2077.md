# S2077 — SQL queries should not be dynamically formatted

## Why
Concatenating or interpolating values into SQL text lets an attacker break out
of the string literal and run their own statements — the `' OR '1'='1` login
bypass, or stacked queries dropping tables. The rule flags SQL built with
interpolation, `String.Format`, or `+` from non-constant parts.

## Do this
1. Replace the dynamic SQL with a parameterized query: `@p0` placeholders plus
   `SqlParameter` / `DbParameter` objects (or your ORM's parameters).
2. If the query shape itself must vary (dynamic WHERE), build the shape from a
   fixed set of fragments you control, and parameterize every value.
3. For dynamic table or column names, validate against an allowlist of known
   identifiers — never take them raw from input.

## AVOID
- Do not "fix" it by escaping single quotes (`Replace("'", "''")`) — escaping
  is encoding-dependent and brittle; parameters separate code from data
  structurally, which escaping never does.
- Do not switch from interpolation to `StringBuilder.Append` — it's the same
  concatenation with the same hole.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

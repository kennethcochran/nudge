# S2692 — "IndexOf" checks should not be for positive numbers

## Why
`IndexOf` returns -1 for "not found" and 0 for "found at the start". Testing
`> 0` treats a match at position 0 as not-found — a classic off-by-one that
silently drops valid results, e.g. a string that *starts with* the searched
text.

## Do this
1. Change the comparison to `>= 0` (or `!= -1`), matching the "found" contract
   of `IndexOf`.
2. Better: if you only need existence, replace the whole check with
   `Contains(...)` — it says what you mean.
3. Add a test with the needle at position 0; that's the case the old code got
   wrong.

## AVOID
- Do not "fix" the comparison by shuffling the arithmetic
   (`IndexOf(...) + 1 > 0`) — it computes the right answer while hiding the
   intent; write the comparison that matches the API contract.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

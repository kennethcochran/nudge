# S3444 — Interfaces should not simply inherit from base interfaces with colliding members

## Why
When an interface inherits two bases that each declare `void Reset()`, a
consumer can't tell which contract they're satisfying, and implementers get
ambiguity errors or silent wrong-member dispatch. The collision is a design
smell: the two bases promise different things under one name.

## Do this
1. Prefer redesigning: if the members mean different things, rename one; if
   they mean the same thing, extract a shared base interface that declares it
   once.
2. If you must keep both bases, redeclare the member in the derived interface
   with `new` and document which semantics win.
3. Check existing implementers still satisfy the intended contract after the
   change.

## AVOID
- Do not "fix" it by adding `new` to hide the collision without documenting
  which base's semantics the member now carries — the ambiguity moves from the
  compiler to the reader, which is worse.
- Do not break the inheritance and duplicate the member declarations in the
  derived interface — that recreates the collision one level down.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

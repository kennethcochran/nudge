# S6803 — Parameters with SupplyParameterFromQuery attribute should be used only in routable components

## Why
**This rule is deprecated and will be removed.** It is Blazor-specific:
`[SupplyParameterFromQuery]` on a non-routable component is silently ignored
by the framework, so the parameter never receives a value. If you are not in
a Blazor project, this rule cannot fire meaningfully; if you are, the
framework has since made the behavior explicit.

## Do this
1. If the component is meant to be routable, add the `@page` directive —
   the attribute then works as intended.
2. If the component is not routable, remove the attribute; the parameter was
   never being populated, so removing it changes no behavior.
3. If the rule fires in CI outside Blazor code, remove S6803 from the active
   profile.

## AVOID
- Do not add a `@page` route to a component just to satisfy the rule when
  the component was never meant to be a page. A spurious route is a new
  public URL surface created to silence a deprecated finding.
- Do not suppress per-occurrence; fix the rule profile once.

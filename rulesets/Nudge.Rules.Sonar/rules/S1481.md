# S1481 — Unused local variables should be removed

## Why
A declared-but-never-read local is dead weight that misleads readers into
thinking it matters — and it often signals a forgotten step, a computed value
that was supposed to be used somewhere.

## Do this
1. If the variable is genuinely unneeded, delete the declaration (and the
   computation too, if it has no side effects).
2. If the right-hand side has side effects you need (a method call that must
   run), call it as a bare statement without assigning the result — or use a
   discard (`_ = ...`) if the value is intentionally ignored.
3. If the variable was meant to be used, wire it in where it belongs instead
   of deleting it — the diagnostic may be pointing at a real omission.

## AVOID
- Do not silence the rule by referencing the variable in a meaningless
  statement — a stray `Console.WriteLine(x)`, a no-op use with no side effects
  to preserve. If nothing needs the value, delete the variable; a fake use
  just hides the dead code.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

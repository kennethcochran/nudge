# S2996 — "ThreadStatic" fields should not be initialized

## Why
`[ThreadStatic]` field initializers run exactly once — on whichever thread
happens to trigger the type initializer. Every other thread sees `default(T)`,
so the "initial value" is a lie for all but one thread, and the bug only
shows up under concurrency.

## Do this
1. Remove the field initializer.
2. Initialize lazily on first use *per thread* (check for the default value
   and assign), or
3. Replace the field with `ThreadLocal<T>(() => initialValue)`, which runs the
   factory once per thread — the semantics the initializer pretended to have.

## AVOID
- Do not add a static constructor that assigns the `[ThreadStatic]` field —
  it runs once, on one thread, which is exactly the broken semantics the rule
  flags.
- Do not "fix" it by initializing the field at the start of every method that
  uses it — that's per-call, not per-thread, and it wipes state other code on
  the same thread may be relying on.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

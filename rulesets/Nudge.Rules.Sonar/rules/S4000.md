# S4000 — Pointers to unmanaged memory should not be visible

## Why
Exposing raw pointers (`int*`, `void*`) in public API
forces every caller into `unsafe` code, defeats the GC's lifetime
tracking (a pointer can dangle after the memory is freed), and makes
the safe/unsafe boundary the caller's problem instead of yours. The
interop layer should own the unsafety.

## Do this
1. Keep pointers private to the interop boundary that needs them.
2. Expose safe abstractions instead: `SafeHandle` derivatives for
   owned native resources, `Span<T>`/`Memory<T>` for buffers, or a
   managed wrapper type that owns the lifetime.
3. If the pointer must cross a boundary internally, document the
   lifetime contract at that boundary and keep it out of public
   signatures.

## AVOID
- Do not wrap the raw pointer in `IntPtr`/`nint`/`UIntPtr` and expose
  that instead — it's the same unmanaged pointer with a struct around
  it; the lifetime and safety problems are unchanged.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

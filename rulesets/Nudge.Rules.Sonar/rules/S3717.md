# S3717 — Track use of "NotImplementedException"

## Why
`NotImplementedException` is a placeholder that made it
to production: every call site is a landmine that throws at runtime
instead of failing at compile time. The rule tracks them so they get
implemented or removed — not left as permanent fixtures.

## Do this
1. Implement the member for real.
2. If it genuinely can't be implemented yet, keep the throw but leave a
   TODO referencing the tracking ticket, and make sure the unfinished
   surface is as small as possible.
3. If the member will never be implemented, remove it (and its
   interface obligation, if the design allows) rather than shipping a
   stub.

## AVOID
- Do not swap `NotImplementedException` for `NotSupportedException`
  or `return default(T)` to quiet the tracker — a stub that pretends to
  work (or throws a different exception for the same unfinished code) is
  worse than an honest placeholder.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3265 — Non-flags enums should not be used in bitwise operations

## Why
Bitwise `|`, `&`, `^` on an enum without `[Flags]` produces values that aren't valid members — the result is meaningless to readers and to any `switch` or validation over the enum. It's a type error the compiler can't see.

## Do this
1. If the values are meant to combine, mark the enum `[Flags]` and give the members powers-of-two values.
2. If they're exclusive choices, replace the bitwise operation with the correct comparison or branching (`==`, `!=`, or a `switch`).

## AVOID
- Do not slap `[Flags]` on the enum while leaving sequential values (0, 1, 2, 3) — combined values still collide with named members; fix the values too.
- Do not cast to `int`, do the bitwise math, and cast back — the invalid-value problem survives the casts.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

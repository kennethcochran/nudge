# S2688 — "NaN" should not be used in comparisons

## Why
By IEEE 754, `NaN != NaN` — so `x == double.NaN` is *always false*. The check
never fires, NaN values slip through silently, and downstream math propagates
the NaN into results that look plausible but are garbage.

## Do this
1. Replace `x == double.NaN` with `double.IsNaN(x)` (and `x != double.NaN`
   with `!double.IsNaN(x)`).
2. Search the file for other NaN comparisons, including `float.NaN` — the
   same rule applies via `float.IsNaN`.
3. Add a test that pushes NaN through the path to prove the check now fires.

## AVOID
- Do not "fix" it by comparing `x.ToString() == "NaN"` — culture-dependent,
   slow, and absurd. Use `double.IsNaN` / `float.IsNaN`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

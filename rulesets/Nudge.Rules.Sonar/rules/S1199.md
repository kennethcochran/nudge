# S1199 — Nested code blocks should not be used

## Why
A bare `{ ... }` block inside a method body — not attached to an `if`,
loop, or `try` — adds a nesting level that scopes nothing meaningful.
Readers assume a block implies a construct (a missing `if`? a leftover from
a deleted loop?) and waste attention resolving the ambiguity; it's usually
debris from an edit that removed the enclosing statement.

## Do this
1. Delete the braces, keeping the statements at the surrounding indentation
   level.
2. If the block was scoping a variable to avoid a name clash, rename the
   variable instead — the block was treating the symptom.
3. If the block was visually grouping related statements, replace it with a
   comment or extract a method; braces are not a grouping construct.

## AVOID
- Do not attach the block to a dummy construct (`if (true) { ... }`) to
  give it a "reason" — that's the same nesting with a lie on top.
- Do not leave the block and add a comment explaining it's intentional;
  intentional or not, it reads as a leftover.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

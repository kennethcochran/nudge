# S3416 — Loggers should be named for their enclosing types

## Why
The rule fires when a logger's category name doesn't match the class that
owns it — e.g. `CreateLogger("MyApp")` inside `OrderService`, or
`ILogger<WrongType>` injected. Log filtering and routing in .NET is
category-based, so a misnamed logger sends that class's logs to the wrong
filter bucket: they get silenced by filters meant for another component or
flood a category nobody watches.

## Do this
1. Prefer constructor injection of `ILogger<EnclosingType>` — the generic
   argument becomes the category automatically and can't drift.
2. If creating manually, call `loggerFactory.CreateLogger<EnclosingType>()`
   rather than the string overload.
3. After the change, grep for the old category string to make sure no filter
   configuration still references it.

## AVOID
- Do not keep the string overload and just fix the string to match — string
  categories drift again the next time the class is renamed; the generic
  form is rename-proof.
- Do not share one static logger instance across multiple classes under a
  single category; per-class categories are the point.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

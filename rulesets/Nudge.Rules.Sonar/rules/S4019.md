# S4019 — Base class methods should not be hidden

## Why
A derived method that hides a base member (same signature, no `override` or
`new`) usually means the author intended a polymorphic override but got
shadowing instead: calls through a base-typed reference silently run the base
implementation, a behavior split invisible at the call site.

## Do this
1. If you intended polymorphism, mark the base method `virtual` (if you own
   it) and the derived one `override`.
2. If hiding is genuinely intended (rare), make it explicit with the `new`
   modifier plus a comment explaining why shadowing — not overriding — is
   correct here.

## AVOID
- Do not slap `new` on the method just to silence the compiler warning when
  the intent was polymorphic. The warning disappears but the behavior split
  remains: base-typed callers still get the base implementation. Fix the
  polymorphism, not the warning.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1607 — Tests should not be ignored

## Why
An ignored test (`[Ignore]`, `[Explicit]`, `Assert.Ignore()`) is a test the suite pretends to have: CI stays green while the covered behavior rots untested. Ignores accumulate because they're easier than fixing the test, and each one is a coverage hole nobody triages.

## Do this
1. Fix the underlying problem (flakiness, changed behavior, broken setup) and re-enable the test.
2. If the behavior the test covered no longer exists, delete the test deliberately — an honest deletion beats a silent ignore.
3. If it's environment-dependent, gate it with a proper category or condition rather than a blanket ignore.

## AVOID
- Do not convert the ignore into a conditional skip that always skips (`if (true) Assert.Ignore()`) — same dead test, new costume.
- Do not delete the test to silence the rule when the behavior still matters — that's the same coverage loss without the paper trail.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

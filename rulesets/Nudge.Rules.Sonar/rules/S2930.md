# S2930 — "IDisposables" should be disposed

## Why
A locally-created `IDisposable` that's never disposed leaks whatever it
holds — file handles, sockets, DB connections, GDI objects — until the
finalizer (if any) runs, which for many resources is never or far too late.
Under load, undisposed disposables exhaust pools and handles, producing
failures far from the leak.

## Do this
1. Wrap the resource in a `using` declaration or `using` statement so
   disposal happens on all paths, including exceptions.
2. If the disposable must outlive the method, transfer ownership explicitly:
   return it, store it in a field, and make the owning type `IDisposable`
   itself so the chain is unbroken.
3. For `async` methods with `IAsyncDisposable` resources, use
   `await using`.

## AVOID
- Do not call `.Dispose()` only at the end of the happy path — an exception
  mid-method skips it; that's exactly what `using` is for.
- Do not "dispose" by calling `.Close()` and assuming equivalence; some
  types' `Close` doesn't release everything `Dispose` does, and the analyzer
  still flags it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

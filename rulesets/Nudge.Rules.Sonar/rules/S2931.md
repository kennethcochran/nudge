# S2931 — Classes with "IDisposable" members should implement "IDisposable"

## Why
A field holding an `IDisposable` (stream, timer, subscription, `HttpClient`)
owns a resource that must be released. If the containing class doesn't
implement `IDisposable` and dispose the member, the resource leaks — handles
stay open, timers keep firing, and finalizers may never run to clean up.

## Do this
1. Implement `IDisposable` on the containing class.
2. In `Dispose()`, dispose every owned `IDisposable` member (and call
   `GC.SuppressFinalize(this)` if the class has a finalizer).
3. Decide ownership explicitly: if the class does *not* own the member (it was
   injected and outlives this object), document that — but the default is: you
   hold it, you dispose it.

## AVOID
- Do not write an empty `Dispose()` method just to satisfy the interface — an
   empty `Dispose` leaks exactly as before; dispose the members.
- Do not dispose only *some* of the disposable members; audit every field.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2345 — Flags enumerations should explicitly initialize all their members

## Why
In a `[Flags]` enum, auto-incremented values (`Read, Write, Execute` becoming
0, 1, 2) destroy bit semantics: combined flags collide with other members'
values and `HasFlag` starts lying. Every member needs an explicit power of
two for bitwise composition to work.

## Do this
1. Assign every member an explicit value: `None = 0`, then `1, 2, 4, 8, ...`
   (bit shifts like `1 << 3` are fine if clearer).
2. Double-check any combined or "all" members (e.g. `All = Read | Write`)
   still equal the OR of exactly the intended bits.

## AVOID
- Do not assign an explicit value to only the first member (or only
  `None = 0`) and leave the rest auto-incremented. The analyzer checks every
  member; partial initialization leaves the same bit-collision bug in the
  remaining members.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

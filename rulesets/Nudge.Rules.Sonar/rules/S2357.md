# S2357 — Fields should be private

## Why
Public (or protected/internal) fields are mutable, unvalidatable,
un-interceptable state: no breakpoint on write, no invariant check, no lazy
init — and every consumer compiled against the field breaks if the
representation ever needs to change. This rule flags non-private fields.

## Do this
1. Make the field private and expose it through a property — an auto-property if no logic is needed today; the property is the seam for tomorrow.
2. If it's effectively a constant, make it const or static readonly instead of an exposed field.
3. Update all direct field accesses to go through the property; the compiler will find them.

## AVOID
- Do not change public to internal and call it encapsulated — it's still a mutable field to every type in the assembly, with all the same problems.
- Do not add a property wrapper while leaving the field public beside it; consumers will keep using the field.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

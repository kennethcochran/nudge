# S9023 — "Include" calls discarded by query reshaping should be fixed

## Why
The rule fires when EF Core's `.Include()` is followed by a reshaping
operation (a `Select` projection, `GroupBy`, etc.) that discards the
include — EF silently ignores the eager load, so the query either N+1s at
materialization time or returns entities without the navigation data you
assumed was loaded. It's a CRITICAL bug because the code compiles and runs;
it's just slower or wrong.

## Do this
1. Decide what the query must return. If you project into a DTO, project
   the navigation properties explicitly inside the `Select`
   (`.Select(o => new Dto { Items = o.Items.Select(...) })`) and delete the
   dead `Include`.
2. If you need tracked entities with their navigations, remove the reshaping
   operation so the `Include` actually applies.
3. Re-run the query path in a test and assert the navigation data is
   populated — the failure mode is silent, so verify behavior, not just
   compilation.

## AVOID
- Do not move the `Include` after the `Select` hoping ordering matters — a
  reshaped query discards includes regardless of position.
- Do not stack extra `Include` / `ThenInclude` calls to "force" the load;
  dead includes don't become live by multiplication.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

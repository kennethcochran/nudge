# S2325 — Method Should Be Static

## Why
An instance method that never touches instance state is lying about what it
needs. Callers must construct an object to call it, readers assume it depends
on the object's state, and test setup grows for no reason. Making it `static`
says exactly what it is: a pure function of its arguments.

## Do this
1. Add the `static` modifier. Update call sites if needed.
2. If making it static feels wrong — if it *should* depend on instance
   state — that's the real design question. Either the method is missing its
   use of `this` (a latent bug) or the rule is a false positive for a method
   kept non-static for polymorphism. Decide explicitly.

## AVOID
- Do not add a spurious reference to `this` (e.g. touching a field you don't
  need) just to keep the method non-static. You've coupled the method to
  instance state for no reason.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

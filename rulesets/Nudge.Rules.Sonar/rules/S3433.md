# S3433 — Test method signatures should be correct

## Why
A test method with the wrong signature — `async void`,
non-public, parameters without a data source — either never runs (the
runner silently skips it, so you have a test that tests nothing) or
fails in confusing ways. A test that doesn't run is worse than no test:
it pretends to cover code.

## Do this
1. Make the method `public` (as your test framework requires).
2. Async tests must return `Task`, never `async void` (an `async void`
   test can't be awaited, so failures surface unpredictably).
3. Parameters are allowed only with a data-source attribute
   (`[TestCase]`, `[DataRow]`, …); otherwise remove them.
4. After fixing, run the test and confirm the runner actually executes
   it (check the test count went up).

## AVOID
- Do not remove the `[Test]` attribute from the broken test to make
  the diagnostic go away — that hides the test instead of fixing it.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

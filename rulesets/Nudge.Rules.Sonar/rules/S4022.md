# S4022 — Enumerations should have "Int32" storage

## Why
An explicit underlying type on an enum (: byte, : short) opts out of the
CLS-friendly Int32 default for no benefit in pure managed code — it
complicates interop assumptions, serialization sizes, and every consumer's
expectations. This rule flags non-Int32 enum storage.

## Do this
1. Remove the explicit underlying type unless a concrete consumer requires it (native interop layout, a serialized wire format, or values exceeding Int32).
2. If interop does require it, document which consumer and keep the annotation — the rule is a nudge, not a law, but the justification must be written down.
3. Check switch statements and casts after removal; Int32 is the default, so pure-managed behavior shouldn't change.

## AVOID
- Do not 'fix' it by writing ': int' explicitly — that is the default spelled redundantly; just drop the annotation.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

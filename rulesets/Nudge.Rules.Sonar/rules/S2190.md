# S2190 — Loops and recursions should not be infinite

## Why
A `while (true)` with no reachable `break`, or a recursive method that always
recurses, never returns — it hangs the thread or blows the stack. The analyzer
flags loops and recursions where it cannot find any exit path, which means a
termination condition is missing or unreachable.

## Do this
1. Identify the condition under which the loop or recursion is supposed to
   stop, and make it explicit: a loop condition, a reachable `break`/`return`,
   or a base case the recursion provably reaches.
2. For recursion, verify the argument actually shrinks toward the base case on
   every code path, not just the happy path.

## AVOID
- Do not add a `break` or base-case check that is unreachable (e.g.
  `if (false) break;`, or a base case comparing the wrong variable). An exit
  path the code can never take is still an infinite loop — the termination
  condition must be reachable and must actually terminate.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

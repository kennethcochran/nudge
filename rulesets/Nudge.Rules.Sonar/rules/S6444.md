# S6444 — Regular expressions should be executed with a timeout

## Why
A regex with catastrophic backtracking on hostile input hangs the executing
thread indefinitely — a one-line ReDoS that can take down a request handler.
.NET regexes run with no timeout unless you explicitly ask for one, so any
regex touching untrusted input is exposed by default.

## Do this
1. Use the `Regex` overloads that accept a `TimeSpan` match timeout on every
   regex executed against untrusted input, e.g.
   `Regex.IsMatch(input, pattern, RegexOptions.None, TimeSpan.FromMilliseconds(100))`.
2. Alternatively, set the AppDomain-wide default once via
   `AppDomain.CurrentDomain.SetData("REGEX_DEFAULT_MATCH_TIMEOUT", TimeSpan.FromMilliseconds(100))`
   if many call sites are involved.
3. Pick a timeout that fails fast relative to the operation — tens to low
   hundreds of milliseconds on a request path — and handle
   `RegexMatchTimeoutException` where the match result matters.

## AVOID
- Do not pass an absurdly long timeout (hours, `Timeout.InfiniteTimeSpan`)
  just to satisfy the analyzer. The timeout *is* the protection; a value no
  real input will ever hit is the same as having no timeout at all.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

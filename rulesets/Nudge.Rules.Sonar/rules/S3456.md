# S3456 — "string.ToCharArray()" and "ReadOnlySpan<T>.ToArray()" should not be called redundantly

## Why
`string.ToCharArray()` allocates a fresh `char[]` to satisfy APIs that already
accept `string` or `ReadOnlySpan<char>` — a copy nobody asked for. Calling
`.ToArray()` on a `ReadOnlySpan<T>` is the same mistake one level down: it
copies a span that was already the span you needed.

## Do this
1. Pass the string directly wherever `string` or `ReadOnlySpan<char>` is
   accepted — drop the `.ToCharArray()`.
2. Drop `.ToArray()` on `ReadOnlySpan<T>`; the span itself is the value to
   pass along.
3. Keep the copy only where the callee genuinely requires an array *and*
   mutates it — then the allocation is real, not redundant.

## AVOID
- Do not assign the span to a local and then call `.ToArray()` on it "to be
  safe" — that is precisely the allocation the rule tells you to remove.
- Do not replace `.ToCharArray()` with `new string(...)` round-trips or manual
  char loops — the fix is passing the string/span through, not a different
  copy.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

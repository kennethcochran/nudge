# S3996 — URI properties should not be strings

## Why
A string-typed "URI" accepts `"not a uri"` at compile time and pushes
validation onto every consumer — each one parsing, each one handling failure
differently. The `Uri` type validates once at construction and then gives you
parsing, combining, and escaping for free, everywhere.

## Do this
1. Change the property type to `Uri` (or keep a string at the serialization
   boundary and convert immediately inside).
2. Parse and validate once, at the boundary where the value enters the
   system.
3. Use `Uri.TryCreate` where invalid input is expected and must be handled
   gracefully.

## AVOID
- Do not keep the string property and validate it with a regex at each use
  site. That is N validators instead of one type — and a regex is a poor
  substitute for real URI parsing anyway.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

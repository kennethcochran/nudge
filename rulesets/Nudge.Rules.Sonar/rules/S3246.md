# S3246 — Generic type parameters should be co/contravariant when possible

## Why
An interface like IProcessor<T> that only ever produces T (or only ever
consumes it) can declare 'out T' / 'in T', unlocking safe implicit
conversions — IProcessor<Derived> usable as IProcessor<Base> — that callers
otherwise work around with casts or wrapper types. This rule flags type
parameters that could be variant.

## Do this
1. Add 'out' (covariant) when T appears only in output positions (return types, read-only properties), 'in' (contravariant) when only in input positions (method parameters).
2. If T appears in both positions, variance isn't available — that's a design fact, not a fix. Consider splitting the interface (e.g. IReader<out T> / IWriter<in T>).
3. Re-check after adding: variant interfaces compose, so downstream casts may simplify away.

## AVOID
- Do not force 'in'/'out' onto a parameter used in both positions to silence the rule — it won't compile, and the real fix is splitting the interface, not annotating harder.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

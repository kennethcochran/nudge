# S125 — Sections of code should not be commented out

## Why
Commented-out code is dead code with a pulse: it rots (references renamed
symbols, contradicts current logic), it confuses readers ("is this
temporarily disabled or permanently dead?"), and it bloats every file it
haunts. Version control already keeps the old code — the comment is a worse,
unversioned copy of what `git log` does properly.

## Do this
1. Delete the commented-out block. If you might need it, that's what
   history is for — note the commit hash in your own notes, not in the
   source.
2. If the block explains *why* something isn't done a certain way, convert
   it into a prose comment stating the reason — keep the insight, delete
   the code.
3. If the code is "temporarily" disabled for debugging, use a feature flag
   or a local stash; don't commit it commented out.

## AVOID
- Do not move the commented-out code into a `#region` labeled "old" or
  "unused" — that's a mausoleum, not a fix.
- Do not "fix" it by uncommenting the code to make the rule stop firing;
  dead code that's live is a bug, not a cleanup.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

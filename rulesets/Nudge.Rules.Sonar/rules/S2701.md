# S2701 — Literal boolean values should not be used in assertions

## Why
`Assert.AreEqual(true, result)` asserts against a hardcoded value — when it
fails you learn nothing about what `result` should have been, and when someone
"fixes" the test they just flip the literal. Assert the meaningful condition,
not a constant.

## Do this
1. Replace the literal with the actual expected expression:
   `Assert.AreEqual(expectedStatus, result)` — or better, assert the property
   directly.
2. If the test checks a boolean-returning method, name what `true` means:
   `Assert.True(order.IsPaid)`.

## AVOID
- Do not "fix" it with `Assert.True(1 == 1)` or `Assert.AreEqual(true, true)` —
  tautologies that pass forever and verify nothing.
- Do not extract the literal to a `const bool Expected = true;` — same
  hardcoded value, one indirection away.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

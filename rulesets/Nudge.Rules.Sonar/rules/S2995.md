# S2995 — "Object.ReferenceEquals" should not be used for value types

## Why
`ReferenceEquals` boxes both value-type arguments, so it compares the identity
of two fresh boxes — always `false` — while allocating for the privilege. For
value types there is no meaningful reference identity to test; the call is
always wrong.

## Do this
1. Use `==` or `.Equals()` for value-type comparison.
2. For "is this the default value" checks, use
   `EqualityComparer<T>.Default.Equals(x, default)`.
3. Reserve `ReferenceEquals` for genuine reference-identity checks on
   reference types — the one thing it actually does.

## AVOID
- Do not cast to `object` first "to make ReferenceEquals work" —
  `(object)x` is the boxing the rule is complaining about; the cast doesn't
  fix it, it *is* it.
- Do not replace it with `x.Equals((object)y)` on a type without a proper
  `Equals` override — you'll get reference equality on the boxes, the same
  always-false answer with extra steps.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1699 — Constructors should only call non-overridable methods

## Why
Calling a virtual method from a constructor invokes the most-derived override
*before* the derived constructor has run — the override executes against
uninitialized derived state. This is a classic source of null-reference and
logic bugs that only manifest in subclasses, far from the code that caused
them.

## Do this
1. If the polymorphic behavior isn't needed during construction, make the
   called method non-virtual (`sealed`, `private`, or `static`).
2. If derived classes must customize construction, restructure: pass the
   needed values as constructor parameters, or use a static factory method
   that constructs the object fully and *then* calls the virtual method.
3. Re-run the subclass tests — this bug class hides in derived types, not in
   the base.

## AVOID
- Do not "fix" it by adding null-guards inside the override so it survives
   being called early — the object is still half-constructed and the
   override's invariants don't hold. Don't call virtuals from constructors,
   period.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

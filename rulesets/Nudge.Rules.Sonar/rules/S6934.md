# S6934 — A Route attribute should be added to the controller when a route template is specified at the action level

## Why
An action-level route template like `[HttpGet("items/{id}")]` with no `[Route]` on the controller produces a root-level route: it's easy to collide with other controllers' routes and hard to discover, because the controller's route prefix — the namespace that keeps action routes organized — is missing.

## Do this
1. Add `[Route("[controller]")]` (or `[Route("api/[controller]")]`) to the controller class.
2. Verify the combined routes still match the intended URLs: controller prefix + action template.
3. Check for collisions with other controllers' routes after adding the prefix.

## AVOID
- Do not move the action's template (including its `{id}` parameters) up to the controller and leave the action bare — keep each route segment where it belongs; the action template describes the action.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

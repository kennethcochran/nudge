# S3215 — "interface" instances should not be cast to concrete types

## Why
Downcasting an interface to a concrete implementation welds the consumer to
one implementation and defeats the abstraction the interface was created
for. It also throws `InvalidCastException` the moment a decorator, proxy, or
test mock stands in for the real thing.

## Do this
1. If the consumer needs the member, promote it to the interface — that is
   what interfaces are for.
2. If only some implementations support it, define a narrower interface and
   pattern-match with a graceful fallback.
3. If genuinely only one implementation can ever exist, question whether the
   interface earns its keep.

## AVOID
- Do not replace the direct cast with `as` plus a null check. That is the
  same coupling to the concrete type, except the failure mode is a
  `NullReferenceException` later instead of an `InvalidCastException` now.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

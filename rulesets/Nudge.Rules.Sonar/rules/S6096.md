# S6096 — Extracting archives should not lead to zip slip vulnerabilities

## Why
Archive entries carry their own paths, and a malicious archive can contain entries like `../../evil.exe`. The flagged extraction loop writes each entry without verifying that the resolved destination stays inside the target directory — so extracting an untrusted archive writes files anywhere the process can write. This is a path traversal with a BLOCKER severity for a reason.

## Do this
1. For each entry, canonicalize the destination: `Path.GetFullPath(Path.Combine(destinationDir, entryPath))`.
2. Verify the canonical path starts with the full destination directory path plus a directory separator; skip the entry (or abort the extraction) if it does not.
3. Keep the check in your extraction loop even when using third-party libraries (SharpZipLib, etc.) — the library does not do this for you.

## AVOID
- Do not "fix" it with `entryPath.Contains("..")` — absolute paths and encoded traversals (`..%2f`, `....//`) sail past substring checks; canonicalize with `GetFullPath` first, then compare.
- Do not strip `../` prefixes with `Replace` — `....//` collapses into `../` after one replacement pass; reject or skip the entry instead.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

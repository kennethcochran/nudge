# S3466 — Optional parameters should be passed to "base" calls

## Why
When an override calls `base.Method()` without passing its optional
parameters, the base's defaults apply. If the base later changes a default,
the override silently diverges from callers who pass the values explicitly —
two call paths, two behaviors, one signature.

## Do this
1. In the override, pass every optional parameter explicitly to the base call:
   `base.Method(a, b: b)`.
2. Keep the override's default values identical to the base's.

## AVOID
- Do not "fix" it by removing the optional parameters from the override —
  that breaks callers relying on them; pass them through instead.
- Do not redeclare different defaults in the override — C# resolves defaults
  at the caller's compile time by static type, so divergent defaults are a
  trap, not a feature.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

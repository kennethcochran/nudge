# S7039 — Content Security Policies should be restrictive

## Why
The flagged Content Security Policy contains `unsafe-inline`, `unsafe-eval`, wildcards, or bare `*` in `script-src` — which lets injected scripts execute even where output encoding missed something. CSP is the last line of defense against XSS; a permissive policy neutralizes it while looking like protection is in place.

## Do this
1. Remove `unsafe-inline` and `unsafe-eval` from `script-src`/`style-src`; move inline scripts to external files or use nonces/hashes.
2. Replace wildcard hosts with the explicit origins the app actually loads resources from.
3. Set a restrictive `default-src` (e.g. `'self'`) and add `object-src 'none'` and `base-uri 'self'`.
4. Validate in report-only mode first, then enforce — and re-test the app's real pages.

## AVOID
- Do not "fix" it by moving the same permissive policy into a `<meta>` tag — the values are the problem, not the delivery mechanism.
- Do not add `unsafe-inline` back "temporarily" to make a widget work; use a nonce or hash for that specific script.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3927 — Serialization event handlers should be implemented correctly

## Why
Serialization event handlers ([OnSerializing], [OnSerialized],
[OnDeserializing], [OnDeserialized]) are discovered by signature: they must
return void, take exactly one StreamingContext parameter, and be non-static
and non-generic. A handler with the wrong shape is silently never called, so
your fixup-on-deserialize logic doesn't run and nobody tells you. This rule
flags malformed handlers.

## Do this
1. Give the handler the exact required shape: void MethodName(StreamingContext context), any accessibility, non-static, non-generic, with the correct attribute.
2. After fixing, verify it actually fires — a quick round-trip serialization test catches the silent skip.
3. If the type has several handlers, check each one; the rule reports them one at a time.

## AVOID
- Do not swap the attribute to match the wrong signature — the method still never runs; fix the signature.
- Do not add the StreamingContext parameter but leave a non-void return or a static modifier; the whole contract must match, not one piece of it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

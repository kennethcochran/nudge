# S3217 — "Explicit" conversions of "foreach" loops should not be used

## Why
foreach (Derived d in baseCollection) compiles but inserts a hidden cast
per element: the first element of an unexpected type throws InvalidCastException at runtime, far from where the collection was filled. This rule flags foreach loops whose explicit element type differs from the collection's.

## Do this
1. Make the cast explicit and deliberate: use .OfType<T>() to filter or .Cast<T>() to assert, so the conversion is visible at the call site.
2. Better, fix the collection's declared type so no cast is needed at all.
3. If heterogeneous elements are legitimate, handle the mismatch explicitly instead of letting the loop throw.

## AVOID
- Do not wrap the loop in try/catch (InvalidCastException) — you would be catching a bug you planted instead of removing it.
- Do not change the loop variable to var and cast inside the body; the hidden cast just moved one line down.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

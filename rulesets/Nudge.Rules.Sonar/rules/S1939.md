# S1939 — Inheritance list should not be redundant

## Why
Listing a base class or interface that's already inherited
(`class D : B, IB` where `B : IB`) states the same relationship twice. The
duplicate entry misleads readers into thinking `D` adds its own
implementation, and if the hierarchy later changes, the redundant entry can
silently change meaning or just rot.

## Do this
1. Remove the redundant entry from the inheritance list, keeping the
   most-derived base class.
2. If the interface was listed to document intent ("this class is usable as
   IB"), that intent is already expressed by the base class — the
   documentation value is zero.
3. Rebuild and run tests; removal is behavior-neutral, but verify no
   reflection code was enumerating the declared interfaces literally.

## AVOID
- Do not "fix" it by removing the entry from the *base* class instead —
  that changes the hierarchy for every sibling, not just this class.
- Do not leave the redundant entry with a comment explaining the
  redundancy; the comment is the code smell narrating itself.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

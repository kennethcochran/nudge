# S2953 — Methods named "Dispose" should implement "IDisposable.Dispose"

## Why
A method named `Dispose` that isn't the interface implementation lies about the
type's contract: `using` blocks and DI containers won't call it, so resources
leak, and readers assume disposal semantics that aren't wired up.

## Do this
1. If the method really is the disposal entry point, have the type implement
   `IDisposable` so the method becomes the interface implementation.
2. If it isn't disposal in the `IDisposable` sense (it "disposes" in some
   domain sense), rename it to what it actually does: `Close`, `Release`,
   `Shutdown`.

## AVOID
- Do not add `: IDisposable` with an explicit interface implementation that
  throws `NotImplementedException` while keeping the real logic in the
  separate `Dispose()` method. That wires the name to the contract in the most
  useless way — `using` would throw, and the leak remains.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

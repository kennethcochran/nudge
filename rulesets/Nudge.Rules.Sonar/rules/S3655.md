# S3655 — Empty nullable value should not be accessed

## Why
Reading `.Value` on a `Nullable<T>` that has no value throws
`InvalidOperationException` at runtime. The analyzer has found a path where
the nullable can be empty at the access — that is a crash waiting for the
right input, and it usually means the empty case was never decided.

## Do this
1. Guard the access: check `.HasValue` first, use pattern matching
   (`if (x is { } v)`), `GetValueOrDefault()`, or `?.` propagation — whichever
   fits the surrounding code.
2. Decide the empty-case behavior explicitly: a default value, an early
   return, or a meaningful exception. Don't leave it implicit.
3. Add a test that drives the null path through the fixed code.

## AVOID
- Do not slap the null-forgiving operator on it (`x!.Value`) to silence the
   analyzer — the exception still happens at runtime; you've only hidden the
   warning. Handle the empty case for real.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2139 — Exceptions should be either logged or rethrown but not both

## Why
Logging an exception and then rethrowing it produces
duplicate log entries for a single failure — once at the catch site,
once wherever it's eventually handled — which makes incident triage
noisy and can double-alert on-call. Worse, it scatters the "who owns
this failure" decision across every layer.

## Do this
1. Decide which single layer owns logging for this failure — usually
   the outermost handler.
2. In every other `catch`, either handle the exception (log it there
   and don't rethrow) or rethrow it with a bare `throw;` and no logging.
3. If you add context while rethrowing, wrap in a more specific
   exception type carrying the context — still without logging at that
   layer.

## AVOID
- Do not delete the log line at the catch site only to log the same
  exception again one frame up the stack — the duplication just moved.
- Do not rethrow with `throw ex;` — it resets the stack trace. A bare
  `throw;` preserves it.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

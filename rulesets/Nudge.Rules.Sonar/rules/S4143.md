# S4143 — Collection elements should not be replaced unconditionally

## Why
`dict[key] = value` silently overwrites whatever was already stored under
that key. When the intent was "add if absent," a duplicate key destroys data
without a whisper — and the unconditional write hides the add-versus-update
decision the author never made.

## Do this
1. Decide the intent. If it is add-if-absent, use `TryAdd` and handle the
   `false` return (log, throw, or merge — deliberately).
2. If it is an update, make the overwrite explicit: check first or leave a
   comment stating that overwriting is intended.
3. Apply the same thinking to index assignment on lists.

## AVOID
- Do not wrap the assignment in `try/catch`. The indexer does not throw on
  overwrite — there is nothing to catch, and the silent data loss continues
  underneath the handler.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

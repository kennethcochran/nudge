# S3457 — Composite format strings should be used correctly

## Why
A composite format string whose placeholders don't match its arguments —
`{0}` with no argument, an argument with no placeholder, a misplaced format
specifier — throws `FormatException` at runtime or silently produces wrong
output. The compiler cannot check the pairing for you.

## Do this
1. Make every placeholder index correspond to an argument: same count, same
   order, valid format specifiers.
2. Prefer interpolated strings (`$"..."`) wherever possible — the compiler
   checks those pairings for you.
3. For format strings stored in resources or constants, add a unit test that
   formats them with representative arguments.

## AVOID
- Do not wrap the formatting call in `try/catch (FormatException)`. A
  mismatched format string is a bug in your code, not an expected runtime
  condition — catching it just moves the failure somewhere harder to find.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S4201 — Null checks should not be combined with "is" operator checks

## Why
In `if (x != null && x is Foo f)`, the pattern check already excludes null —
the explicit null check is dead code that makes readers wonder what case it
covers. Redundant conditions aren't harmless: they imply a distinction that
doesn't exist.

## Do this
1. Delete the redundant null check and keep the pattern:
   `if (x is Foo f)`.
2. If the null check was guarding a *different* variable, split the conditions
   so each guards its own variable instead of piling onto one `&&`.
3. For nullable value types, pattern matching already handles `HasValue` —
   the same simplification applies.

## AVOID
- Do not replace `is` with `as` plus a null check to "use both checks" —
  that is the same redundancy in older syntax.
- Do not keep the null check "for clarity" — a check that can never change
  the outcome clarifies nothing; it suggests a null case the pattern already
  rules out.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6677 — Message template placeholders should be unique

## Why
In structured logging (`ILogger` message templates, Serilog), each `{Name}`
placeholder becomes a named property on the log event — if two placeholders
share a name but receive different values, one silently overwrites the other
in the structured payload, and dashboards querying that property get
whichever value won. The rendered text looks fine, which is why the
corruption goes unnoticed until someone queries the logs.

## Do this
1. Give each distinct value a distinct placeholder name: `{UserId}` and
   `{ImpersonatedUserId}`, not `{User}` twice.
2. If both placeholders intentionally carry the *same* value, pass it once
   against one placeholder — or keep both names distinct anyway so future
   edits can't diverge them silently.
3. Check the argument order matches the placeholder order; a duplicated name
   often indicates a copy-pasted argument list.

## AVOID
- Do not "uniquify" by appending digits (`{User1}`, `{User2}`) without
  checking whether the two values are actually the same — numbered
  placeholders with identical values are noise, and with different values
  they're cryptic; name them by meaning.
- Do not fix it by dropping one of the arguments while keeping both
  placeholders — a placeholder with no matching argument renders literally
  as `{User}` in the output.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

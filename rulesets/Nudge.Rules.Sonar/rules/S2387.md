# S2387 — Child class fields should not shadow parent class fields

## Why
**This rule is deprecated and will be removed.** Shadowing a parent field
with a same-named child field is confusing, but the language already
requires the `new` keyword to make it explicit, and modern analyzers cover
the genuinely dangerous cases elsewhere. A finding here is the rule set
showing its age, not your code showing a defect.

## Do this
1. If the shadowing is intentional and the `new` keyword is present, nothing:
   the code is already as explicit as the language requires.
2. If the shadowing is accidental (you did not realize the parent had that
   field), rename the child field — but do that because the design is
   confusing, not because the rule fired.
3. If the rule fires in CI, remove S2387 from the active profile rather
   than annotating code.

## AVOID
- Do not rename fields purely to silence a deprecated rule when the
  shadowing is deliberate and documented. Churn without a defect is the
  opposite of maintenance.
- Do not suppress per-occurrence; fix the rule profile once.

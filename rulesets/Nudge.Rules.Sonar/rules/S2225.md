# S2225 — "ToString()" method should not return null

## Why
ToString() carries an implicit contract: it never returns null. Callers —
string interpolation, concatenation, logging, UI binding — do not null-check
it, so a null return becomes a NullReferenceException far from the cause.
This rule flags overrides that can return null.

## Do this
1. Make the override total: return a meaningful representation, falling back to string.Empty (or base.ToString()) for the degenerate case — never null.
2. If the string is built from nullable fields, apply ?? string.Empty at the construction site, inside ToString itself.
3. Annotate the override as returning non-null so the compiler enforces the contract going forward.

## AVOID
- Do not add '!' at call sites (x.ToString()!) — the null still escapes to every other consumer of the type.
- Do not return null! from the override to silence the nullable warning; that lies to the compiler and to every caller.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

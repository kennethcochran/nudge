# S1075 — URIs should not be hardcoded

## Why
Hardcoded URLs scatter environment-specific addresses through the code. Moving
from dev to staging to prod — or a domain change, or a secret embedded in a
URL — becomes a find-and-replace hunt, and the one occurrence you miss is the
one that pages you at 2 AM.

## Do this
1. Move the URI into configuration (`appsettings.json`, an options class) and
   read it via `IOptions<T>` / `IConfiguration` at the use site.
2. If the value is genuinely fixed across every environment, a named constant
   is acceptable — but be honest about whether it varies.
3. Keep per-environment values in config files/transforms, not in `#if`
   blocks.

## AVOID
- Do not move the hardcoded URI into a `Constants` class and call it done
   when the value varies by environment — that is still hardcoded, just
   relocated. Environment-varying values belong in configuration.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

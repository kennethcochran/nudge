# S6580 — Use a format provider when parsing date and time

## Why
`DateTime.Parse` / `TryParse` / `ParseExact` without an `IFormatProvider` use the current thread culture — `"03/04/2026"` parses as March 4 or April 3 depending on the machine. The bug only manifests under a different locale, which usually means production.

## Do this
1. Pass an explicit provider: `CultureInfo.InvariantCulture` for machine-generated formats, or the specific `CultureInfo` when parsing genuine user input.
2. Prefer `ParseExact` / `TryParseExact` with an explicit format string when the format is known.

## AVOID
- Do not pass `CultureInfo.CurrentCulture` explicitly to silence the rule — that's the default behavior spelled out; the parsing stays exactly as culture-dependent as before.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

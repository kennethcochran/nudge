# S2952 — Classes should "Dispose" of members from the classes' own "Dispose" methods

## Why
A class that owns `IDisposable` fields but never disposes them leaks handles,
connections, and unmanaged memory for the object's entire lifetime — the
garbage collector runs finalizers, not `Dispose`, so nobody else will clean up
for you.

## Do this
1. Implement `IDisposable` on the owning class.
2. In `Dispose()`, dispose each owned `IDisposable` field (null-conditional
   `?.Dispose()` is fine).
3. Dispose only what the class *owns* — not injected or shared instances it
   didn't create; disposing someone else's dependency is a use-after-dispose
   bug for its real owner.

## AVOID
- Do not write an empty `Dispose()` to satisfy the rule — an undisposed
  field behind a no-op `Dispose` is the same leak with a signature.
- Do not "dispose" the fields by setting them to `null` — nulling a reference
  releases nothing; only `Dispose()` runs cleanup.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

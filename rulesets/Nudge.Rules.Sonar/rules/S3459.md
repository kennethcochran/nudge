# S3459 — Unassigned members should be removed

## Why
A private field or property that is never assigned and never read is dead code: it misleads readers into thinking it holds state, and it adds noise to every future edit of the class. The analyzer only flags members with genuinely no writer, so this is the compiler telling you the member does nothing.

## Do this
1. Confirm the member is never assigned anywhere — constructors, initializers, and any reflection-based frameworks you use.
2. If it's dead, delete the declaration.
3. If it's populated by reflection/serialization (a DTO property, an ORM-mapped field), keep it — but make sure it's actually part of a live serialized contract, not a leftover.

## AVOID
- Do not "assign" it in a constructor just to silence the rule (e.g. `_unused = null;`) — that's a fake assignment, not a use.
- Do not make it `public` to dodge the private-member detection — visibility doesn't create a reader.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

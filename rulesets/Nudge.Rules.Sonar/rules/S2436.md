# S2436 — Types and methods should not have too many generic parameters

## Why
`Foo<T1, T2, T3, T4, T5, T6>` is a signature nobody can read or call correctly
— each parameter multiplies the cognitive load, inference failures, and the
odds of swapped arguments. A long type-parameter list is a sign the abstraction
is missing a concept that wants a name.

## Do this
1. Group related parameters into a meaningful options or context type:
   `Foo<TConfig, TResult>` where `TConfig` is a record holding the rest.
2. Name the new type after the concept it represents, not the parameters it
   swallowed.
3. Update call sites; type inference usually gets simpler, not harder.

## AVOID
- Do not bundle the parameters into a `ValueTuple<T1, T2, ...>` type argument
   — that's the same unreadable list wearing angle brackets; introduce a named
   concept.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2114 — Collections should not be passed as arguments to their own methods

## Why
Calling `list.AddRange(list)` — or similar self-referential calls — mutates a
collection while reading it. The behavior is undefined or surprising, and with
deferred LINQ execution it can loop forever or throw mid-enumeration.

## Do this
1. Materialize a snapshot first: `list.AddRange(list.ToList())` — the eager
   copy is fixed before the mutation starts.
2. Better, reconsider the operation itself: appending a collection to itself is
   often a sign the algorithm should build a new collection instead of
   mutating in place.

## AVOID
- Do not "fix" it with `list.AddRange(list.AsEnumerable())`. `AsEnumerable()`
  is still a live view of the same collection — the self-reference remains;
  only an eager copy (`ToList()` / `ToArray()`) breaks it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

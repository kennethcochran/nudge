# S6423 — Azure Functions should log all failures

## Why
An exception caught and swallowed — or rethrown without logging — inside a Function vanishes from Application Insights: the invocation shows as failed with no cause, and you debug blind. The `catch` block is often the only place the failure context still exists.

## Do this
1. Inject `ILogger<T>` (or take the `ILogger` parameter) and log the exception in the `catch` block with context — function name and the relevant ids — before handling or rethrowing.
2. If the catch intentionally swallows, the log line is the *only* record: log at `Error`/`Warning` with the exception object, not just its message.

## AVOID
- Do not "log" with `Console.WriteLine` or `Debug.WriteLine` — that output doesn't reach the Functions logging pipeline.
- Do not log only `ex.Message` as a string and drop the exception object — you lose the stack trace, which is usually the whole point.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3451 — "[DefaultValue]" should not be used when "[DefaultParameterValue]" is meant

## Why
`[DefaultValue]` is for designers and serializers — it does nothing for optional parameters in COM interop. The compiler and COM callers look at `[DefaultParameterValue]` (or C#'s native `= default` syntax), so the wrong attribute means the default is silently ignored at call sites while looking correct in source.

## Do this
1. Replace `[DefaultValue(x)]` with `[DefaultParameterValue(x)]` on the parameter — or, preferably, use a C# optional parameter (`void M(int p = x)`).
2. Verify callers that relied on the default still compile and behave as intended.

## AVOID
- Do not stack both attributes "to be safe" — the misleading one stays misleading.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S101 — Types should be named in PascalCase

## Why
C# convention is PascalCase for type names; a type named `my_class` or
`customerDTO` breaks the visual contract every reader relies on — in C#,
casing is how you tell a type from a variable at a glance. Inconsistent
naming also trips tooling and analyzers that assume the convention.

## Do this
1. Rename the type to PascalCase (`customerDto` → `CustomerDto`) using the
   IDE's rename refactoring, so every reference, file name, and doc comment
   updates together.
2. Check serialization boundaries: if the type name appears in JSON/XML
   contracts, database mappings, or reflection-based lookups, update those
   mappings in the same change.
3. For public API in a shipped library, weigh the breaking change — but for
   internal code, just rename.

## AVOID
- Do not rename only the declaration and hand-edit a few call sites; missed
  references are compile errors at best and silent reflection failures at
  worst — use the IDE rename.
- Do not "fix" it by tweaking one letter (`my_class` → `My_class`); the rule
  wants PascalCase, not a smaller violation.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

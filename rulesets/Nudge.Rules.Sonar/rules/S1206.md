# S1206 — Equals and GetHashCode Should Be Overridden Together

## Why
Same contract as CS0659: `Equals` and `GetHashCode` must agree. Equal objects
must produce equal hash codes, or hash-based collections (`Dictionary`,
`HashSet`) silently fail to find objects they contain. Overriding one without
the other breaks the contract.

## Do this
1. Override `GetHashCode` combining the same fields `Equals` compares, e.g.
   `HashCode.Combine(X, Y)`.
2. Verify: equal instances must return equal hash codes. Test it directly.
3. For simple value carriers, consider a `record` — the compiler generates
   both correctly.

## AVOID
- Do not implement `GetHashCode() => 0;` or any constant. It satisfies the
  letter of the rule but destroys hash distribution — lookups degrade to
  linear scans.
- Do not hash different fields than `Equals` compares.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

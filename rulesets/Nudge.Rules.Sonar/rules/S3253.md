# S3253 — Constructor and destructor declarations should not be redundant

## Why
An explicit parameterless constructor that just calls `base()`, or an empty
finalizer `~C() {}`, adds ceremony the compiler already provides — and an empty
finalizer is actively harmful, forcing every instance through the finalization
queue for no reason.

## Do this
1. Delete the redundant constructor or finalizer and let the compiler supply
   the default.
2. If the finalizer was a placeholder for future unmanaged cleanup, delete it
   now — add it back if and when unmanaged resources actually arrive.

## AVOID
- Do not keep the redundant declaration and add a comment ("default ctor",
  "reserved for future use") to make it look intentional. A documented no-op
  is still a no-op — and in the finalizer's case, still a per-instance GC tax.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

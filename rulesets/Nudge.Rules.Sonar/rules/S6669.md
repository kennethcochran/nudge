# S6669 — Logger field or property name should comply with a naming convention

## Why
Loggers are everywhere; a consistent name (conventionally `_logger` for a
private field) lets readers and tooling spot logging instantly during reviews,
refactors, and searches. A creatively named logger field hides in plain sight
and every future reader pays the discovery cost again.

## Do this
1. Rename the field or property to the convention the rule expects (typically
   `_logger` for a private field).
2. Let the IDE perform the rename so every usage updates mechanically.
3. Check the file for a second logger-like field left behind by an earlier
   partial rename and consolidate.

## AVOID
- Do not keep the old name alive as a second field or property aliasing the new
   one; one logger, one name.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

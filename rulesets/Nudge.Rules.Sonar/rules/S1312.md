# S1312 — Logger fields should be "private static readonly"

## Why
A logger should be one per class, created once, and
immutable: `private static readonly`. An instance logger field wastes a
reference per object for something that never varies by instance, and a
non-readonly logger invites reassignment that changes logging behavior
mid-run in ways no reader expects.

## Do this
1. Declare the logger as `private static readonly` (e.g.
   `private static readonly ILogger Log =
   LogManager.GetCurrentClassLogger();` or the equivalent for your
   logging framework).
2. Name it after the type, not the instance — the category comes from
   `typeof(YourClass)`, which doesn't need an instance.
3. Remove any per-instance logger initialization from constructors.

## AVOID
- Do not make it an instance field "so each instance logs its own
  name" — derive the logger name from the type, which is identical for
  every instance.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

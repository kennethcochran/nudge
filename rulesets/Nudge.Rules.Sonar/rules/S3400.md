# S3400 — Methods should not return constants

## Why
A method whose every path returns the same literal is a constant wearing a
method costume — callers pay a call for a value the compiler already knows,
and readers expect computed behavior that isn't there.

## Do this
1. If the value is truly fixed, replace the method with a `const` field or a
   get-only property.
2. If the method was supposed to compute something, implement the actual logic
   — the constant return is usually a stub that escaped into production.

## AVOID
- Do not make the return "non-constant" cosmetically (`return flag ? 42 : 42;`,
  or reading the constant out of a config value that never changes). The value
  is still constant; the rule flags the semantics, not the literal syntax.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1104 — Fields should not have public accessibility

## Why
Public fields expose raw storage as API: callers can
read and write the value with no validation, no change notification,
and no way for you to evolve the representation later without breaking
every consumer. A property costs nothing and buys you a seam for all of
that.

## Do this
1. Replace the public field with a property.
2. Give the setter the narrowest accessibility the design needs —
   `private`, `init`, or none at all — not an unrestricted public
   setter by default.
3. If the field was `readonly`, the property getter alone preserves
   that; if callers wrote to it, decide deliberately whether writes are
   part of the contract.

## AVOID
- Do not replace `public int x;` with `public int X { get; set; }`
  when nothing needs to write it — an unrestricted public setter is
  barely better than a field for encapsulation.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

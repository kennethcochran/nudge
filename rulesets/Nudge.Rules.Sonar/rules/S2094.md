# S2094 — Empty Class

## Why
An empty class is a named nothing. It shows up in navigation, in
documentation, in dependency graphs — and contributes nothing. Usually it's a
placeholder someone forgot, or a bad abstraction that never earned its
existence. Either fill it or delete it.

## Do this
1. If the class was meant to hold behavior or state, implement it now.
2. If it's genuinely unnecessary, delete it. An unused abstraction is worse
   than none — it suggests a design that isn't there.
3. If it's a marker type (used only as a generic parameter or attribute
   target), say so with a comment — intentional emptiness is fine, silent
   emptiness isn't.

## AVOID
- Do not add junk members (an unused field, a `// TODO` comment as a body)
   just to make the class non-empty. A class with a meaningless member is
   still an empty class with extra steps.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

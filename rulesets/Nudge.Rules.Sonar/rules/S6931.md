# S6931 — ASP.NET controller actions should not have a route template starting with "/"

## Why
A leading `/` in `[Route("/api/items")]` or `[HttpGet("/items")]` makes the
template absolute: it discards the controller-level route prefix. That is
almost always accidental, and it silently changes the URL the action is served
at — the endpoint moves without any compile-time signal.

## Do this
1. Remove the leading `/` so the action template is relative to the
   controller-level `[Route]`.
2. If the absolute route was genuinely intentional, move the full path up to
   the controller-level `[Route]` and keep action templates relative — one
   place defines the URL.
3. Verify the served URLs with a route test or by inspecting the endpoint
   list.

## AVOID
- Do not keep the leading `/` and "fix" the URL by duplicating the prefix
   into the controller route — the absolute template still ignores it. Remove
   the slash.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

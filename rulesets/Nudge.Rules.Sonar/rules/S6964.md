# S6964 — Value type property used as input in a controller action should be nullable, required or annotated with the JsonRequiredAttribute to avoid under-posting.

## Why
A non-nullable value-type property (e.g. `int Quantity`) in a model-bound input
silently defaults to `0` when the client omits it. The action cannot
distinguish "the client sent 0" from "the client sent nothing"
(under-posting), so validation passes on data the client never provided.

## Do this
1. Make the property nullable (`int?`) and treat null as "not provided", or
   mark it `required` / `[JsonRequired]` so model binding rejects a missing
   value outright.
2. Handle the not-provided case explicitly in the action: a 400 with a clear
   message, or a documented default applied deliberately — not an accidental
   zero.
3. Add a test that posts the payload without the field and asserts the
   expected rejection or default.

## AVOID
- Do not leave the property non-nullable and "handle" it by treating `0` as
   missing — zero is a legitimate value for many fields, and the ambiguity is
   the bug. Make the type express optionality.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

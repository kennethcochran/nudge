# S3995 — URI return values should not be strings

## Why
Returning a URL as `string` pushes parsing, validation, and escaping onto
every caller and invites malformed-URI bugs at each one. `System.Uri` carries
the parsing, escaping, and comparison semantics in a single type — the method
advertises "this is a URI" instead of "this is some text".

## Do this
1. Change the return type to `System.Uri` (or `Uri?` if absence is a real
   case).
2. Construct the `Uri` at the source with `new Uri(...)`, validating early
   where the value originates.
3. Update callers to use `Uri` members (`AbsoluteUri`, `ToString()`) instead
   of string operations on the result.

## AVOID
- Do not "fix" it by changing the return type to `object` or `dynamic` while
   still returning a string — the type information is still lost to every
   caller. Return `System.Uri`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

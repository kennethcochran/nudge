# S1066 — Merge Nested If Statements

## Why
An `if` directly inside another `if` with no `else` is one condition wearing
two costumes. The nesting adds a cognitive level for no reason: the reader
must hold the outer condition while evaluating the inner one, when `if (a
&& b)` says the same thing flat. Shallow code is cheaper to review.

## Do this
1. Merge into a single condition with `&&`: `if (a) { if (b) {...} }`
   becomes `if (a && b) {...}`.
2. Only when there's no `else` on either — if an `else` exists, the merge
   changes semantics; restructure more carefully instead.

## AVOID
- Do not "merge" by inverting one condition into an unreadable negation just
  to force a single `if`. `if (!(a && !b) || c)` is not an improvement.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6603 — The collection-specific "TrueForAll" method should be used instead of the "All" extension

## Why
`list.All(predicate)` goes through `IEnumerable<T>`, allocating an enumerator;
`List<T>.TrueForAll` iterates the backing array directly. On hot paths the
enumerator churn shows up in profiles for zero benefit.

## Do this
1. When the receiver is statically a `List<T>`, call
   `list.TrueForAll(predicate)` instead of `list.All(predicate)`.
2. Keep `All` when the static type is `IEnumerable<T>` or an interface — the
   rule only applies where the concrete `List<T>` type is known.

## AVOID
- Do not "fix" it by widening the variable's declared type to
  `IEnumerable<T>` so you can keep `All` — you've hidden the concrete type
  and kept the slower path.
- Do not hand-roll the loop with an early `break` unless profiling justifies
  it — `TrueForAll` is the idiomatic fix here.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

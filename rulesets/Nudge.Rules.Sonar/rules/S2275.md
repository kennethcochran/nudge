# S2275 — Composite format strings should not lead to unexpected behavior at runtime

## Why
`string.Format("{0} {2}", a, b)` compiles without complaint and then throws
`FormatException` at runtime — or worse, prints the wrong value in the wrong
slot. The compiler cannot check that placeholder indexes line up with the
argument list, so the pairing has to be verified by hand.

## Do this
1. Count placeholders against arguments: every `{n}` must satisfy
   `n < argument count`, and check for skipped or duplicated indexes.
2. Prefer interpolated strings (`$"..."`) where each value sits next to its
   text — the pairing becomes self-evident.
3. For format strings in resources or localization files, add a test that
   formats them with sample arguments so mismatches fail in CI, not in
   production.

## AVOID
- Do not add a dummy extra argument just to satisfy the highest placeholder
  index — a placeholder printing a meaningless value is a bug, not a fix.
- Do not "fix" it by removing the offending placeholder while leaving the now
  unused argument — dead arguments rot into the next person's confusion.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

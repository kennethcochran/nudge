# S6965 — REST API actions should be annotated with an HTTP verb attribute

## Why
A controller action with no `[HttpGet]` / `[HttpPost]` / etc. is reachable by
any verb through conventional routing — a data-mutating action becomes
invocable via GET, which caches, proxies, and crawlers all treat as safe and
repeatable.

## Do this
1. Annotate the action with the verb that matches what it actually does:
   `[HttpGet]` for reads, `[HttpPost]` / `[HttpPut]` / `[HttpDelete]` for
   mutations.
2. Check the route template at the same time — attribute routing
   (`[Route(...)]`) makes the endpoint's URL explicit too.

## AVOID
- Do not slap `[HttpGet]` on an action that mutates state just to satisfy the
  analyzer. The attribute must describe the real behavior; a mutating GET is a
  correctness and caching bug wearing a compliant annotation.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3874 — "out" and "ref" parameters should not be used

## Why
`out`/`ref` parameters are a second, invisible return channel: they defeat
method chaining, complicate async, and force callers to declare temporaries
before the call. C# 7+ tuples and small result records express multiple outputs
as one visible return value that composes normally.

## Do this
1. Change the method to return a tuple or a small result record —
   `(bool Success, int Value)` instead of `bool TryGet(..., out int value)`.
   (The established `Try*` pattern is the idiomatic exception; leave those.)
2. Update call sites to deconstruct the return:
   `var (ok, val) = Parse(input);`
3. For `ref` used as in-place mutation, return the new value instead and let
   the caller assign it.

## AVOID
- Do not keep the `out` parameter and add a wrapper "result bag" class whose
   only job is to carry the same out values — that's the parameter list
   renamed, not removed; return a tuple or record instead.
- Do not replace `out` with a one-element array or a mutable holder object
   passed by value; same trick, same smell.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

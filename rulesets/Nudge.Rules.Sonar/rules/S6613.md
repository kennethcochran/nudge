# S6613 — "First" and "Last" properties of "LinkedList" should be used instead of the "First()" and "Last()" extension methods

## Why
`LinkedList<T>.First` and `.Last` are O(1) node references the list already
maintains; the `Enumerable` extension methods iterate the list to find what
is already known. But note the semantics differ on empty lists: the property
returns `null`, while the extension method throws.

## Do this
1. Replace `.First()` / `.Last()` calls with the `.First` / `.Last`
   properties.
2. Recheck the empty-list path: code that relied on the throw now gets a
   null node — add an explicit null check or an early return where the old
   behavior mattered.

## AVOID
- Do not paper over the semantic difference with a null-forgiving `!` on the
  property. If empty is possible, handle it; if it is impossible, assert it
  explicitly rather than lying to the compiler.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3236 — Caller information arguments should not be provided explicitly

## Why
`[CallerMemberName]` / `[CallerFilePath]` / `[CallerLineNumber]` parameters
exist so the compiler fills them in at the call site. Passing an explicit
value defeats the mechanism: the hardcoded string rots on the next rename or
move, and the logged caller name becomes a lie.

## Do this
1. Delete the explicit argument at the call site; leave the parameter with its
   default value.
2. Confirm the parameter still carries the `[CallerMemberName]` (or sibling)
   attribute with a default.
3. Run the affected path and confirm the logged caller name now reflects the
   real caller.

## AVOID
- Do not pass `nameof(ThisMethod)` explicitly "for clarity" — it hardcodes
  today's caller and lies after the next rename, which is exactly what the
  attribute exists to prevent.
- Do not work around it by adding a second overload that takes the caller
  name as a required parameter — you've reintroduced the manual passing the
  attribute was designed to eliminate.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

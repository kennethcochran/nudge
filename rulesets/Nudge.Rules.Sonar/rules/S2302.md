# S2302 — "nameof" should be used

## Why
A hard-coded member name in a string — `"PropertyName"` in an exception, a
logging scope, a `PropertyChanged` notification — does not survive renaming.
Refactoring tools miss it, the compiler never flags it, and the stale string
fails silently at runtime.

## Do this
1. Replace string literals that name a type, member, or parameter with
   `nameof(...)`.
2. For `ArgumentNullException` and friends, use the overloads that take the
   parameter name via `nameof`.

## AVOID
- Do not build the name by concatenating onto `nameof`
  (`nameof(Foo) + "Bar"`). That is half a fix: the suffix is still an
  unchecked string. Apply `nameof` to the actual symbol you mean.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

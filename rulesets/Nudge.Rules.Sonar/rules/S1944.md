# S1944 — Invalid casts should be avoided

## Why
A direct cast to a type the value can never be throws `InvalidCastException`
at runtime — and the compiler already knows the conversion can't succeed. The
flagged cast is either dead code or a latent crash waiting for the right
input.

## Do this
1. If the value might genuinely be the target type, use pattern matching
   (`if (x is Target t)`) or `as` plus a null check.
2. If the cast should always succeed, fix the declared type of the value
   instead of casting at the use site.
3. For numeric narrowing where overflow is a real concern, use an explicit
   `checked` cast or `Convert` with overflow semantics you chose deliberately.

## AVOID
- Do not wrap the cast in `try/catch (InvalidCastException)` — exceptions are
  not control flow, and the catch hides *which* conversions are actually
  expected versus which are bugs.
- Do not "fix" it by casting through `object` or `dynamic` — you've silenced
  the compiler's proof without changing the runtime outcome.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

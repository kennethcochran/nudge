# S3902 — "Assembly.GetExecutingAssembly" should not be called

## Why
`Assembly.GetExecutingAssembly()` returns the assembly containing the
*currently running code* — in libraries, single-file apps, NativeAOT, or test
runners that's often not the assembly you meant. Resource lookups, version
info, and location data then silently come from the wrong place. It's a guess
disguised as an API.

## Do this
1. Decide which assembly you actually want: the one defining a known type →
   `typeof(KnownType).Assembly`; the app's entry point →
   `Assembly.GetEntryAssembly()`; the caller →
   `Assembly.GetCallingAssembly()`.
2. Replace the call with the precise one.
3. Check resource lookups and version reads nearby — they were probably also
   guessing.

## AVOID
- Do not "fix" it by caching `GetExecutingAssembly()` in a static field — the
   wrong assembly, captured once, is still the wrong assembly.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

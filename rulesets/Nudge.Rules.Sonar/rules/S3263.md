# S3263 — Static fields should appear in the order they must be initialized

## Why
Static field initializers run in textual order: a field initialized from
another static field declared *below* it reads the default value (`null`,
`0`) instead of the intended one. The bug is order-dependent — it moves when
someone reorders the file — which makes it miserable to diagnose.

## Do this
1. Reorder the declarations so each static field appears after the fields it
   depends on.
2. For non-trivial dependency graphs, prefer an explicit static constructor —
   the order is stated once, in code, instead of implied by layout.
3. Mark fields `readonly` where the value never changes, so the initialization
   story is complete at declaration.

## AVOID
- Do not "fix" it with lazy-initialization wrappers on everything — laziness
  hides the dependency graph instead of making the declaration order correct.
- Do not fix the order in one file while the same pattern (field A reads
  field B declared below) survives elsewhere in the class — check all static
  initializers, not just the flagged line.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

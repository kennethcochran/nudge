# S3010 — Static fields should not be updated in constructors

## Why
An instance constructor that writes to a static field mutates shared state on
every `new` — order-dependent, thread-unsafe, and invisible at the call site.
Worse, it runs again with each instantiation, so the "initialization" it
performs is not initialization at all; it is repeated mutation of global
state.

## Do this
1. If the write is one-time setup, move it to a static constructor or a
   static field initializer — the constructs designed for exactly this.
2. If the data genuinely varies per instance, it should not be static:
   make it an instance field.

## AVOID
- Do not guard the write with `if (_field == null)` double-checked locking
  inside the instance constructor. That is a static constructor written
  badly — racy, noisy, and redundant. Use the real one.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

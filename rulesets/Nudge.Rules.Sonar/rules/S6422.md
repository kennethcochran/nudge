# S6422 — Calls to "async" methods should not be blocking in Azure Functions

## Why
`.Result`, `.Wait()`, or `.GetAwaiter().GetResult()` on the Functions host blocks a threadpool thread per invocation and risks sync-over-async deadlocks. The Functions runtime is built around async end-to-end; blocking calls starve its scaling and can hang the host under load.

## Do this
1. Make the function `async Task` (or `async Task<IActionResult>`) and `await` the call.
2. Propagate `async` up through any helpers the function calls — don't stop halfway and block at the next layer.

## AVOID
- Do not "fix" it by wrapping the blocking call in `Task.Run(() => ... .Result)` — that just moves the blocked thread to the pool; you still burn a thread per invocation.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S5034 — "ValueTask" should be consumed correctly

## Why
Unlike `Task`, a `ValueTask` may only be awaited or consumed once. Awaiting it
twice, or storing it in a field for later, can corrupt state or throw —
because the instance may wrap a pooled `IValueTaskSource` that gets recycled
the moment the first consumption completes.

## Do this
1. `await` the `ValueTask` immediately at the call site, in the same
   expression that produced it.
2. If you must store it, hand it to multiple consumers, or await it
   conditionally, convert it once with `.AsTask()` and use the resulting
   `Task` everywhere instead.

## AVOID
- Do not await the same `ValueTask` twice because "it worked in testing".
  Whether the second await misbehaves depends on the pooled source's state —
  it is a latent corruption bug, not a tested-safe pattern. Convert to `Task`
  via `.AsTask()` if multiple consumptions are genuinely needed.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6968 — Actions that return a value should be annotated with ProducesResponseTypeAttribute containing the return type

## Why
An ASP.NET Core action returning `OrderDto` without `[ProducesResponseType]`
leaves OpenAPI/Swagger guessing — generated clients get `object` or nothing,
and the status codes the action can actually return go undocumented.

## Do this
1. Add `[ProducesResponseType(typeof(OrderDto), StatusCodes.Status200OK)]`,
   with one attribute per status code the action can return (200, 404, 400…).
2. Match each declared type to what the action actually returns on that path —
   check the `NotFound()`/`BadRequest()` branches too.

## AVOID
- Do not "fix" it with `[ProducesResponseType(typeof(object), 200)]` — it
  silences the rule while telling API consumers nothing.
- Do not change the action's return type to `IActionResult` to dodge the rule —
  you lose the typed contract the attribute was documenting.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

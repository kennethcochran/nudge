# S3877 — Exceptions should not be thrown from unexpected methods

## Why
`Equals`, `GetHashCode`, `ToString`, static constructors, `Dispose`,
finalizers, and operator overloads are invoked implicitly by the runtime and
the framework — a throw there surfaces far from its cause. A throwing
`GetHashCode`, for example, breaks every `Dictionary` and `HashSet` that
touches the type, with no meaningful stack to debug.

## Do this
1. Identify which contract method the diagnostic points at.
2. Move the throwing validation into an explicit method that callers invoke
   deliberately (`Validate()`, `EnsureReady()`).
3. Make the contract method total: return a best-effort value instead of
   throwing, and let the explicit method carry the failure semantics.

## AVOID
- Do not keep the throw and add a "this should never happen" comment — the
  framework calls these methods on paths you can't see, and "never" is doing
  a lot of work in that sentence.
- Do not wrap every call site in try/catch to contain it — you can't wrap the
  framework's call sites, which are the ones that break.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

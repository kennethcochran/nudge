# S2333 — Redundant modifiers should not be used

## Why
A modifier that changes nothing — `private` on an interface member, `sealed`
on a static class, `readonly` on a `const` — compiles silently but misleads
the reader into believing it does something. Dead modifiers also rot: when
the surrounding declaration changes, the redundant modifier starts implying
intent that was never there.

## Do this
1. Delete the redundant modifier. The declaration means exactly what it
   meant before, minus the noise.
2. If you added the modifier deliberately as documentation, replace it with
   a comment — comments are honest about being documentation.

## AVOID
- This rule is mechanical: the complete fix is deletion. Do not move the
  modifier to a neighboring member "where it might apply" — that invents
  meaning that was never intended.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

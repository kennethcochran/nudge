# S5856 — Regular expressions should be syntactically valid

## Why
An invalid regex pattern throws `ArgumentException` when the `Regex` is
constructed (or first used) — a crash in production from a string literal that
was never executed in tests. Because the pattern is just a string, the
compiler can't catch it; only a test or the analyzer can.

## Do this
1. Read the exact pattern the diagnostic flags and identify the syntax error:
   unbalanced parentheses or brackets, a stray escape, a bad quantifier.
2. Fix the pattern to express what was actually intended; if the intent is
   unclear from the code, check the tests or ask before guessing.
3. Add a unit test that constructs and exercises the regex — a test that
   merely builds it catches this entire class of bug permanently.
4. Don't change behavior while fixing: leave `RegexOptions` as they are until
   the pattern is correct.

## AVOID
- Do not wrap the `new Regex(...)` in try/catch to swallow
   `ArgumentException` — that hides a bug that should be fixed at the source,
   and now every caller needs null-handling for a regex that should simply be
   correct.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

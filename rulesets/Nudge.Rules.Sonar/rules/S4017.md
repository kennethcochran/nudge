# S4017 — Method signatures should not contain nested generic types

## Why
`Dictionary<string, List<(int Id, string Name)>>` in a public signature forces
every caller to reconstruct the nesting in their head (and in their code). The
nesting usually hides an unnamed domain concept begging for a name — and
unnamed shapes can't be documented, constrained, or reused.

## Do this
1. Introduce a named type for the nested structure — a record
   (`record OrderLine(int Id, string Name);`) or a dedicated collection type.
2. Simplify the signature to use it: `IReadOnlyList<OrderLine>`.
3. Keep the behavior identical — this is a naming refactor, not a logic
   change.

## AVOID
- Do not "simplify" with a file-level `using` alias
   (`using OrderLines = List<(int, string)>;`) and keep the anonymous shape —
   the concept is still unnamed for every consumer outside the file; declare a
   real type.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

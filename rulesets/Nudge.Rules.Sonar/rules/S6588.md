# S6588 — Use the "UnixEpoch" field instead of creating "DateTime" instances that point to the beginning of the Unix epoch

## Why
`new DateTime(1970, 1, 1, 0, 0, 0, DateTimeKind.Utc)` is seven magic arguments
spelling a constant the framework already names. `DateTime.UnixEpoch` is
unambiguous and un-mistypeable — one wrong argument in the long form silently
shifts every timestamp derived from it.

## Do this
1. Replace the construction with `DateTime.UnixEpoch`.
2. Check the `DateTimeKind` first: if the original used `Local` or left the
   kind unspecified, that's a different instant and a latent bug — fix the kind
   bug before replacing, don't cement it.

## AVOID
- This rule is mechanical — there is no meaningful dodge. Just verify the
  kind was actually UTC before replacing: `new DateTime(1970, 1, 1)` with
  unspecified kind is not the Unix epoch until you say which time zone it's
  in.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

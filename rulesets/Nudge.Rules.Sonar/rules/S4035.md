# S4035 — Classes implementing "IEquatable<T>" should be sealed

## Why
Value equality on an unsealed class is a broken promise waiting to happen: a
subclass adds a field, inherits `Equals`, and now two "equal" objects differ
in state while symmetry and hash-code guarantees quietly fall apart.

## Do this
1. Seal the class: `public sealed class OrderKey : IEquatable<OrderKey>`.
2. If the type is genuinely designed for inheritance, document the equality
   contract subclasses must honor (virtual `Equals`, careful `GetHashCode`) —
   but treat that as a deliberate design commitment, not the default.

## AVOID
- Do not work around it by sealing only the `Equals` method while leaving the
  class open. A subclass can still add state that `Equals` ignores — the
  equality contract stays broken; sealing the method doesn't seal the
  semantics.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

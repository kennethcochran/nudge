# S3060 — "is" should not be used with "this"

## Why
'this is Foo' is always true — an object is always an instance of its own
type — so the check is dead logic, usually a leftover from a copy-paste where
the left side used to be a different variable. This rule flags 'is' applied
to 'this'.

## Do this
1. Delete the check — or replace it with the comparison that was actually intended (against another variable, or a type test on a parameter).
2. Verify the surrounding branch still makes sense once the constant-true condition is gone.

## AVOID
- Do not replace 'this is Foo' with 'this as Foo != null' or 'this.GetType() == typeof(Foo)' — all still constant-true; the detector changes but the dead logic doesn't.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

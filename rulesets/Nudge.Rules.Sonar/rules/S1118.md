# S1118 — Utility classes should not have public constructors

## Why
A class of only static members cannot be meaningfully instantiated. A public
constructor invites `new Utility()` calls that produce state-free objects
and leave every reader wondering whether instances are supposed to matter —
they aren't, and the constructor says otherwise.

## Do this
1. Declare the class `static`, which also prevents instance state from
   creeping in later.
2. If the class cannot be static (e.g. it must remain inheritable for legacy
   reasons), give it a private constructor instead.

## AVOID
- Do not keep the public constructor "for future use" or "for tests." If
  instantiation ever becomes meaningful, that is a redesign of the type —
  not a constructor waiting patiently in the meantime.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

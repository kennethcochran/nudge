# S2198 — Unnecessary mathematical comparisons should not be made

## Why
Comparisons that can never be true or false — an
unsigned value `< 0`, a non-nullable struct `== null` — are dead logic.
They mislead readers into thinking a case is handled ("what happens
when it's negative?") when the case is impossible, and they suggest the
author misunderstood the type.

## Do this
1. Delete the meaningless comparison.
2. Ask why it was written: if it was guarding against underflow from a
   subtraction, restructure the arithmetic (check before subtracting,
   or use a signed/checked type) instead of testing the impossible.
3. If the value genuinely can be negative, the type is wrong — change
   the type at the source rather than testing around it.

## AVOID
- Do not cast to a signed type just to keep the comparison
  (`(int)x < 0`) — the check is still meaningless for values that can't
  be negative; fix the logic or the type instead.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2589 — Boolean expressions should not be gratuitous

## Why
The rule fires on boolean expressions that say nothing:
`if (isReady == true)`, `return flag != false`, `x && true`. The redundant
comparison adds a token the reader must parse and discard, and the
`== true` / `== false` forms are where inverted-logic bugs hide — `== false`
inverts less visibly than `!`.

## Do this
1. Drop the comparison against a literal: `isReady == true` → `isReady`,
   `isReady == false` → `!isReady`.
2. Drop identity operands: `x && true` → `x`, `x || false` → `x`.
3. Re-read the surrounding condition after simplifying — gratuitous wrappers
   often hid that the whole condition was constant.

## AVOID
- Do not "simplify" `x == true` into `x != false` — that's the same
  gratuitous comparison wearing a different operator.
- Do not leave the expression and add a comment explaining it's intentional;
  if it's intentional, the simplified form says the same thing.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

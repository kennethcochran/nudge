# S8969 — Null-forgiving operators should not be redundant

## Why
A `!` on an expression that cannot be null — a non-nullable value type, or a
reference the compiler already knows is non-null — is dead noise. It trains
readers to skim past `!`, so the operators that actually matter get ignored
too.

## Do this
1. Delete the redundant `!`; the expression's type already proves
   non-nullability, so nothing is lost.
2. If you added the `!` because the compiler warned, investigate why — the
   real fix is usually a better null check upstream, not the operator.

## AVOID
- This one is purely mechanical: deleting the operator is the complete fix. Do
  not "fix" it by widening the operand's declared type to nullable just to
  make the `!` meaningful — that weakens the type contract for the whole call
  chain to justify a single character.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3885 — "Assembly.Load" should be used

## Why
`Assembly.LoadFrom`, `LoadFile`, and `Load(byte[])` bypass the normal load
context, causing type-identity bugs — the "same" type loaded twice won't cast
to itself, and dependencies resolve differently than the rest of the app
expects. `Assembly.Load` with a full name uses the standard load context.

## Do this
1. Replace `Assembly.LoadFrom(path)` / `LoadFile(path)` / `Load(bytes)` with
   `Assembly.Load(assemblyName)` using the assembly's full display name.
2. If you only have a file path, derive the name first with
   `AssemblyName.GetAssemblyName(path)`, then `Load` it.
3. For plugin scenarios needing isolation, use `AssemblyLoadContext` — not
   `LoadFrom`.

## AVOID
- Do not "fix" it by swapping `LoadFile` for `LoadFrom` (or vice versa) —
  both bypass the load context; the rule wants `Load`.
- Do not catch the resulting `FileLoadException` / `InvalidCastException` and
  retry with a different load method — fix the load call itself.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

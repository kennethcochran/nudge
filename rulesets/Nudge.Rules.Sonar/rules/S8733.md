# S8733 — Potential Cartesian Explosion

## Why
One EF Core query with two or more `Include`s over collection navigations makes
the database return the cartesian product — 100 orders × 100 lines × 100 notes
is a million rows for 300 entities. It's a latency and memory bomb that gets
worse as the data grows, and it usually only shows up in production-sized data.

## Do this
1. Split the load: call `AsSplitQuery()` so EF issues one query per collection
   instead of one giant join, or
2. load the collections in separate queries yourself and stitch them together
   in memory.
3. If you only need a few fields, project to a DTO with `Select` instead of
   including whole entities — no cartesian product to begin with.

## AVOID
- Do not "fix" it with `AsNoTracking()` — tracking has nothing to do with the
  row multiplication; the explosion remains untouched.
- Do not slap `.Take(10)` on the outer query and call it fixed — the product
  still explodes underneath for the rows you do fetch; split the queries.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1862 — Related "if/else if" statements should not have the same condition

## Why
`if (x > 5) ... else if (x > 5) ...` — the second branch can never execute.
It's dead code, and usually one of the two conditions is a typo for the check
that was intended. The chain silently ignores a case the author believed was
handled.

## Do this
1. Figure out what the second condition was supposed to be — check git history,
   tests, or the surrounding logic — and write that.
2. If the duplicate was accidental and both branches should merge, delete the
   dead branch.
3. Add a test covering the case the dead branch was meant to handle, so the
   next typo gets caught.

## AVOID
- Do not "differentiate" the conditions with a tautology (`x > 5` versus
   `x > 5 && true`) — the branch is still dead; write the condition that was
   actually intended.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

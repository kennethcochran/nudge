# S3168 — "async" methods should not return "void"

## Why
`async void` methods can't be awaited: callers can't know when the work
finishes, and exceptions escape to the synchronization context — typically
crashing the process. The method's failure modes become unobservable by
design.

## Do this
1. Change the return type to `Task` (or `Task<T>` if it produces a value).
2. `await` the method at its call sites.
3. Keep `async void` only for event handlers, where the framework signature
   genuinely requires `void`.

## AVOID
- Do not wrap the body in a try/catch that swallows everything "because the
  caller can't observe failures" — unobservable failure is the disease, and
  swallowing is a worse symptom than the crash.
- Do not "fix" it by returning `Task` but never awaiting it at the call sites
  — fire-and-forget `Task`s have the same unobserved-exception problem, just
  one step removed.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

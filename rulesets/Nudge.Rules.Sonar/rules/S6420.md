# S6420 — Client instances should not be recreated on each Azure Function invocation

## Why
Creating an `HttpClient` (or similar client) on every
Azure Function invocation and disposing it exhausts sockets: each
disposed client leaves its connections in TIME_WAIT, and under load the
host runs out of ports. `HttpClient` is designed to be created once and
reused — it handles connection pooling and DNS refresh internally when
kept alive.

## Do this
1. Create the client once: a `static readonly` instance, a singleton
   registered in DI, or `IHttpClientFactory` — and never dispose it per
   invocation.
2. Remove the per-invocation `using`/`Dispose` on the shared client;
   disposal is what causes the exhaustion.
3. If different invocations need different configuration (headers,
   base address), use named/typed clients from `IHttpClientFactory`
   rather than constructing clients by hand.

## AVOID
- Do not make the client `static` but keep disposing it at the end of
  each invocation — disposal defeats the reuse; you're back to socket
  exhaustion with extra steps.
- Do not cache one client per input value in a static dictionary that
  grows forever — that's a leak wearing a cache's clothes.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2330 — Array covariance should not be used

## Why
C# lets you assign `string[]` to `object[]` (array covariance), but the
array is still a `string[]` at runtime — so `objects[0] = 42` compiles and
then throws `ArrayTypeMismatchException`. The type system promises something
the runtime can't honor; it's a hole that turns compile-time-safe-looking
code into a runtime bomb, hence CRITICAL.

## Do this
1. Use the concrete array type (`string[]`) at the declaration and
   parameter sites instead of the base array type.
2. If you need a read/write collection of a base type, use `List<object>` /
   `IList<object>` — generics are invariant, so the hole doesn't exist.
3. For read-only access, `IReadOnlyList<object>` (or `IEnumerable<object>`)
   is safe: covariance is sound when there's no writing.

## AVOID
- Do not keep the covariant array and add a cast at each write site
  (`((string[])objects)[0] = ...`) — you've just moved the runtime check
  into your code by hand.
- Do not "fix" it by catching `ArrayTypeMismatchException`; the exception
  means the design is wrong, not that the operation needs a fallback.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

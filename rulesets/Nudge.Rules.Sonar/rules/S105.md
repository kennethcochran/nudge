# S105 — Tabulation characters should not be used

## Why
Tabs render at unpredictable widths — 4 columns in your editor, 8 in the
diff viewer, something else in the next person's IDE — so tab-indented code
misaligns everywhere except the author's screen. Mixed tabs and spaces are
worse: the code looks aligned in one tool and staggered in another, hiding
real indentation errors.

## Do this
1. Convert tabs to spaces with the IDE's "convert tabs to spaces" /
   reformat command (or `dotnet format`), using the project's indent width
   (4 spaces is the C# default).
2. Enable "insert spaces for tabs" in your editor so new code doesn't
   reintroduce them.
3. Check the whole file, not just the flagged line — tab usage is usually
   file-wide.

## AVOID
- Do not replace tabs with a *different* number of spaces per line to
  "preserve alignment" — uniform indentation is the point; per-line
  tweaking recreates the misalignment by hand.
- Do not fix only the flagged lines while the rest of the file still uses
  tabs; the next edit reintroduces the inconsistency.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

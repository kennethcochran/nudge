# S2674 — The length returned from a stream read should be checked

## Why
`Stream.Read` is allowed to return fewer bytes than requested — network
streams, pipes, and crypto streams do this routinely. Code that ignores the
return value processes a partially-filled buffer as if it were full:
truncated data, stale bytes from a previous read, or a hang waiting for more.

## Do this
1. Capture the return value and loop until the buffer is full or the stream
   ends:
   `while (read < count) { var n = stream.Read(buffer, read, count - read); if (n == 0) break; read += n; }`
2. On modern targets, prefer `stream.ReadExactly(buffer)` (or `ReadAtLeast`),
   which performs the loop for you and throws on premature end-of-stream.

## AVOID
- Do not check the return value with a single `if (read > 0)` and then proceed
  as if the whole buffer were filled. A partial read passes that check and
  still leaves the tail of the buffer uninitialized — the check must drive a
  loop, or be delegated to `ReadExactly`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

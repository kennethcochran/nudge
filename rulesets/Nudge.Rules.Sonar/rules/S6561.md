# S6561 — Avoid using "DateTime.Now" for benchmarking or timing operations

## Why
DateTime.Now is a wall clock, not a stopwatch: ~15ms resolution on Windows
plus NTP clock adjustments, which means quantization noise and even backwards
time. Code that measures elapsed time with it gets garbage precision. This
rule flags DateTime.Now used for benchmarking or timing.

## Do this
1. Use System.Diagnostics.Stopwatch (StartNew / GetTimestamp) for measuring intervals.
2. For timestamps of events rather than durations, prefer DateTime.UtcNow — but that is event time, not a benchmark.
3. If the code computes durations from two DateTime.Now samples, rewrite it around a single Stopwatch.

## AVOID
- Do not switch DateTime.Now to DateTime.UtcNow and call it a benchmark fix — UtcNow is cheaper but its resolution is still far too coarse for timing; the Stopwatch is the point.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

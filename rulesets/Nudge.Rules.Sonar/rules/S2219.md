# S2219 — Runtime type checking should be simplified

## Why
`x.GetType() == typeof(Foo)` and manual `as`-plus-null-check chains are
verbose, miss inheritance relationships, and duplicate what pattern matching
expresses in one readable construct. They also tend to rot: the type name in
the comparison drifts out of sync with refactors.

## Do this
1. Replace `GetType() == typeof(T)` checks with `is` patterns
   (`x is Foo f`), which handle inheritance correctly.
2. Replace `var f = x as Foo; if (f != null)` with `x is Foo f` directly in
   the condition.
3. Keep an exact-type check only when derived types must genuinely be
   excluded, and leave a comment saying why.

## AVOID
- Do not hide the `GetType()` comparison inside a helper method
  (`IsExactlyFoo(x)`). The verbosity moves; the fragility and the missed
  inheritance stay.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

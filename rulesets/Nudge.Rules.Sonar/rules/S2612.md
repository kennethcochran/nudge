# S2612 — File permissions should not be set to world-accessible values

## Why
Creating files with world-readable or world-writable permissions (Unix mode
`0o777`, or `UnixFileMode` with Other bits set) exposes their contents — keys,
tokens, user data — to every account on the machine. Once you set modes
explicitly, the default umask is no longer a backstop.

## Do this
1. At the flagged file-creation call, replace the world-accessible mode with
   the minimum the file needs — typically owner read/write only
   (`UserRead | UserWrite`) for sensitive files.
2. Ask whether the file needs group/other access at all; prefer the most
   restrictive mode that still works.
3. If the file holds secrets, reconsider whether it should exist on disk at
   all versus living in a secret store.

## AVOID
- Do not set a permissive mode at creation and "fix" it with a chmod-style
  call further down. The file exists with weak permissions in between, and the
  two-step dance is exactly what the rule flags — set the restrictive mode in
  the creation call itself.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

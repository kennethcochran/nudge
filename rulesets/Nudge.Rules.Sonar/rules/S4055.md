# S4055 — Literals should not be passed as localized parameters

## Why
Passing a hard-coded literal where a localized string
belongs breaks localization: the localizer works from resource files,
and a literal embedded in code (or concatenated from fragments) can
never be translated. Users in other locales get a mix of translated UI
and untranslated fragments.

## Do this
1. Move the entire message template into the resource file with
   placeholders (`"File {0} not found"`), not fragments.
2. Pass only runtime values as the format parameters at the call site.
3. Verify the flagged call site now references the resource string, and
   check neighboring literals for the same problem.

## AVOID
- Do not build the message with concatenation or interpolation of
  literals (`"Error: " + code`) to dodge the rule — the localizer still
  can't translate the fragments; the whole template must live in the
  resource.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

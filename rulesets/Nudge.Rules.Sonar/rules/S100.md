# S100 — Methods and properties should be named in PascalCase

## Why
Public .NET API surface follows PascalCase for methods
and properties; a non-conforming name sticks out in IntelliSense,
breaks the codebase's visual consistency, and — for libraries — looks
unprofessional to consumers. The fix is mechanical but must be
complete.

## Do this
1. Rename the flagged member to PascalCase.
2. Update all call sites, including named-argument usages.
3. Check non-compiler references to the old name: reflection
   (`nameof`/string lookups), serialization attributes, docs, and
   config files that name the member.

## AVOID
- Do not rename only the declaration while leaving stringly-typed
  references (reflection, JSON property names, docs) pointing at the old
  name — the rename isn't done until every reference is consistent.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S5443 — Temporary files should not be created in publicly writable directories

## Why
The flagged code creates a temp file at a predictable path in a world-writable directory (a hardcoded `/tmp/...` name, or the shared temp root addressed by name). Another local user can pre-create that path as a symlink — redirecting your writes to their target — or simply read the file you left behind. This is a TOCTOU/symlink attack, not a tidiness issue.

## Do this
1. Use `Path.GetTempFileName()`, or `Path.GetTempPath()` + `Path.GetRandomFileName()`, so the runtime creates the file atomically in the user's private temp directory.
2. If you must use a fixed directory, create it with restrictive ACLs and open files with options that fail if the file already exists.
3. Set minimal permissions on the created file.

## AVOID
- Do not keep the predictable path but append `Guid.NewGuid()` and call it safe — unpredictability alone doesn't fix the shared-directory symlink race; atomic creation in a private dir does.
- Do not build the temp path by concatenating an environment variable an attacker may influence.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

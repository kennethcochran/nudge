# S4002 — Disposable types should declare finalizers

## Why
A type that directly owns an unmanaged resource (raw IntPtr, OS handle)
with no finalizer leaks that resource if Dispose is never called — the GC
can't see native memory. This rule flags disposable types holding unmanaged
resources without a finalizer.

## Do this
1. Best fix: stop holding the raw resource — wrap it in SafeHandle (or a SafeHandle-derived type) and let its critical finalizer own the lifetime; your type then needs no finalizer at all.
2. If SafeHandle genuinely can't cover it, add a finalizer (~MyType()) that releases only the unmanaged resource and calls Dispose(false).
3. Make sure Dispose(bool) distinguishes managed from unmanaged cleanup per the standard pattern.

## AVOID
- Do not add an empty finalizer to satisfy the rule — an empty ~MyType() {} adds GC cost (finalizer queue) while freeing nothing.
- Do not touch managed objects from the finalizer; it runs on the GC thread after those objects may already be collected.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6673 — Log message template placeholders should be in the right order

## Why
Structured logging binds placeholders to arguments positionally: `{UserId}` in
the second slot with the user id passed third logs the wrong value under the
right name. Every downstream query, dashboard, and alert built on that field
then silently reports fiction.

## Do this
1. Reorder the arguments to match the placeholder sequence — or reorder the
   placeholders to match the arguments, whichever keeps the names meaningful.
2. Keep placeholder names stable: they are the schema your log queries and
   alerts are built on.
3. Use a logging analyzer (or a unit test over the template) that verifies
   template/argument pairing so the next edit can't silently re-break it.

## AVOID
- Do not rename the placeholders to match the misordered arguments — the
  names are the contract with your queries and dashboards; the argument order
  is what's wrong.
- Do not "fix" it by switching to string interpolation — that destroys the
  structured template entirely, trading mislabeled fields for no fields.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

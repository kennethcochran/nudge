# S6513 — "ExcludeFromCodeCoverage" attributes should include a justification

## Why
`[ExcludeFromCodeCoverage]` without a reason lets untested code hide silently:
future readers can't tell whether the exclusion was deliberate (generated code,
an untestable platform shim) or just coverage-padding.

## Do this
1. Add `Justification = "..."` naming the real reason, e.g. "DTO with no
   behavior", "platform-specific interop not exercisable in unit tests", or
   "generated code".
2. If you can't write an honest justification, treat that as the signal: the
   code should be tested instead — write the test and drop the attribute.

## AVOID
- Do not add an empty or placeholder justification (`Justification = ""`,
  `"n/a"`, `"TODO"`). A justification that justifies nothing is the same as
  no justification; the rule wants a reason a human can evaluate.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

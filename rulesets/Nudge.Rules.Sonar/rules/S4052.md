# S4052 — Types should not extend outdated base types

## Why
Inheriting from legacy non-generic bases (`CollectionBase`, `DictionaryBase`,
`ReadOnlyCollectionBase`, and their kin) drags in boxing, weak typing, and
APIs superseded by generics two decades ago. Every consumer pays the
performance and type-safety cost of the obsolete base.

## Do this
1. Replace the base with the modern generic equivalent (`Collection<T>`,
   `Dictionary<TKey, TValue>`, `ReadOnlyCollection<T>`).
2. Update overridden members to the generic signatures and drop the casts the
   old base forced on callers.
3. Run the tests for the type and its consumers.

## AVOID
- Do not "fix" it by inserting a new derived type that still inherits the
   outdated base — the legacy API is still the foundation. Replace the base
   class itself.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

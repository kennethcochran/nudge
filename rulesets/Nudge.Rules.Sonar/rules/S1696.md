# S1696 — NullReferenceException should not be caught

## Why
Catching `NullReferenceException` treats the symptom of a bug as an expected
condition. The null has a cause — an uninitialized field, a missing guard, a
method returning null against its contract — and catching the exception hides
that cause while leaving program state unpredictable after the catch.

## Do this
1. Find what is null on the throwing path; the diagnostic location is the
   starting point, not the answer — trace it back to the source.
2. Fix the cause: initialize the field, add an explicit null guard
   (`ArgumentNullException.ThrowIfNull`), or handle the absent value as a
   real case.
3. Remove the `catch (NullReferenceException)` block.
4. Add a test for the previously-null path.

## AVOID
- Do not replace `catch (NullReferenceException)` with `catch (Exception)` —
   that is a broader version of the same dodge. Fix the null at its source.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

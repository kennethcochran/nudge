# S3427 — Method overloads with default parameter values should not overlap

## Why
When `Foo(int a)` coexists with `Foo(int a, int b = 0)`, a call like `Foo(5)`
is ambiguous or resolves in surprising ways, and one overload becomes
unreachable dead weight. The API lies about its own shape.

## Do this
1. Decide which overload is the real one: usually keep the single method with
   default values and delete the redundant overload.
2. If the overloads genuinely differ (different parameter types, not just
   arity), remove the default values that create the overlap.
3. Check call sites after the change — overload resolution may now pick a
   different method; the compiler will tell you.

## AVOID
- Do not "resolve" the overlap by adding a dummy parameter to one overload —
   you've kept both confusing signatures and added noise.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

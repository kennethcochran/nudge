# S2757 — Non-existent operators like "=+" should not be used

## Why
`x =+ 1` parses as `x = +1` — assignment of positive one, not increment. It
compiles, it runs, and it silently resets `x` instead of adding to it. The
same typo family includes `=-`, `=*`, and `=/`.

## Do this
1. Write what you meant: `x += 1;` (or `x++`).
2. Scan the surrounding code for the sibling typos (`=-`, `=*`, `=/`) — they
   travel together.

## AVOID
- This rule is mechanical — there is no meaningful dodge. Just confirm the
  intent was addition before "fixing": if the code genuinely meant assignment
  of a unary-plus value (vanishingly rare), say so explicitly with parentheses
  and a comment so the next reader doesn't "fix" it back.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

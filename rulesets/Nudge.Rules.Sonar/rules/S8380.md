# S8380 — Return types named "partial" should be escaped with "@"

## Why
`partial` is a contextual keyword in C#, and a type
named `partial` used as a return type (or anywhere a type name appears)
creates parsing ambiguity for the compiler and confusion for readers —
`partial Foo Bar()` doesn't read as a method returning `partial` the
way `Foo Bar()` reads as returning `Foo`.

## Do this
1. Rename the type to something that describes what it is
   (`PartialResult`, `PartialMatch`, …) — preferred when you own the
   type.
2. If the name is fixed by an external contract you can't change,
   escape it with `@partial` at the use site.
3. Update all references so the escaped or renamed form is used
   consistently.

## AVOID
- Do not rename to `Partial2` or `partialClass` just to dodge the
  rule — pick a name that describes the type, or escape it properly with
  `@`.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

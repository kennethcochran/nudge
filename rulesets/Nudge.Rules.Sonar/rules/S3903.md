# S3903 — Types should be defined in named namespaces

## Why
A type in the global namespace collides with any other global type of the same name — including ones from future dependencies — and it can't be disambiguated with a `using`. It's a name-collision bomb with a long fuse.

## Do this
1. Wrap the type in a namespace matching the project structure (e.g. `MyApp.Core`).
2. Fix any references that break (usually none — same-assembly references resolve fine).

## AVOID
- Do not "fix" it with a vague catch-all namespace like `Common` shared across unrelated files — put the type in the namespace it actually belongs to.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2583 — Conditionally executed code should be reachable

## Why
A condition the analyzer can prove always true (or always false) means one
branch is dead: either the logic is wrong and the live branch isn't the
intended one, or the dead code misleads readers about what can happen. This
rule flags provably constant conditions.

## Do this
1. Determine which is wrong: the condition or the surrounding code. Fix the logic so the condition can actually vary, or delete the dead branch if the constant outcome is correct.
2. Inspect the values feeding the condition — a hardcoded flag or an assignment just above (x = 5; if (x > 10)) is usually the real culprit.
3. After the fix, both branches should be reachable in principle; add a test covering each.

## AVOID
- Do not make the condition textually non-constant without changing the logic — e.g. comparing against a method that always returns the same value — dead code with extra steps.
- Do not delete the live branch and keep the dead one by mistake; verify which branch the tests actually exercise.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

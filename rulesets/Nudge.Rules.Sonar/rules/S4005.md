# S4005 — "System.Uri" arguments should be used instead of strings

## Why
A `string`-typed URI parameter accepts `"not a uri"` and defers the failure
to parse time, deep inside the method. `System.Uri` pushes validation to the
boundary — invalid input is rejected before it enters — and gives you
`Scheme`, `Host`, and `AbsolutePath` parsing for free instead of hand-rolled
string splitting.

## Do this
1. Change the parameter type to `System.Uri`.
2. Let callers construct it, or validate once at the entry point with
   `Uri.TryCreate` and reject invalid input there.
3. Replace manual string splitting on the URI with `Uri` properties.

## AVOID
- Do not keep the `string` parameter and add `Uri.TryCreate` at the top of
  every method — the validation belongs in the type, not copy-pasted into
  each body.
- Do not "fix" it by accepting `string` and throwing `UriFormatException`
  yourself — you've reimplemented the constructor's validation worse than the
  constructor does it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

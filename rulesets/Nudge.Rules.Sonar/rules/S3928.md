# S3928 — Parameter names used into ArgumentException constructors should match an existing one

## Why
`throw new ArgumentNullException("nmae")` with a misspelled or wrong parameter name points the debugger — and the reader — at the wrong parameter. The one piece of information the exception exists to convey is wrong, so the throw actively misdirects debugging.

## Do this
1. Pass `nameof(theActualParameter)` instead of a string literal.
2. Verify the named parameter is the one actually being validated at that throw site.

## AVOID
- Do not just fix the typo in the string literal and keep the literal — the next rename breaks it again silently; `nameof` is refactor-safe.
- Do not pass `nameof` of a different, similarly-named parameter.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

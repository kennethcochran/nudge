# S1449 — Culture should be specified for "string" operations

## Why
String operations like Compare, StartsWith, IndexOf, or ToUpper/ToLower
without an explicit culture or StringComparison silently use the current
thread culture — the same code behaves differently on a Turkish vs. a US
machine (the Turkish-I being the classic breakage), corrupting sorting,
lookup keys, and parsing. This rule flags the implicit-culture overloads.

## Do this
1. Pass an explicit StringComparison (Ordinal / OrdinalIgnoreCase for programmatic strings; CurrentCulture(gnoreCase) only for user-facing text) or an explicit CultureInfo.
2. Choose deliberately per call site: keys, protocols, and file formats want Ordinal; displayed text wants the user's culture.
3. Sweep the file for sibling calls with the same omission.

## AVOID
- Do not pass CultureInfo.CurrentCulture everywhere to silence the rule — that just writes down the ambient behavior you already had; the point is to choose Ordinal where the string is programmatic.
- Do not 'fix' StartsWith(x) by switching to ToUpper() comparisons; that trades one culture bug for another.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

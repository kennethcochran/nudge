# S3967 — Multidimensional arrays should not be used

## Why
`int[,]` is not CLS-compliant, indexes awkwardly, and performs worse than
jagged arrays in common access patterns — the CLR optimizes single-dimension
array access, while multidimensional indexing goes through a slower path.
It's also unfamiliar to most C# readers, who reach for `[][]` or
collections first.

## Do this
1. Replace `int[,]` with a jagged array `int[][]`, adjusting initialization
   (`new int[rows][]` plus per-row allocation) and indexing (`[i][j]`).
2. If rectangularity is a real invariant, wrap the jagged array in a small
   type that enforces equal row lengths at construction.
3. Update method signatures and call sites together — array rank is part of
   the type, so this is a compile-checked mechanical change.

## AVOID
- Do not hide the `int[,]` inside a wrapper class while keeping it as the
  storage — the non-compliant, slow shape is still there.
- Do not replace it with `Array.CreateInstance(typeof(int), lengths)`
  tricks; that's the same multidimensional array with reflection syntax.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2183 — Integral numbers should not be shifted by zero or more than their number of bits-1

## Why
Shifting by 0 is a no-op that suggests the author thought something was
happening; shifting an `int` by 32 or more (a `long` by 64 or more) is
worse — C# masks the shift count (`count & 31`), so `x << 32` silently
behaves as `x << 0`, which is almost never the intent. Both usually indicate
a wrong constant or a copy-paste from a different width.

## Do this
1. If the shift amount is a constant that's wrong (e.g. `<< 32` meant for a
   64-bit value), fix the constant or widen the operand to the intended
   width first.
2. If the shift is genuinely `<< 0`, delete it — it's a dead operation.
3. If the shift count is computed, add a guard or debug assertion that it's
   within `[1, bits - 1]` so the next wrong value fails loudly instead of
   silently masking.

## AVOID
- Do not "fix" an over-wide shift by masking it yourself
  (`x << (n & 31)`) — C# already masks; explicit masking just blesses the
  silent wraparound.
- Do not widen the operand (cast to `long`) while keeping the wrong
  constant if the surrounding code is 32-bit — the value changes meaning
  downstream.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1006 — Method overrides should not change parameter defaults

## Why
Default parameter values bind at the *caller's* compile time from the
*static* type — so if `Base.M(x = 1)` is overridden as `override M(x = 2)`,
a caller holding a `Base` reference still gets `1` while a caller holding
the derived type gets `2`. The override's default is a trap: it looks like it
changes behavior, but only for some callers, silently.

## Do this
1. Remove the default value from the override entirely — the base
   declaration's default is the one that applies, and the override must
   accept it.
2. If you genuinely need different defaults per type, don't use overriding
   for it: add a non-virtual overload or a differently-named method on the
   derived class.
3. Check interface implementations too — the same rule applies when the
   default is declared on the interface.

## AVOID
- Do not "fix" it by making the override's default match the base's and
  leaving both — the duplication will drift again; the override should
  declare no default at all.
- Do not work around it with `[Optional]` / `[DefaultParameterValue]`
  attributes on the override; that's the same trap with COM-interop syntax.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3059 — Types should not have members with visibility set higher than the type's visibility

## Why
A `public` member on an `internal` class is unreachable outside the assembly —
the wider visibility is a lie suggesting API surface that doesn't exist. It
also misleads API-review tooling and the next developer, who reads "public"
as a compatibility promise.

## Do this
1. Reduce the member's visibility to match (or sit below) the type's.
2. If the member genuinely needs to be public API, make the *type* public —
   but that's a permanent API-surface commitment, so make it deliberately and
   document it.
3. Check `InternalsVisibleTo` consumers before narrowing, so friend
   assemblies don't break.

## AVOID
- Do not make the type `public` just to match the member without thinking —
  a public type is a forever promise to external consumers; narrowing the
  member is usually the right call.
- Do not "fix" it by adding a public wrapper type around the internal one —
  you've laundered the visibility instead of deciding what the API surface
  should be.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

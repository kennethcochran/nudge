# S4023 — Interfaces should not be empty

## Why
An empty interface is a marker with no contract — it can't be consumed
polymorphically (there's nothing to call), and readers can't tell what
implementing it promises. Most marker interfaces are better expressed as
attributes; the rest are unfinished abstractions.

## Do this
1. If the interface marks types for reflection or DI purposes, replace it with
   an attribute — attributes are the idiomatic marker mechanism.
2. If it's an unfinished abstraction, add the members the implementations
   already share (look at what the implementers have in common).
3. If nothing implements it and nothing will, delete it.

## AVOID
- Do not add a meaningless member (a `void Marker();` nobody calls) just to
   make the interface non-empty — an unused member is the same lie with more
   text.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

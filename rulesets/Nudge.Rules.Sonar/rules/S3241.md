# S3241 — Methods should not return values that are never used

## Why
A method that computes and returns a value no caller uses is either dead logic
(the computation is wasted and misleading) or a caller bug (someone forgot to
use the result). Either way, the signature lies about the contract.

## Do this
1. If callers should use the value, fix the callers to consume the return.
2. If nobody needs it, change the method to return `void` — make the
   signature honest.
3. Check test fakes and mocks too — a stubbed return nobody asserts on is the
   same smell.

## AVOID
- Do not "fix" it with `_ = Compute();` at every call site — discarding the
  value everywhere keeps the lying signature; change the method or use the
  value.
- Do not "use" the value by logging it and moving on when the value was meant
  to drive control flow — that's observability theater, not a fix.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3447 — "[Optional]" should not be used on "ref" or "out" parameters

## Why
[Optional] on a ref or out parameter is a promise the runtime cannot keep:
optional parameters need a default value the caller can omit, but ref/out
demand a real variable at the call site, so the attribute is silently ignored
and callers must pass the argument anyway. This rule flags the meaningless
combination.

## Do this
1. Remove [Optional] and provide overloads: one with the parameter, one without, with the shorter forwarding a sensible default variable.
2. If the parameter is genuinely sometimes-unneeded output, consider returning a result object instead of using out.
3. Check COM-interop callers — if the signature exists for COM, restructure the interop surface rather than keeping a broken attribute.

## AVOID
- Do not keep [Optional] and add [DefaultParameterValue] beside it on a ref/out parameter — the combination is still unrepresentable and still ignored.
- Do not change ref to a nullable value parameter without checking every caller's definite-assignment expectations.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

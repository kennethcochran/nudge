# S6781 — JWT secret keys should not be disclosed

## Why
A JWT signing key that appears in source code, logs, error messages, or API
responses lets anyone mint valid tokens and impersonate any user. Disclosure
is usually permanent — once committed or logged, the key must be treated as
burned.

## Do this
1. Remove the key from wherever it is disclosed: the source file, the log
   statement, or the response payload.
2. Load the key at runtime from a secret store or environment variable, and
   audit where it has already leaked (git history, log aggregators) to decide
   whether rotation is required.
3. If there is any chance the key was exposed, rotate it: generate a new key
   and invalidate tokens signed with the old one.

## AVOID
- Do not base64-encode the key, split it into concatenated string pieces, or
  move it to a config file that ships with the app and call it fixed.
  Obfuscation is still disclosure; the key must live outside the codebase and
  outside the log stream.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3963 — "static" fields should be initialized inline

## Why
Static fields assigned in a static constructor (or lazily inside methods)
scatter initialization away from the declaration: readers must hunt for the
value, and ordering bugs creep in as the class grows. An inline initializer
runs in declaration order, sits next to the type it initializes, and is
obvious at a glance.

## Do this
1. Move the assignment into the field declaration:
   `private static readonly Foo _x = new Foo(...);`
2. If initialization needs non-trivial logic, put it in a private static
   helper method called from the initializer — the declaration stays the
   single source of the value.
3. Delete the static constructor if nothing else uses it.

## AVOID
- Do not "fix" it by moving the assignment into a static property getter
   that re-creates the value on every access — that changes semantics (and
   thread-safety). Initialize once, inline, at the declaration.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

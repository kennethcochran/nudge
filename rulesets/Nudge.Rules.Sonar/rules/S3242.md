# S3242 — Method parameters should be declared with base types

## Why
Taking `List<T>` when the body only enumerates forces every caller to
materialize a `List` — arrays, LINQ results, and other sequences are rejected
for no reason. The most general type the body actually uses keeps the method
usable by the widest set of callers.

## Do this
1. Take the most general type the body uses: `IEnumerable<T>` for
   enumeration, `IReadOnlyList<T>` for indexing, `ICollection<T>` when you
   need `Count` plus mutation.
2. Check the body first — don't generalize past what it actually calls
   (no `IEnumerable<T>` if the body indexes).
3. Keep the concrete type only where the implementation genuinely depends on
   it.

## AVOID
- Do not change the parameter to `IEnumerable<T>` and then call `.ToList()`
  first thing in the body "for convenience" — you've re-imposed the
  materialization cost on every caller while pretending to accept anything.
- Do not generalize the parameter but leave XML docs promising `List`
  semantics — the contract readers see should match the contract callers get.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

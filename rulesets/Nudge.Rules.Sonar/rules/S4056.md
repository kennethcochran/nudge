# S4056 — Overloads with a "CultureInfo" or an "IFormatProvider" parameter should be used

## Why
`ToString()`, `Parse`, `string.Compare`, and friends without a culture
parameter use the *current thread culture* — so `"3.14".Parse` works on a US
machine and throws on a German one, and sort orders change with locale. The
behavior of your code silently depends on where it runs, which is how "works
on my machine" bugs are born.

## Do this
1. Decide per call site: machine-readable data (persistence, wire formats,
   parsed config) → `CultureInfo.InvariantCulture`; human-facing display →
   `CultureInfo.CurrentCulture` (or the UI culture).
2. Switch to the overload taking `IFormatProvider` / `CultureInfo` and pass
   the chosen culture explicitly.
3. For string comparison, prefer the `StringComparison` overload (`Ordinal`
   / `OrdinalIgnoreCase` for identifiers and protocols) over
   culture-sensitive comparison.

## AVOID
- Do not pass `CultureInfo.CurrentCulture` everywhere reflexively — for
  persisted/parsed data that's just the implicit default made explicit, and
  it stays locale-fragile; `InvariantCulture` is the fix for machine data.
- Do not "fix" it by setting the thread's culture globally at startup; that
  papers over every call site and breaks libraries that depend on the
  ambient culture.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

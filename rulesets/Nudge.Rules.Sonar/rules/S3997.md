# S3997 — String URI overloads should call "System.Uri" overloads

## Why
An API taking a URI as `string` skips validation — malformed URIs fail deep
inside with confusing errors, and every caller re-implements parsing slightly
differently. The `Uri` type validates at construction; the string overload
should be a thin convenience that parses once and delegates.

## Do this
1. Add (or locate) the overload taking `System.Uri`.
2. Make the `string` overload parse once (`new Uri(uriString, ...)` with the
   appropriate `UriKind`) and delegate to the `Uri` overload.
3. Put all real logic in the `Uri` overload — the string one does parsing and
   nothing else.

## AVOID
- Do not duplicate the method body in both overloads — one implementation (the
   `Uri` one), one thin adapter.
- Do not "validate" the string with a regex and then pass the raw string
   deeper; parse to `Uri` and delegate.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

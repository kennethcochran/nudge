# S2068 — Credentials should not be hard-coded

## Why
The rule fires on passwords, API keys, and connection-string secrets written
as string literals in source. Source code is copied, logged, indexed, and
eventually leaked — a secret in a literal is shared with everyone who ever
sees the repo, including future public mirrors. Rotation is painful too:
every key change becomes a code change, rebuild, and redeploy.

## Do this
1. Move the credential out of source into configuration or a secrets store:
   environment variables, user-secrets in development, Azure Key Vault / AWS
   Secrets Manager / HashiCorp Vault in production.
2. Read it at startup via `IConfiguration` (or equivalent) so rotation never
   requires a rebuild.
3. Rotate the exposed credential now — assume anything ever committed is
   compromised — and scrub it from git history if it was pushed.

## AVOID
- Do not move the literal into a `Constants` class, a `.resx`, or a config
  file checked into the repo — that's the same exposure in a different
  drawer.
- Do not Base64-encode, encrypt-with-a-hardcoded-key, or split the string
  into concatenated pieces; obfuscation is not secret management, and the
  decoder sits right next to it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2223 — Non-constant static fields should not be visible

## Why
A `public static` mutable field is global writable state: any code in the
process can change it, breaking invariants and making behavior depend on call
order. It is the field equivalent of a global variable, and it defeats
thread-safety reasoning for the whole type.

## Do this
1. If the value never changes after initialization, make the field
   `private static readonly` (or `const`) and expose it through a get-only
   property if callers need to read it.
2. If it genuinely must be mutable shared state, make the field private and
   expose controlled mutation — a method that validates, or a thread-safe
   accessor — so the invariant lives in one place.

## AVOID
- Do not convert it to a public static auto-property with a public setter.
  That is the same globally writable state with nicer syntax; the rule's
  concern is the writability, not the field-versus-property spelling.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

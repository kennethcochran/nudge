# S3458 — Empty "case" clauses that fall through to the "default" should be omitted

## Why
case 1: case 2: default: — empty case labels that fall through to default
are noise: default already covers them, so the labels add reading cost plus a
future trap (someone adds code to 'case 1:' expecting it to run only for 1,
not realizing it falls through). This rule flags empty cases falling into
default.

## Do this
1. Delete the empty case labels and let default handle those values — that is what it was already doing.
2. If a value genuinely needs distinct handling later, add the case with its body then, not as an empty placeholder now.

## AVOID
- Do not add 'break;' to the empty cases to silence the rule — that changes behavior: values that used to fall through to default now hit an empty case and skip the default logic entirely.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

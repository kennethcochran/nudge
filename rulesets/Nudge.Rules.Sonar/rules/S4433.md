# S4433 — LDAP connections should be authenticated

## Why
The rule fires when a `DirectoryEntry` (or `LdapConnection`) is created with
anonymous or unauthenticated settings — `AuthenticationTypes.Anonymous`,
`AuthenticationTypes.None`, or no credentials at all. An unauthenticated
bind exposes directory reads (and sometimes writes) to anyone who can reach
the server, and simple binds send credentials in cleartext. Directory
servers are high-value targets; anonymous access is rarely intended.

## Do this
1. Bind with explicit credentials and `AuthenticationTypes.Secure`
   (Kerberos/NTLM) at minimum.
2. If traffic crosses an untrusted network, layer
   `AuthenticationTypes.SecureSocketsLayer` (LDAPS) on top so the bind
   itself is encrypted.
3. Confirm the application actually needs the access level it binds with —
   use a least-privilege service account, not a domain admin.

## AVOID
- Do not pass empty-string credentials with `AuthenticationTypes.None` —
  that is still an anonymous bind with extra steps.
- Do not "fix" it by catching the authentication failure and falling back
  to an anonymous bind; a fallback path is an unauthenticated path.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

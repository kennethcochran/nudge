# S2970 — Assertions should be complete

## Why
The flagged assertion performs no check: a bare FluentAssertions `.Should()` with no chained matcher, an `Assert.That(x)` with no constraint, or a tautology like `Assert.True(true)`. It yields a passing test that verifies nothing — inflating the suite's count while covering zero behavior.

## Do this
1. Find what the test was meant to verify and write the real check: chain the matcher (`.Should().Be(expected)`), supply the constraint, or put the genuine expected value in the assertion.
2. If the test cannot meaningfully assert anything, delete the test — a test that can't fail is worse than no test, because it pretends coverage exists.

## AVOID
- Do not "complete" it with a tautology (`Assert.AreEqual(x, x)`, asserting a value against itself) — a passing-by-construction assertion is the same lie.
- Do not replace it with `Assert.Pass()` — that just renames the no-op.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

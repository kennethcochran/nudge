# S8368 — Identifiers should not conflict with the C# 14 "extension" contextual keyword

## Why
`extension` became a contextual keyword in C# 14 (extension members). Using it
as a variable, parameter, or member name compiles today but confuses every
reader — and any future language change can turn your identifier into a syntax
error.

## Do this
1. Rename the identifier to something that says what it holds:
   `fileExtension`, `ext`, `targetExtension`.
2. Search the whole solution for other uses of `extension` as an identifier
   and rename them the same way, so the codebase is uniformly clean.

## AVOID
- Do not "fix" it with the verbatim escape (`@extension`) — it silences the
  diagnostic while keeping the confusing name; rename it properly.
- Do not rename to `Extension` (capitalized) — same confusion, different
  casing; pick a name that doesn't collide at all.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

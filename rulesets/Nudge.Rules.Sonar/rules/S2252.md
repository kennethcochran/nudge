# S2252 — For-loop conditions should be true at least once

## Why
`for (i = 10; i < 10; i++)` never executes its body — almost always a bounds
mix-up: wrong initializer, flipped comparison, or an off-by-one in the limit.
It's dead code that looks alive, and its body was never tested.

## Do this
1. Work out the intended range and fix whichever of the initializer or the
   condition is wrong.
2. If the loop is intentionally conditional, rewrite it as a `while` or guard
   the `for` with an `if` so the intent is explicit.
3. Re-run the surrounding tests — a loop that never ran means its body has
   zero coverage.

## AVOID
- Do not "fix" it by nudging the condition to be trivially true once (e.g.
  `i <= 10` when the intent was `< n`) without checking the intended bounds —
  you'll trade a dead loop for an off-by-one.
- There is no cosmetic dodge for this rule; the loop either runs or it
  doesn't. Verify the bounds against the actual data, not the diagnostic.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

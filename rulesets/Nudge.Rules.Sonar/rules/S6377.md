# S6377 — XML signatures should be validated securely

## Why
Proving an XML signature is cryptographically well-formed is only half the
job. SignedXml.CheckSignature() with no trusted key merely proves the document
was signed by somebody, and a valid signature whose references don't cover the
elements you act on still lets an attacker swap the payload. This rule flags
signature validation that skips the trust decision.

## Do this
1. Validate the signature against a specific trusted key or certificate — pin the expected signer and never accept 'any valid signature'.
2. Verify that the signed references actually cover the XML you are about to act on: check the Reference URIs and digests, not just the signature value.
3. Reject documents carrying unexpected transforms, or elements you depend on that fall outside the signed references.

## AVOID
- Do not call CheckSignature() with no key argument and treat 'true' as trusted — that only proves the document was signed by somebody.
- Do not validate the signature and then read values from elements outside the signed references; the verified part and the used part must coincide.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

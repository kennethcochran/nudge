# S3353 — Unchanged variables should be marked as "const"

## Why
A local variable or field that is assigned once and
never modified should be `const`: it tells the reader the value is
fixed, lets the compiler enforce that, and (for locals) enables
constant folding. A non-const "constant" invites a future edit that
accidentally mutates what was meant to be fixed.

## Do this
1. Mark the variable `const` (it must be initialized with a
   compile-time constant expression).
2. If the value is fixed at construction time but not a compile-time
   constant, `readonly` is the correct tool — that's a different,
   legitimate case, not a fallback for const-able values.

## AVOID
- Do not mark it `readonly` (or `static readonly`) when the value is
  a compile-time constant just to avoid the `const` keyword — `const`
  is the precise declaration of "this value never changes, ever".
- Do not assign the value from a method call to make it "not const-able"
  when a literal would do.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

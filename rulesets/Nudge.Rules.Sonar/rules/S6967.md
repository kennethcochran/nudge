# S6967 — ModelState.IsValid should be called in controller actions

## Why
Model binding and validation attributes (`[Required]`, `[Range]`, `[EmailAddress]`)
run before your action body — but nothing stops the action from running on
invalid data. Skipping the `IsValid` check lets malformed input flow straight
into business logic and the database.

## Do this
1. At the top of every POST/PUT/PATCH action that takes a bound model, add:
   `if (!ModelState.IsValid) return BadRequest(ModelState);`
   (or `return ValidationProblem();`).
2. Place the check before any side effects — no database writes, no service
   calls, no emails before validation passes.
3. If the project style allows it, consider `[ApiController]`, which performs
   this check automatically — but only as a deliberate team decision, not as a
   way to dodge the explicit check.

## AVOID
- Do not check `IsValid` halfway through the action after writes have already
  happened — validation must gate the side effects, not trail them.
- Do not "validate" by re-checking individual properties manually while
  ignoring `ModelState` — the binding pipeline already ran; read its verdict.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

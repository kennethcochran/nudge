# S3962 — "static readonly" constants should be "const" instead

## Why
A `static readonly` field initialized with a compile-time constant behaves
like a constant but isn't one: it can't be used in `case` labels, attribute
arguments, or default parameter values, and every reader has to check
whether it's ever reassigned. `const` states the intent — this value is
fixed forever — and the compiler enforces it.

## Do this
1. Change `static readonly` to `const` where the initializer is a
   compile-time constant (literals, `nameof`, simple constant expressions).
2. Keep `static readonly` when the value is computed at runtime (`new`,
   method calls) — those can't be `const`, and the rule doesn't ask for
   them.
3. Pause for *public* constants consumed by other assemblies: `const` values
   are baked into callers at compile time, so changing one later requires
   recompiling dependents. If the value might change across versions, keep
   `static readonly` deliberately and document why.

## AVOID
- Do not convert runtime-computed `static readonly` fields (e.g.
  `static readonly Regex R = new(...)`) to `const` — it won't compile, and
  the attempt wastes a cycle.
- Do not make a versioned public value (protocol versions, feature flags)
  `const` purely to satisfy the rule; binary compatibility matters more
  than the warning.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

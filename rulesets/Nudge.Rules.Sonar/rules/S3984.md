# S3984 — Exceptions should not be created without being thrown

## Why
`new InvalidOperationException("...");` as a bare statement constructs an
exception and drops it on the floor — in nearly every case the author forgot
the `throw`. The error condition passes silently and the program continues as
if nothing was wrong, far from where the failure will eventually surface.

## Do this
1. Add the missing `throw`: `throw new InvalidOperationException("...");`
2. If the construction was intentional (building an exception to throw later or
   to return), assign it to a clearly named variable and actually use it —
   never leave it as a bare statement.
3. Re-read the surrounding error handling; a missing `throw` often means the
   intended failure path was never finished.

## AVOID
- Do not assign it to a discard (`_ = new ...`) or an unused local to silence
   the rule — a constructed-never-thrown exception is still dead code hiding a
   missing `throw`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S104 — Files should not have too many lines of code

## Why
A thousand-line file is several responsibilities sharing a filename.
Navigation, code review, and merge conflicts all degrade — and the file's
name stops meaning anything, so new code lands wherever there is room.

## Do this
1. Identify the distinct responsibilities in the file and extract each into
   its own type and file, named for what it contains.
2. Split along responsibility lines, not line counts: each resulting file
   should have one reason to change.

## AVOID
- Do not split the file with `partial` classes (`Foo.Part1.cs`,
  `Foo.Part2.cs`) just to drop the per-file count. The god class survives
  intact; only the line count was laundered.
- Do not rebalance by moving code into `#region` blocks. Regions hide the
  size; they do not reduce the responsibility.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

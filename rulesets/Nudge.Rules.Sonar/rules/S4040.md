# S4040 — Strings should be normalized to uppercase

## Why
ToUpper() / ToLower() with no culture use the current thread culture — the
Turkish-I problem being the famous case ('i'.ToUpper() becomes 'İ'), which
breaks case-insensitive keys, normalization, and comparisons on machines with
different locales. This rule flags culture-sensitive casing used for
normalization.

## Do this
1. Use ToUpperInvariant() for normalization and case-insensitive programmatic comparison — or compare with StringComparison.OrdinalIgnoreCase directly.
2. Reserve the culture-sensitive overloads for text actually shown to users.
3. Grep for other ToUpper()/ToLower() calls in the same area; they travel in packs.

## AVOID
- Do not switch ToUpper() to ToLower() and call it fixed — the culture-sensitivity (the actual bug) is unchanged; only the direction flipped.
- Do not pass CultureInfo.CurrentCulture explicitly to silence the rule; that just writes down the bug you already had.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

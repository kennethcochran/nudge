# S1123 — "Obsolete" attributes should include explanations

## Why
A bare `[Obsolete]` tells the caller "don't use this" but not what to use instead or why — so callers either ignore the warning or guess at the replacement, and the migration the attribute was meant to drive stalls indefinitely.

## Do this
1. Add the message naming the replacement and, briefly, the reason: `[Obsolete("Use NewMethod instead. OldMethod doesn't handle X.")]`.
2. If there is genuinely no replacement, say so explicitly: `[Obsolete("No replacement; this API will be removed in v3.")]`.

## AVOID
- Do not add a filler message like `[Obsolete("Deprecated")]` or `[Obsolete("Don't use")]` — it carries zero information beyond what the attribute already says.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3264 — Events should be invoked

## Why
An event that's declared but never invoked is either dead API surface or a
missing notification: subscribers attach handlers that can never fire, which
reads as a promise the code doesn't keep. This rule flags events with no
raise site.

## Do this
1. If the event represents something real, raise it where the thing happens (EventName?.Invoke(this, args)), following the project's event-raising pattern.
2. If nothing will ever raise it, remove the event — dead public API is worse than no API.
3. For public API you can't remove yet, check who was meant to subscribe before deciding; don't privatize an event external code was meant to use.

## AVOID
- Do not add a bogus raise (in Dispose, in a finalizer, on a timer) just to give the event a call site — subscribers get a meaningless notification and the lie moves downstream.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

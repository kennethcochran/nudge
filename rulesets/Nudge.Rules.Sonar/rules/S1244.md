# S1244 — Floating point numbers should not be tested for equality

## Why
Binary floating-point values (`float`, `double`) cannot
represent most decimal fractions exactly, so `==` on two computed
values is almost never true even when they're mathematically equal —
and occasionally true when they shouldn't be. Equality tests on floats
produce flaky, input-dependent behavior.

## Do this
1. Replace `a == b` with a tolerance comparison: `Math.Abs(a - b) <
   epsilon`, choosing epsilon relative to the operands' magnitude
   (e.g. a small multiple of the expected scale), not a magic constant.
2. If the domain needs exact decimal arithmetic (money, scores,
   quantities), switch the type to `decimal` instead of comparing
   floats.
3. Keep `==` only where exact bit-equality is genuinely intended (e.g.
   comparing against a literal `0.0` sentinel you assigned yourself).

## AVOID
- Do not cast both sides to `double` and compare — the precision
  problem survives the cast.
- Do not pick epsilon from thin air (`1e-9`) without considering the
  operands' scale; a fixed epsilon is wrong for both tiny and huge
  values.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

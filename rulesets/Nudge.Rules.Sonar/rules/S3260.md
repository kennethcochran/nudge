# S3260 — Non-derived "private" classes and records should be "sealed"

## Why
A `private` nested class can never be inherited from outside its containing
type — and if nothing inside inherits it either, leaving it unsealed invites a
subclass that can never arrive, while forfeiting the JIT's devirtualization
wins on its virtual calls.

## Do this
1. Add `sealed` to the class or record declaration.
2. If something in the containing type actually derives from it, the analyzer
   wouldn't have flagged it — double-check that the inheritance is real before
   deciding the rule is wrong.

## AVOID
- Do not widen the accessibility (to `internal` or beyond) just to make the
  rule inapplicable. That changes the type's API surface to dodge a one-word
  fix.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

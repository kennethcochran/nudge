# S2184 — Results of integer division should not be assigned to floating point variables

## Why
`double ratio = count / total;` divides as integers first — `3 / 4` becomes
`0`, and only then converts to `0.0`. The cast happens after the precision is
already gone, so the result is silently wrong, not just imprecise.

## Do this
1. Cast an operand *before* dividing: `double ratio = (double)count / total;`.
2. Prefer casting the first operand so the whole expression promotes to
   floating point.

## AVOID
- Do not "fix" it by casting the result — `(double)(count / total)` still
  performs integer division first; the cast must happen before the `/`.
- Do not multiply by `1.0` after the division (`count / total * 1.0`) — same
  ordering bug, same `0.0`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

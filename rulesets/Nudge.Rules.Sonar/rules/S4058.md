# S4058 — Overloads with a "StringComparison" parameter should be used

## Why
`Equals`, `StartsWith`, `IndexOf`, and friends without an explicit
`StringComparison` use the current culture. That makes `"file".StartsWith
("FILE")` true on some machines and false on others, and it harbors the
Turkish-I bug — where `ToUpper`/`ToLower` round-trips corrupt data — in
exactly the code that looks innocent.

## Do this
1. Pass an explicit comparison: `Ordinal` / `OrdinalIgnoreCase` for
   programmatic strings (identifiers, keys, protocols).
2. Use `CurrentCulture` / `InvariantCulture` only when human-language
   comparison rules genuinely apply, and say so in a comment.

## AVOID
- Do not "fix" the diagnostic with `.ToUpper()` / `.ToLower()` before
  comparing. That allocates on every call and is still culture-dependent —
  the Turkish-I bug lives exactly in that pattern.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6932 — Use model binding instead of reading raw request data

## Why
Reading Request.Form, Request.Query, or the raw body stream by hand
bypasses model binding — you lose validation, type conversion, and the single
declared shape of the input, and every action re-implements parsing slightly
differently. This rule flags direct reads of raw request data in controllers and endpoints.

## Do this
1. Declare what you need as action parameters or a [FromBody] / [FromForm] / [FromQuery] model and let the binder populate it.
2. Put validation on the model (data annotations or FluentValidation) so invalid input is rejected before your code runs.
3. If you need something exotic like a streaming upload, bind the metadata and take the stream as a parameter — don't dig it out of HttpContext manually.

## AVOID
- Do not read Request.Body and call JsonSerializer.Deserialize yourself and call it 'binding' — you've reimplemented the binder without its validation and error handling.
- Do not mix: binding half the inputs and hand-reading the rest in the same action leaves two sources of truth for one request.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3453 — Classes should not have only "private" constructors

## Why
A non-static class whose only constructors are private can never be
instantiated from outside and can never be inherited — so either the `private`
is a mistake, or the class was meant to be static. The rule flags the
contradiction between an instantiable-looking class and no usable constructor.

## Do this
1. If the class holds only static members, mark it `static` — that expresses
   the intent and the compiler enforces it.
2. If instances are meant to exist, add a constructor with the right
   accessibility (`public`, `protected`, or `internal`), or expose a factory
   method/property documenting how instances are obtained.
3. If the class is a singleton, say so explicitly: keep the private constructor
   but add the static `Instance` accessor so the pattern is deliberate, not
   accidental.

## AVOID
- Do not silence it by adding a `public` constructor that throws
   `NotImplementedException` — a constructor that can never succeed is worse
   than a private one.
- Do not make the class `abstract` just to dodge the rule when it was meant to
   be instantiated; that trades one contradiction for another.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

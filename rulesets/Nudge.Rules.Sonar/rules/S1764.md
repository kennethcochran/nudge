# S1764 — Identical expressions should not be used on both sides of operators

## Why
x == x, a - a, name.Equals(name) — identical operands on both sides of an
operator are either always-true/always-zero (dead logic) or a typo where the
second operand should be something else. Either way the expression doesn't do
what a reader thinks. This rule flags them.

## Do this
1. Determine the intended second operand — usually a sibling variable or property — and use it.
2. If the expression is genuinely intentional (e.g. the NaN self-check x != x), rewrite it to say what it means (double.IsNaN(x)) instead of relying on the idiom.
3. Add a test pinning the intended behavior so the typo can't creep back.

## AVOID
- Do not make the sides textually different without changing semantics — e.g. x == +x or x == (x) — the detector goes quiet and the dead logic stays.
- Do not delete the whole check if it was guarding something; find the operand it was meant to compare against.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

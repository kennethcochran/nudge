# S1144 — Unused private types or members should be removed

## Why
Dead private code — unused fields, methods, types —
still gets read, still gets maintained (or worse, "maintained" by
someone afraid to touch it), and still misleads readers about what the
class does. If nothing calls it, it isn't part of the design.

## Do this
1. Verify the member is truly unreachable: no callers, no reflection
   (`nameof`/string lookups), no serialization hooks, no partial-class
   counterparts.
2. Delete it. Version control keeps the history if you ever need it
   back.
3. If it's meant to be public API surface, make that intent explicit by
   widening visibility deliberately — not as a trick to silence the
   rule, but as a real API decision.

## AVOID
- Do not "use" the member by referencing it from another piece of
  dead code or from a test that never runs — the code is still dead,
  just harder to spot.
- Do not widen visibility to `public`/`internal` solely to dodge the
  rule on code nobody calls.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

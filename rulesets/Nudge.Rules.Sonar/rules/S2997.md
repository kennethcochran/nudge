# S2997 — "IDisposables" created in a "using" statement should not be returned

## Why
Returning an `IDisposable` created inside a `using`
statement hands the caller a disposed object: the `using` disposes it
when the method returns, so the first thing the caller does with the
resource throws `ObjectDisposedException`. The ownership contract is
broken at the return statement.

## Do this
1. Decide who owns the resource's lifetime. If the caller should own
   it, create it without `using` and document the transfer explicitly
   (XML docs stating the caller must dispose it, a descriptive method
   name, or a factory type).
2. If the method should own it, don't return the resource — materialize
   the result inside the `using` block and return the data, not the
   disposable.
3. Never return a half-disposed object "temporarily" while you decide;
   pick an ownership model now.

## AVOID
- Do not rewrite `using var x = ...; return x;` as `var x = ...;
  return x;` without documenting that ownership transfers — the caller
  must know it now owns disposal, or the leak just moved.
- Do not "fix" it by returning a copy/string of the resource when the
  caller needs the live resource — that changes the API's meaning;
  transfer ownership explicitly instead.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

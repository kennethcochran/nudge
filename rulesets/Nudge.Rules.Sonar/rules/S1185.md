# S1185 — Overriding members should do more than simply call the same member in the base class

## Why
`public override void Save() => base.Save();` adds a stack frame and a
maintenance surface in exchange for zero behavior — it suggests customization
that doesn't exist, and future readers will waste time looking for it.

## Do this
1. If no customization is needed, delete the override entirely — the base
   implementation is inherited automatically.
2. If customization was intended but never written, add the actual behavior
   now instead of leaving the hollow override.

## AVOID
- Do not keep the override and add a no-op line (a comment, a logging call
  that logs nothing meaningful) to make it "do more". The rule is about
  behavior, not line count — an override that still just delegates adds
  nothing.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

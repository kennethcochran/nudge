# S2629 — Logging templates should be constant

## Why
`logger.LogInformation($"User {id} logged in")` renders the message eagerly and
hands the sink one opaque string — you lose the structured `{UserId}` property
that log queries, dashboards, and alerts filter on, and you pay the formatting
cost even when the log level is disabled.

## Do this
1. Replace interpolation with a message template:
   `logger.LogInformation("User {UserId} logged in", id)`.
2. Keep the template string a compile-time constant; pass values as arguments.
3. Use semantic placeholder names (`{UserId}`, not `{0}`) so sinks can index
   them.

## AVOID
- Do not "fix" it by assigning the interpolated string to a local first and
  passing that — it's still interpolation; the template must contain the
  placeholders and the values must be arguments.
- Do not guard the interpolated call with `if (logger.IsEnabled(...))` and
  call it done — you've kept the unstructured string; use the template form.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

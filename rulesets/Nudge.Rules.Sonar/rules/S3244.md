# S3244 — Anonymous delegates should not be used to unsubscribe from Events

## Why
`button.Click -= (s, e) => HandleClick(s, e);` creates a *new* delegate
instance that never equals the one you subscribed — the unsubscribe silently
does nothing, the handler stays attached, and you get leaks or duplicate
handling. Delegate equality is by target plus method; a fresh lambda is never
equal to the subscribed one.

## Do this
1. Store the subscribed delegate in a field (or a local, if subscribe and
   unsubscribe are in the same scope): `private EventHandler _handler;`
2. Subscribe with the stored instance: `button.Click += _handler;`
3. Unsubscribe with the *same* stored instance: `button.Click -= _handler;`
4. If you subscribed with a method group (`button.Click += HandleClick;`),
   unsubscribe with the identical method group — method groups on the same
   target compare equal.

## AVOID
- Do not "fix" it by unsubscribing with a *different* named method than the one
   subscribed — equality is by target and method, so a different method is the
   same silent no-op as the lambda.
- Do not wrap the lambda in a local function and unsubscribe with that; it's
   still a different instance unless it's the exact delegate you stored at
   subscribe time.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S9022 — Redundant "Include" calls should be removed

## Why
Chained duplicate `.Include(x => x.Orders)` on the same navigation adds
nothing to the generated query — Entity Framework already loads it once. The
duplicate is almost always a copy-paste or merge artifact, and it obscures
which includes the query actually depends on.

## Do this
1. Delete the duplicate `Include` call.
2. Sanity-check the remaining query still loads what the consuming code
   touches, especially if lazy loading is enabled (a removed include plus
   lazy proxies can turn into an N+1).

## AVOID
- Do not "dedupe" by splitting the query into two queries with the include
  on a different branch. The redundancy is textual, not behavioral — just
  delete the extra call.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3450 — Parameters with "[DefaultParameterValue]" attributes should also be marked "[Optional]"

## Why
In COM interop signatures, `[DefaultParameterValue(x)]` without `[Optional]`
is an inconsistent pair — COM consumers see a default value on a parameter the
metadata says is required, and some interop layers misbehave when the two
disagree. The attributes are meant to travel together.

## Do this
1. Add `[Optional]` alongside the existing `[DefaultParameterValue(...)]`.
2. Keep both attributes' values consistent with each other and with the
   documented COM contract.
3. Check sibling parameters in the same signature for the same missing
   attribute.

## AVOID
- Do not "fix" it by deleting `[DefaultParameterValue]` when COM callers rely
   on the default — add the missing `[Optional]` instead.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

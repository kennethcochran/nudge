# S4487 — Unread "private" fields should be removed

## Why
A private field that's never read is dead weight — it suggests unfinished work,
a removed feature whose cleanup was forgotten, or state nothing depends on. It
misleads readers into thinking it matters, and it can keep its object graph
alive pointlessly.

## Do this
1. Check whether the field was *supposed* to be read somewhere — a missing
   read is sometimes the real bug (a computed result that's silently ignored).
2. If it's genuinely dead, delete the field and its assignments.
3. If it exists for a side effect (rare), make that explicit — but deletion is
   right in nearly every case.

## AVOID
- Do not add a meaningless read of the field (a dummy log line, a no-op use)
   just to make it "read" — the field is still dead; delete it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

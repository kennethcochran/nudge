# S9118 — Default values should be compatible with their entity property type

## Why
`HasDefaultValue("0")` on an `int` property (or any default literal that isn't
representable as the property's CLR type) compiles fine but fails — or silently
misbehaves — when the migration runs or the database applies the default. The
default must be a value of the property's own type.

## Do this
1. Read the diagnostic to find the expected property type.
2. Change the default literal to a value of that CLR type (`0` for `int`,
   `false` for `bool`, not their string spellings).
3. Regenerate the migration snapshot and verify the default renders correctly
   in the migration code.

## AVOID
- Do not change the property's type to `string` to match a bad default — the
  default was wrong, not the model.
- Do not switch to `HasDefaultValueSql` with a raw SQL literal to dodge the
  type check — you've moved the mismatch somewhere the compiler can't see it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

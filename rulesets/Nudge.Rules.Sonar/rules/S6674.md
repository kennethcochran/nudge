# S6674 — Log message template should be syntactically correct

## Why
Structured logging templates (`"Processing order {OrderId}"`) are parsed at runtime: a malformed template — unbalanced braces, an empty `{}`, a stray `{` — either throws or silently drops the property. Either way the log event loses the data you thought you captured, exactly when you're investigating.

## Do this
1. Fix the template syntax: balanced braces, named placeholders, no empty `{}`.
2. Make sure each placeholder has a matching argument, in order.
3. Exercise the logging path (or unit-test the template) to confirm the properties render.

## AVOID
- Do not "fix" it by switching to string interpolation (`$"..."`) just to silence the template check — you lose structured properties (they become baked-in text) and pay the formatting cost on every call even when the log level is off.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

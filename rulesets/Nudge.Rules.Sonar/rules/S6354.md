# S6354 — Use a testable date/time provider

## Why
`DateTime.UtcNow` sprinkled through logic is untestable — you can't freeze
time, so expiry, rounding, and scheduling behavior can only be tested by
sleeping or by hoping. An injected `TimeProvider` makes time a controllable
input like any other dependency.

## Do this
1. Inject `TimeProvider` (or your `IClock` abstraction) via the constructor
   and call `timeProvider.GetUtcNow()` instead of `DateTime.UtcNow`.
2. In tests, substitute `FakeTimeProvider`
   (`Microsoft.Extensions.Time.Testing`) or a stub to set exact instants.
3. Migrate call sites one at a time; new code takes the provider from day one.

## AVOID
- Do not "fix" it with a `static class Clock { public static DateTime UtcNow
  => DateTime.UtcNow; }` — a static wrapper is just as untestable; the
  provider must be injectable per instance.
- Do not make the provider an optional constructor parameter defaulting to
  `TimeProvider.System` and then never pass it in tests — that's the seam
  existing only on paper; pass the fake in the tests.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

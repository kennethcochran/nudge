# S3876 — Strings or integral types should be used for indexers

## Why
Indexers conventionally take `int`/`long` (like arrays) or `string` (like
dictionaries). An indexer keyed on an exotic type confuses every consumer —
`obj[weirdKey]` reads like array access but behaves like a bespoke lookup,
and discoverability through IntelliSense suffers.

## Do this
1. If the key is naturally integral or textual, change the indexer parameter
   to that type.
2. Otherwise, convert the indexer into a regular method (`GetByXxx(...)`)
   whose name explains the lookup.
3. Update the call sites to the new form.

## AVOID
- Do not "fix" it by adding a second string-keyed indexer overload alongside
   the exotic one — two indexers differing only by key type is more confusing
   than one odd one. If the key isn't int/string-like, use the method form.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

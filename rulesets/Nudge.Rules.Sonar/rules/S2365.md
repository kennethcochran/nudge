# S2365 — Properties should not make collection or array copies

## Why
A property getter that returns _items.ToList() (or a fresh array copy)
looks like it exposes the collection but hands out a disposable snapshot:
callers who Add to it or read Count are working on a copy while the real
collection never changes. It is also a per-access allocation. This rule flags
getters that copy.

## Do this
1. Decide the contract. If callers should see live data, return IReadOnlyList<T> / IReadOnlyCollection<T> (or expose the field via AsReadOnly()). If they should get a snapshot, that is a method, not a property — rename to GetItemsSnapshot() or similar so the copy is explicit.
2. Never return a mutable copy from a property and let callers believe they are editing the original.
3. Fix every caller that was relying on the copy semantics before changing the return.

## AVOID
- Do not cache the copy in a field and return that — it is still a copy, now also stale.
- Do not rename the property to GetItems() while keeping call sites written as if it were the live collection; the rename alone fixes nothing unless the copy semantics are made explicit at each call site.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2934 — Property assignments should not be made for "readonly" fields not constrained to reference types

## Why
A `readonly` field holding a value type (a struct) cannot be mutated in place:
`myReadonlyStruct.Prop = x` compiles but silently mutates a *copy* and
discards it. The assignment looks like it works, does nothing, and the bug is
invisible without the analyzer.

## Do this
1. Decide the intent: is the struct meant to be mutated after construction, or
   is it immutable?
2. If mutation is intended, drop `readonly` from the field (or expose a
   property with a private setter instead of a field).
3. If the struct should stay immutable, construct a new value and assign the
   whole field (in the constructor) instead of mutating members.
4. Add a test asserting the mutation actually takes effect.

## AVOID
- Do not "fix" it by assigning to a local copy and discarding that — that is
   exactly what the buggy code already does. Decide mutable-field versus
   immutable-struct, then write code that matches the decision.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3005 — "ThreadStatic" should not be used on non-static fields

## Why
`[ThreadStatic]` on an instance field is silently ignored by the runtime —
each instance gets its own copy regardless of thread, so the per-thread
semantics you declared do not exist. It compiles, does nothing, and the
attribute lies in the declaration about how the field behaves.

## Do this
1. If per-thread storage is really what you want, make the field `static`
   (which is what `[ThreadStatic]` requires to function).
2. Prefer `ThreadLocal<T>` — or `AsyncLocal<T>` if the value must flow across
   `await` boundaries, which `[ThreadStatic]` does not.
3. If the attribute was accidental, just remove it.

## AVOID
- Do not keep the attribute on the instance field "as documentation." A
  lying attribute is worse than no attribute: every future reader will
  reason from behavior the field does not have.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S4070 — Non-flags enums should not be marked with "FlagsAttribute"

## Why
`[Flags]` promises combinable values. An enum with sequential values (`Red = 0, Green = 1, Blue = 2`) marked `[Flags]` produces nonsense combinations — `Red | Green` equals `Blue` — that `ToString` and `HasFlag` then misreport. The attribute is a lie about the enum's semantics.

## Do this
1. If the values are meant to combine, assign powers of two (1, 2, 4, 8, …) with `None = 0`, and keep `[Flags]`.
2. If they're exclusive choices, remove `[Flags]`.

## AVOID
- Do not keep `[Flags]` and "fix" the values as sequential numbers starting at 0 — zero must be `None` and the rest powers of two, or the attribute is still a lie.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

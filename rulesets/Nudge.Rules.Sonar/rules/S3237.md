# S3237 — "value" contextual keyword should be used

## Why
In `set`, `init`, `add`, and `remove` accessors, the incoming value is
already available as the contextual keyword `value`. Declaring your own
local named `value` inside the accessor shadows it — every read of `value`
then hits your local instead of the incoming value, so the assignment (or
event subscription) silently operates on the wrong data. This rule flags
the shadowing declaration.

## Do this
1. Delete the shadowing local and use the contextual keyword `value`
   directly in the accessor body.
2. Check what the accessor was doing with the shadow: if it never read the
   incoming value at all, that's the real bug — wire `value` through to
   the backing field or event.

## AVOID
- Do not "fix" it by renaming the local (`var v = 5; _field = v;`) and
  keeping the logic. The rule goes quiet, but the accessor still ignores
  the incoming value — you've hidden the bug instead of fixing it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

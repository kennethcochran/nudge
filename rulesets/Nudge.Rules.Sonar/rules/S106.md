# S106 — Standard outputs should not be used directly to log anything

## Why
`Console.WriteLine` logging can't be leveled, filtered, routed, or turned off;
it interleaves with real stdout consumers, pollutes pipelines, and disappears
in services with no console attached. Production code needs a logging
abstraction so output goes where operations expects it.

## Do this
1. Replace direct `Console` writes with an `ILogger<T>` (or the project's
   logging abstraction), choosing the right level (Information, Warning,
   Error).
2. Take the logger via constructor injection (or the established pattern in
   this codebase) rather than instantiating one inline.
3. Keep the message text; drop formatting hacks that existed only because the
   console was the sink (manual timestamps, separators) — the logger adds
   those.

## AVOID
- Do not write a thin wrapper class around `Console.WriteLine` and call the
   rule satisfied — the output still bypasses every logging pipeline; use the
   real logging abstraction.
- Do not reroute to `System.Diagnostics.Trace` or `Debug` instead; those are
   the same problem in a different namespace.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2201 — Methods without side effects should not have their return values ignored

## Why
Methods like `string.Replace`, `Enumerable.Where`, or `DateTime.AddDays` don't
mutate — they return a new value. Discarding it means the call did nothing;
the code reads as if it worked while the original value flows on unchanged.

## Do this
1. Assign the result: `s = s.Replace(oldValue, newValue);`,
   `items = items.Where(predicate).ToList();`.
2. If the call truly was pointless, delete it — don't leave a no-op that
   misleads the next reader into thinking something happened.

## AVOID
- Do not "fix" it with a discard — `_ = s.Replace(oldValue, newValue);` —
  the value is still thrown away; the bug remains, now with a bow on it.
- Do not wrap the call in a helper that ignores the return "for readability" —
  same no-op, one indirection away.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

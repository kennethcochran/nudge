# S4220 — Events should have proper arguments

## Why
`public event Action<string> SomethingHappened;` bypasses the .NET event
pattern — subscribers get a bare value with no sender, no extensibility, and
tooling (designers, convention-based frameworks) doesn't recognize it as an
event. The pattern exists so handlers know *who* raised the event and the args
can grow without breaking signatures.

## Do this
1. Define an `EventArgs`-derived class carrying the data:
   `class SomethingHappenedEventArgs : EventArgs` with the payload as
   properties.
2. Declare the event with the generic handler:
   `public event EventHandler<SomethingHappenedEventArgs>? SomethingHappened;`
3. Raise it with `(this, args)` so subscribers receive the sender.

## AVOID
- Do not "fix" it by changing `Action<string>` to `Action<object, string>` —
   a positional sender-plus-payload mimics the shape without the contract; use
   `EventHandler<TEventArgs>`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

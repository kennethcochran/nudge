# S4158 — Empty collections should not be accessed or iterated

## Why
Indexing or iterating a collection that's provably empty at that point
(`new List<int>()[0]`, a `foreach` over a just-created empty list) is either an
`ArgumentOutOfRangeException` waiting to happen or dead code — the author meant
to populate it first, or meant a different collection.

## Do this
1. If the collection should have elements, populate it before the access — or
   fix the code that was supposed to fill it.
2. If it's genuinely empty by design, delete the access or iteration — it's
   dead code.
3. If emptiness is only *possible* (not provable), guard it: check
   `Count`/`Any()` before indexing.

## AVOID
- Do not add a dummy element (`list.Add(default)`) just so the index access
   doesn't throw — an empty collection with a fake element is worse than an
   exception; fix the population logic or delete the access.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

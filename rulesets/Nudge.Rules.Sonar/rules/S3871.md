# S3871 — Exception types should be "public"

## Why
Exceptions cross assembly boundaries by design — a library throws, the caller
catches. A non-public exception type can't be named in a `catch` block outside
its assembly, so callers can only catch `Exception` and lose the ability to
handle that specific failure; serialization and some frameworks also require
public exception types.

## Do this
1. Change the exception type's accessibility to `public`.
2. Keep the standard exception constructor set (message, message plus inner
   exception, serialization constructor) so the type behaves like a proper
   exception.
3. If the exception was internal because it carries sensitive details, keep the
   details out of the message text — don't keep the type hidden.

## AVOID
- Do not "fix" it by catching the internal exception inside the same assembly
   and rethrowing a public one — that adds a translation layer to avoid a
   one-word accessibility change.
- Do not nest the exception as `public` inside an `internal` class; it is still
   unreachable to outside callers.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

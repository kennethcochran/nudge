# S2328 — "GetHashCode" should not reference mutable fields

## Why
Hash codes are computed when an object enters a hash-based collection. If a
mutable field changes afterwards, `Dictionary` / `HashSet` lookups hash to the
wrong bucket and the entry becomes unfindable — `ContainsKey` returns false
for a key that is sitting right there in the collection.

## Do this
1. Compute `GetHashCode` only from immutable (`readonly`) fields or
   get-only properties.
2. If the type is used as a key and its fields must change, make the type
   immutable instead (init-only properties, `record`).
3. Keep `GetHashCode` consistent with `Equals` — equal objects must hash
   equal.

## AVOID
- Do not "fix" it by caching the hash at construction — the object still
  mutates after insertion and lookups still miss; the *fields* must be
  immutable, not the hash.
- Do not base the hash on `RuntimeHelpers.GetHashCode(this)` while `Equals`
  compares fields — equal objects would then hash differently, breaking the
  contract from the other side.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

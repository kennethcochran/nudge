# S4136 — Method overloads should be grouped together

## Why
Overloads scattered across a class force readers to hunt to learn the full
calling surface — and the XML doc comments on distant overloads drift out of
sync with each other. Adjacent overloads read as one API.

## Do this
1. Move the overloads so they're adjacent, ordered from most to least
   parameters (or following the existing convention in the file).
2. While you're there, check the doc comments agree with each other.

## AVOID
- This rule is mechanical — there is no meaningful dodge. Don't "group" them
  by extracting the overloads into a partial-class file: that's scattering
  with a filing system, and readers still can't see the full surface in one
  place.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2445 — Blocks should be synchronized on read-only fields

## Why
The flagged `lock` targets `this`, a `Type`, a string literal, or a mutable field — all lock objects that outside code can also lock on (or, for strings, that are process-wide interned). That enables deadlocks against you, and a mutable lock field can be reassigned mid-flight, silently breaking mutual exclusion. Only a `private readonly` field is unobservable and unchangeable.

## Do this
1. Add a dedicated lock object: `private readonly object _syncLock = new();` (name it for what it guards).
2. Replace every `lock(this)`, `lock(typeof(X))`, `lock(someString)`, and `lock(mutableField)` with `lock(_syncLock)`.
3. If different members guard different state, use one lock object per independent state — don't funnel everything through a single global lock without thinking.

## AVOID
- Do not lock on a `private object` field that isn't `readonly` — reassignment swaps the lock identity and mutual exclusion breaks silently.
- Do not lock on a string, even a private one — interned strings are shared process-wide.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2368 — Public methods should not have multidimensional array parameters

## Why
Multidimensional arrays (`int[,]`) are a .NET-specific shape: they're not
CLS-compliant, they interop poorly, and every consumer must use the same
awkward indexing. In a public signature you're exporting that awkwardness
to all callers — and public API shape is hard to take back, which is why
this is a BLOCKER.

## Do this
1. Change the parameter to a jagged array (`int[][]`) — CLS-compliant,
   familiar indexing, same data.
2. If the rectangular guarantee matters, encapsulate it in a small type
   (e.g. a `Matrix<T>`) that validates dimensions once instead of trusting
   every caller.
3. Update all call sites in the same change; for shipped public API, add the
   new overload and `[Obsolete]` the old one rather than breaking callers
   silently.

## AVOID
- Do not keep the `int[,]` parameter and add a jagged-array overload that
  converts internally while leaving the old one public — the non-compliant
  surface is still public.
- Do not dodge by making the method `internal` while it's still consumed as
  public API through `InternalsVisibleTo`; fix the shape.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

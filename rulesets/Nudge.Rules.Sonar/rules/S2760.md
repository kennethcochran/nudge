# S2760 — Sequential tests should not check the same condition

## Why
Two test methods that assert the same condition are
either testing the same thing twice (one of them is redundant) or were
meant to test different scenarios and don't (one of them is wrong).
Either way, the suite is lying about its coverage.

## Do this
1. Compare the two tests' setups: if the scenarios are truly
   identical, merge the tests into one.
2. If the setups differ, the assertions should assert what's actually
   different about each scenario — fix the assertion that doesn't match
   its setup.
3. Run both tests after the change and confirm each one fails for the
   reason its name claims.

## AVOID
- Do not "fix" it by deleting the duplicate assertion when the two
  tests were meant to cover different scenarios — a deleted assertion
  that should have been corrected leaves the scenario untested.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S4586 — Non-async "Task/Task<T>" methods should not return null

## Why
Callers `await` the returned task unconditionally. A null `Task` detonates
as a `NullReferenceException` at the await point — far from the method that
broke the contract — and the type system cannot catch the lie because
`Task<T>` is a reference type.

## Do this
1. Return `Task.CompletedTask` (or `Task.FromResult(value)` for `Task<T>`).
2. If the method genuinely has asynchronous work to do, consider making it
   `async` — but only if there is something to await.

## AVOID
- Do not return `null!` with the null-forgiving operator. It silences the
  analyzer while keeping the `NullReferenceException` — the exact
  metric-gaming this guidance exists to prevent.
- Do not mark the method `async` when there is nothing to await just to
  avoid writing the return. That adds a state machine for zero benefit.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3343 — Caller information parameters should come at the end of the parameter list

## Why
Caller-info parameters (`[CallerMemberName]`, `[CallerFilePath]`,
`[CallerLineNumber]`) only receive compiler-filled values when the caller can
omit them. A required parameter declared after them means callers can no
longer omit the caller-info arguments positionally — they're forced to pass
caller-info explicitly (defeating the feature) or contort every call into
named arguments, and the values rot on every rename.

## Do this
1. Move all caller-info parameters after every other parameter in the list.
2. Leave them with their default values so callers can omit them.
3. Remove any explicit caller-info arguments at call sites that only existed
   because of the old ordering.

## AVOID
- Do not give the parameter after them a default value too and call it done —
  the contract is positional: callers must be able to omit the caller-info
  arguments, and anything required after them breaks that.
- Do not "fix" it by hardcoding `nameof(...)` at the call sites — that is the
  manual passing the attribute was designed to eliminate.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S4226 — Extensions should be in separate namespaces

## Why
Extension methods declared in a broad namespace — or the same namespace as the extended types — get imported implicitly everywhere that namespace is used: IntelliSense pollution on every type, plus ambiguous-call surprises when two such extensions collide. A dedicated namespace makes the extension opt-in per file.

## Do this
1. Move the extension class into its own namespace (e.g. `MyApp.Extensions`).
2. Add the `using` only in the files that actually need the extensions.

## AVOID
- Do not "fix" it by moving the class to a new namespace but adding a `global using` for it — that's the same implicit import with extra steps.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

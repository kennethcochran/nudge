# S3971 — "GC.SuppressFinalize" should not be called

## Why
`GC.SuppressFinalize` only does something when the object has a finalizer to
suppress. Calling it on a type without one is dead code that implies a
finalizer exists — and in the Dispose pattern the call belongs inside
`Dispose()`, paired with a real finalizer, nowhere else.

## Do this
1. If the type has no finalizer, delete the call — there is nothing to
   suppress.
2. If you are implementing the full Dispose pattern (with a finalizer guarding
   unmanaged resources), keep the call inside `Dispose()` where it belongs and
   make sure the finalizer actually exists.

## AVOID
- Do not add an empty finalizer (`~MyClass() { }`) just to give the
  `SuppressFinalize` call something to suppress. Finalizers impose a real GC
  cost — every instance survives an extra collection generation — so an empty
  one is pure overhead purchased to justify a pointless call.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

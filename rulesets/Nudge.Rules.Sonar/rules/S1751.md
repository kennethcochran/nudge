# S1751 — Loops with at most one iteration should be refactored

## Why
A `for`, `while`, or `foreach` that can execute at most once is not a loop —
it is an `if` in disguise, usually the result of a misplaced `break` or a
condition that makes a second iteration impossible. Readers waste time
hunting for the iteration that never happens, and the real logic hides behind
loop ceremony.

## Do this
1. Decide which was intended: a single conditional execution, or genuine
   repetition.
2. If single execution was intended, replace the loop with `if` and move any
   loop-invariant setup out.
3. If repetition was intended, fix the condition or the stray `break`/`return`
   that strangles it — and add a test that exercises multiple iterations.

## AVOID
- Do not "fix" the diagnostic by deleting the `break` so the loop now
  iterates. If one pass was the actual intent, you have changed behavior
  under the guise of cleanup — decide first, then refactor.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S4260 — "ConstructorArgument" parameters should exist in constructors

## Why
In MEF, `[ImportingConstructor]` with
`[ConstructorArgument("name")]` names a constructor parameter that must
exist. A mismatch — the attribute names a parameter the constructor
doesn't have — means the import never binds: composition fails at
runtime (or silently leaves the import unsatisfied), far from the typo.

## Do this
1. Compare the `ConstructorArgument` name against the constructor's
   actual parameter names and fix the spelling/casing mismatch.
2. If the constructor genuinely needs the value, add the parameter and
   use it; if the attribute is stale, remove or correct the attribute.
3. Rebuild and, if possible, exercise composition in a test so the
   binding is verified, not assumed.

## AVOID
- Do not add a constructor parameter with the matching name that the
  constructor ignores — a dead parameter that exists only to satisfy the
  attribute is a lie in the API; either the value is needed (use it) or
  the attribute is wrong (fix it).

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

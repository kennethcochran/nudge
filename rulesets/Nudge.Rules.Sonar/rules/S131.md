# S131 — "switch/Select" statements should contain a "default/Case Else" clauses

## Why
A `switch` with no `default` clause silently does
nothing for unexpected values. When a new enum member or discriminator
value is added later, the switch keeps compiling and keeps ignoring it
— the bug hides until runtime. An explicit `default` forces the
decision about unexpected values to be made once, visibly.

## Do this
1. Add a `default` clause to the flagged switch.
2. Decide what unmatched values mean: if they indicate a bug or an
   unhandled new case, `throw` (e.g. `InvalidOperationException` /
   `ArgumentOutOfRangeException` naming the value); if "do nothing" is
   genuinely correct, say so in a comment.
3. For switches over enums, consider whether the `default` should stay
   forever or whether the switch should become exhaustive as cases are
   added.

## AVOID
- Do not add an empty `default: break;` blindly when an unexpected
  value signals a bug — a silent default turns a future missing case
  into a silent no-op instead of a loud failure.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S6962 — You should pool HTTP connections with HttpClientFactory

## Why
`new HttpClient()` per request creates a new connection pool per instance, and
disposing it doesn't immediately release sockets — under load you exhaust
ephemeral ports (socket exhaustion) and requests start failing.
`IHttpClientFactory` pools handlers, reuses connections, and rotates DNS
entries.

## Do this
1. Register the factory once at startup: `services.AddHttpClient();` (or
   `AddHttpClient<TClient>()` for typed clients).
2. Inject `IHttpClientFactory` (or the typed client) where the
   `new HttpClient()` was, and create clients via `factory.CreateClient()`.
3. Delete the manual `new HttpClient()` / `using var client = new HttpClient()`
   code — the factory owns handler lifetime now.

## AVOID
- Do not replace per-request `new HttpClient()` with one `static readonly
   HttpClient` — that dodges socket exhaustion but pins DNS forever and skips
   the factory's handler rotation; use `IHttpClientFactory`.
- Do not write your own mini-factory class that news up `HttpClient`
   internally; that's the same bug with an extra layer.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1450 — Private fields only used as local variables in methods should become local variables

## Why
A private field touched by only one method is shared mutable state in
disguise: it suggests persistence across calls that doesn't exist, invites
threading bugs (two calls stomping each other's "local"), and forces readers
to check every method for writers that aren't there.

## Do this
1. Move the declaration into the method as a local variable.
2. Delete the field.
3. If two methods genuinely share it, that's real shared state — keep the
   field and document the sharing instead of pretending it away.

## AVOID
- Do not make the field `static` "since only one method uses it" —
  shared-across-instances is worse than shared-across-calls, not better.
- Do not keep the field and add a comment saying it's "effectively local" —
  the type system already has a construct for effectively-local, and it's
  called a local variable.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

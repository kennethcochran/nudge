# S1226 — Method parameters, caught exceptions and foreach variables' initial values should not be ignored

## Why
Reassigning a parameter before ever reading it — or catching an exception and
never touching it — silently discards the caller's value or the error
details. The usual story is a lost input, a swallowed error, or a
half-finished refactor; none of them are what the code appears to do.

## Do this
1. If the initial value matters, restructure so the parameter flows into the
   logic *before* any assignment — read it, then decide.
2. If the parameter is genuinely unused, remove it (and fix the call sites).
3. If a caught exception is genuinely uninteresting, use `catch {` with no
   variable — but prefer logging or handling it; silent catches are how
   incidents become mysteries.

## AVOID
- Do not assign the parameter to itself or to a discard (`_ = param;`) to
  "use" it — the analyzer is satisfied and the caller's value still goes
  nowhere.
- Do not "handle" a swallowed exception by logging a constant string without
  the exception — you've kept the catch and discarded the diagnosis.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S4004 — Collection properties should be readonly

## Why
A settable collection property (`public List<T> Items { get; set; }`) lets any
caller replace the entire collection, silently breaking invariants the class
maintains — event subscriptions, lazy initialization, validation on add. The
class should own its collection; callers should mutate its *contents*, not
swap the instance.

## Do this
1. Remove the setter (or make the property get-only):
   `public List<T> Items { get; } = new();`
2. Change callers that replaced the collection to mutate it instead
   (`Clear()` + `Add`/`AddRange`).
3. If even content mutation should be restricted, expose `IReadOnlyList<T>`
   while keeping a private mutable list internally.

## AVOID
- Do not keep the public setter and "fix" it with a comment saying "don't
   replace this" — the API still allows it and the next caller won't read the
   comment. Remove the setter.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

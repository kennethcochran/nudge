# S2486 — Generic exceptions should not be ignored

## Why
An empty `catch (Exception)` swallows everything — including `OutOfMemory`,
`NullReferenceException`, and your own bugs — and execution marches on in a
corrupted state. The failure becomes silent and undebuggable, and the catch
block reads as deliberate handling when it handles nothing.

## Do this
1. Catch the specific exception type you can actually handle, not `Exception`.
2. Do something real in the handler: log with context, retry with backoff,
   compensate, or rethrow.
3. If swallowing is genuinely correct (rare — e.g. best-effort cleanup),
   say why in a comment and log at debug level at minimum.

## AVOID
- Do not replace the empty block with `catch (Exception ex) { _ = ex; }` or
  a comment-only body. Naming the variable or narrating the swallow does not
  make it handling — the exception is still silently discarded.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

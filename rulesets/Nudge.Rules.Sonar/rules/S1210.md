# S1210 — "Equals" and the comparison operators should be overridden when implementing "IComparable"

## Why
`IComparable<T>` defines ordering; `Equals` and `==` define equality.
Implementing one without the other lets `list.Sort()` and
`list.Contains(x)` disagree about whether two items are "the same" —
sorted collections and dictionaries behave inconsistently, and the bug only
shows up with specific data.

## Do this
1. Implement the full set consistently with `CompareTo`: override
   `Equals(object)`, implement `IEquatable<T>`, override `GetHashCode()`, and
   overload `==`, `!=`, `<`, `>`, `<=`, `>=`.
2. Make them all agree: `CompareTo` returning 0 if and only if `Equals`
   returns true.

## AVOID
- Do not "fix" it by implementing `IComparable<T>` explicitly to hide it —
  the inconsistency remains for anyone who finds it.
- Do not overload the operators to delegate to `CompareTo` while leaving
  `Equals` as reference equality — pick one semantics and implement it
  everywhere.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

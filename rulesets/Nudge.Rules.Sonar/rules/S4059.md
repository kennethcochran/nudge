# S4059 — Property names should not match get methods

## Why
A type with both a `Name` property and a `GetName()` method is ambiguous —
which is canonical? Do they differ? Callers guess, and the two can drift apart
(one gets the new logic, the other doesn't), leaving behavior that depends on
which spelling the caller happened to pick.

## Do this
1. Decide which is canonical — usually the property — and delete the other.
2. If the method does something genuinely different (takes parameters, has side
   effects, is expensive), rename it to say what it does differently
   (`GetDisplayName()`, `ResolveName()`).
3. Update all call sites to the surviving member.

## AVOID
- Do not keep both and add XML docs claiming they're "equivalent" — two
   equivalent members is still one too many; delete one.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

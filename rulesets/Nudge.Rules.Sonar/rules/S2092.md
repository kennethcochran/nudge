# S2092 — Cookies should have the "secure" flag

## Why
Without `Secure`, the browser sends the cookie over plain HTTP as well as
HTTPS — one cleartext request, or one SSL-stripping attacker on the network
path, exposes the session. The flag restricts the cookie to encrypted
transport only.

## Do this
1. Set `Secure = true` on `CookieOptions` for every sensitive cookie.
2. Enforce HTTPS app-wide (`UseHttpsRedirection` plus HSTS) so the flag is
   never moot because the app itself serves HTTP.
3. Confirm the `Secure` attribute appears on the `Set-Cookie` header in dev
   tools.

## AVOID
- Do not set `Secure` only in production configuration while dev/test cookies
  stay cleartext — flags diverge, and the "temporary" cleartext cookie is the
  one that ends up in a shared test environment.
- Do not confuse `Secure` (transport) with `HttpOnly` (script access) — they
  solve different thefts, and you need both.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3262 — "params" should be used on overrides

## Why
If the base declares `params int[] args` and the override drops `params`,
callers through a base-typed reference can still use the comma syntax while
callers through the derived type can't — the override silently narrows the
calling convention depending on the static type at the call site.

## Do this
1. Add `params` to the override's parameter:
   `public override void M(params int[] args)`.
2. Pass it straight through to the base call.

## AVOID
- Do not "fix" it by adding a second overload with `params` alongside the
  non-`params` override — now overload resolution differs by static type; just
  put `params` on the override.
- Do not change the parameter type to `IEnumerable<int>` — that's a different
  signature and no longer an override at all.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

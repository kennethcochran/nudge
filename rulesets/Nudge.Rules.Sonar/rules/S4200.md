# S4200 — Native methods should be wrapped

## Why
A `public static extern` P/Invoke method exposes raw interop: no argument
validation, no error-code translation, no safe-handle discipline — and every
caller re-implements (or skips) the marshaling care independently. One managed
wrapper centralizes it.

## Do this
1. Make the `DllImport` method `private`.
2. Add a `public` (or `internal`) managed wrapper that validates arguments,
   calls the native method, checks return codes /
   `Marshal.GetLastWin32Error()`, and translates failures into exceptions.
3. Prefer `SafeHandle` over raw `IntPtr` in the wrapper's signature.

## AVOID
- Do not "fix" it by changing `public` to `internal` — the raw native method
  is still directly callable; it must be `private` behind a wrapper.
- Do not add the wrapper but leave the extern method public "for advanced
  callers" — that public surface is exactly the exposure the rule flags.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

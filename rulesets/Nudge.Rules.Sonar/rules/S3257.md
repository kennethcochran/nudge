# S3257 — Declarations and initializations should be as concise as possible

## Why
int i; ... i = 5; — declaring a variable and initializing it in a separate
statement adds a line and a moment where the variable holds a meaningless
value. This rule flags declarations that can be merged with their
initialization.

## Do this
1. Merge: int i = 5; — declare the variable at the point where you have the value.
2. If the value isn't available at the declaration, the declaration is too early — move it down to first use.
3. Watch for the '= null' / '= default' placeholder initialization; it is the most common instance of this pattern.

## AVOID
- There is no meaningful dodge for this rule — merging is the fix. Do not 'merge' by initializing with a dummy value at declaration and reassigning later; that is the pattern the rule wants gone.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1698 — "==" should not be used when "Equals" is overridden

## Why
If a type overrides `Equals` but not `==`, then `a == b` silently performs
reference equality while `a.Equals(b)` performs value equality — two spellings
of "equality" that disagree, a trap for every future reader of the code.

## Do this
1. At the flagged site, prefer the explicit `.Equals()` call so the value
   semantics are visible, or
2. Overload `==` (along with `!=`, plus `Equals` and `GetHashCode` to match) on
   the type so both spellings agree — then the inconsistency is fixed
   structurally.

## AVOID
- Do not cast to `object` before comparing (`(object)a == (object)b`) to force
  reference equality and dodge the rule. If reference equality is truly what
  you want, say so with `ReferenceEquals(a, b)` — the cast is a hidden
  semantic change, not a fix.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

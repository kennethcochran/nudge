# S4041 — Type names should not match namespaces

## Why
A type named the same as its namespace (`Foo.Foo`)
creates ambiguity at every use site: `Foo` could mean the namespace or
the type, IDE resolution gets confused, and readers have to disambiguate
in their heads. It usually happens when a namespace grows around a
"main" class that took the namespace's name.

## Do this
1. Rename the type or the namespace so the simple name is
   unambiguous — rename whichever one carries less meaning (often the
   namespace can gain a suffix like `.Core`, or the type a suffix like
   `Service`/`Manager`).
2. Update all references, including `using` aliases and fully qualified
   names.
3. Check for the same collision pattern in sibling namespaces while
   you're at it.

## AVOID
- Do not "fix" it with a `using` alias at one use site — the
  ambiguity is still in the codebase for every other reader and every
  future use site. Rename the type or the namespace.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

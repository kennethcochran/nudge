# S4275 — Getters and setters should access the expected fields

## Why
`public int Width { get => height; set => width = value; }` — the getter reads
a different backing field than the setter writes. Reads return stale or wrong
data; it's a copy-paste bug that compiles cleanly and fails silently, often
only surfacing as mysteriously wrong UI values or state.

## Do this
1. Point the getter and setter at the same backing field.
2. If each accessor intentionally touches different state, that's not a
   property — split it into methods whose names say what they do.
3. Prefer auto-properties (`{ get; set; }`) where there's no extra logic —
   with no explicit field, there's nothing to mismatch.

## AVOID
- Do not "fix" it by making the setter write *both* fields to "keep them in
  sync" — you've hidden the mismatch instead of resolving which field the
  property actually owns.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

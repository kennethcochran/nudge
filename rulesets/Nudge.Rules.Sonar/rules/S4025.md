# S4025 — Child class fields should not differ from parent class fields only by capitalization

## Why
A derived field `value` hiding a base field `Value` means `this.value` and `((Base)this).Value` are different storage: assignments go to one, reads come from the other, and the bug is invisible at every call site. Case-only shadowing is a trap, not a feature.

## Do this
1. Rename the derived field so it no longer shadows — or delete it if it was meant to *be* the base field, and use the base one.
2. Search for all uses of both names and verify each now resolves to the intended storage.

## AVOID
- Do not add `new` to the derived field to "declare" the hiding — the dual-storage trap remains for every reader and every future edit.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3358 — Ternary operators should not be nested

## Why
Nested `?:` reads right-to-left through multiple condition/result pairs with
no visual structure — `a ? b : c ? d : e` forces the reader to parenthesize
mentally, and the branch that "looks" attached to the inner condition is
easy to misread. Misreading a nested ternary in review is how inverted
logic ships.

## Do this
1. Rewrite as an `if` / `else if` / `else` chain when the branches assign or
   return different values.
2. If the expression chooses among several values, use a `switch`
   expression instead — each arm is labeled and ordered.
3. If one branch's condition is itself a meaningful concept, extract it into
   a well-named boolean method or local so the remaining ternary is flat.

## AVOID
- Do not add parentheses and reformat across lines and call it fixed —
  `a ? b : (c ? d : e)` is still a nested ternary, just a prettier one.
- Do not flatten it with `&&` / `||` tricks that preserve the nesting logic
  in a less readable form.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

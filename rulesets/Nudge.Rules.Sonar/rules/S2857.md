# S2857 — SQL keywords should be delimited by whitespace

## Why
SQL built by string concatenation without whitespace
around keywords produces `"...FROM" + table` → `"...FROMtable"` —
invalid SQL at best. But the missing space is a symptom; the disease is
concatenating runtime values into SQL text at all, which is also how
injection happens.

## Do this
1. Replace the concatenated SQL with a parameterized query: the SQL
   text is fixed, values travel as parameters.
2. If you must build SQL text dynamically (dynamic table/column names),
   validate each fragment against an allowlist of known identifiers —
   never embed raw input.
3. The whitespace fix alone is not the fix; parameters are.

## AVOID
- Do not "fix" it by just adding the missing space while still
  concatenating untrusted input into the SQL string — the syntax is
  fixed but the injection hole is wide open. Parameterize.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

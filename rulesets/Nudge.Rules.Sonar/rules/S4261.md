# S4261 — Methods should be named according to their synchronicities

## Why
A `Task`-returning method without the `Async` suffix lies about its contract:
callers can't tell at a glance whether it completes synchronously or must be
awaited, and the resulting sync-over-async mistakes (`.Result` deadlocks,
unawaited tasks) follow from that ambiguity.

## Do this
1. Rename `Task`/`Task<T>`-returning methods to end in `Async`.
2. Use the IDE's rename refactoring so every call site, override, and
   interface member follows.
3. Keep a non-suffixed name only for the rare method that returns a `Task`
   but genuinely completes synchronously *by contract* — and document why.

## AVOID
- Do not rename only the flagged method while its siblings keep sync-style
  names — if `Load` became `LoadAsync`, its partner `Save` needs the same
  treatment; apply the convention to the whole API surface, not the one line
  the analyzer saw.
- Do not "fix" it by changing the return type to `void` and blocking inside —
  you've traded a naming lie for a deadlock hazard.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

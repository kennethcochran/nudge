# S3169 — Multiple "OrderBy" calls should not be used

## Why
`OrderBy(a).OrderBy(b)` doesn't sort by a-then-b — the second `OrderBy`
*re-sorts from scratch*, discarding the first ordering (modulo sort stability).
The first call is wasted work, and the code misleads readers into thinking both
keys apply.

## Do this
1. Replace the second (and any further) `OrderBy` with
   `ThenBy`/`ThenByDescending`: `OrderBy(a).ThenBy(b)`.
2. Keep the key selectors exactly as they were — only the method name changes.
3. If you truly want only the last key's ordering, delete the earlier `OrderBy`
   calls instead of leaving them.

## AVOID
- Do not "merge" the keys into one composite key (`OrderBy(x => (x.A, x.B))`)
   as the fix — tuple comparison has subtly different null-handling and
   comparer semantics than `OrderBy(A).ThenBy(B)`; use `ThenBy`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

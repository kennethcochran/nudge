# S3994 — URI Parameters should not be strings

## Why
A `string url` parameter accepts anything — malformed input, wrong schemes,
injection payloads — and every method in the chain re-validates (or doesn't).
`System.Uri` parses and validates once, at the boundary, and carries the
parsed structure with it.

## Do this
1. Change the parameter type to `System.Uri` (or `Uri?` where absence is
   valid).
2. Parse at the entry point with `Uri.TryCreate` / `new Uri(...)`, rejecting
   invalid input there with a clear error.
3. Push the `Uri` type through internal call chains so validation isn't
   repeated — or skipped — downstream.

## AVOID
- Do not keep the `string` parameter and parse it into a `Uri` as the first
  line of the method. Validation then happens per call site instead of once at
  the boundary, and every other method taking the string stays unprotected —
  the type change is the fix.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

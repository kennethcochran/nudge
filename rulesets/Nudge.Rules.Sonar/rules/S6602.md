# S6602 — "Find" method should be used instead of the "FirstOrDefault" extension

## Why
`FirstOrDefault(e => e.Id == key)` on a set with a key
lookup (EF `DbSet`, `List<T>`, …) does a linear scan with a predicate,
while `Find(key)` uses the key directly — hitting the identity map /
change tracker in EF instead of issuing a query, and short-circuiting
by key for in-memory collections. The predicate version is slower and
(in EF) can hit the database when the entity is already tracked.

## Do this
1. Replace `.FirstOrDefault(e => e.Id == key)` with `.Find(key)` (or
   `FindAsync` in async code).
2. Confirm the lambda was a pure key comparison — if it had extra
   conditions, `Find` isn't equivalent; restructure so the key lookup
   happens first.
3. Handle the null result the same way the old code handled a missing
   entity.

## AVOID
- Do not wrap the `FirstOrDefault` predicate in your own extension
  method named `Find` — the rule is about using the provider's key
  lookup (identity map / index), not about the method name.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3884 — "CoSetProxyBlanket" and "CoInitializeSecurity" should not be used

## Why
**This rule is deprecated and will be removed.** It targeted COM security
initialization calls that are vanishingly rare in modern .NET, where COM
interop itself is a legacy concern. If this fires, you are in interop code
old enough that the rule's advice predates the framework you are actually on.

## Do this
1. Nothing, unless you are actively writing new COM interop — in which case
   the question is why, not how the security call is spelled.
2. If the rule fires in CI on legacy interop code, remove S3884 from the
   active profile rather than touching working interop code.

## AVOID
- Do not "modernize" COM security initialization to satisfy a deprecated
  rule. Interop security calls are load-bearing; changing their spelling
  without understanding the COM security model risks breaking authentication
  in ways no test will catch.
- Do not suppress per-occurrence; fix the rule profile once.

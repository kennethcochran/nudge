# S1172 — Unused method parameters should be removed

## Why
A parameter nobody reads is a lie in the signature: it promises the caller
influence it doesn't have, and forces every call site to supply a value for
nothing. Usually it's a leftover from a refactor. This rule flags parameters
never used in the body.

## Do this
1. If the parameter is truly dead, remove it and update the call sites — that is the whole fix.
2. If an override or interface implementation must keep the signature, rename the parameter to _ (discard) and, if the reason isn't obvious, leave a comment saying why the slot exists.
3. Check whether the parameter should be used — sometimes the flag means a missing feature, not a redundant parameter.

## AVOID
- Do not 'use' the parameter with a no-op (_ = param, or Debug.Assert(param is not null)) just to make the diagnostic go away — the signature still lies and every caller still passes a meaningless value.
- Do not comment out the parameter name but leave the type; the clutter remains.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

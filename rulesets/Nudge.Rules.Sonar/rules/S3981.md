# S3981 — Collection sizes and array length comparisons should make sense

## Why
Comparisons like `list.Count < 0` or `span.Length < 0` can never be true —
counts and lengths are never negative. A branch guarded by one is dead code,
and its presence means the author believed something false about the values
involved. That false belief usually points at a real bug nearby: the wrong
collection, the wrong comparison, or inverted logic.

## Do this
1. Work out what was actually meant: an emptiness check? A capacity check?
   A "has items" check?
2. Write the comparison that means it (`Count == 0`, `Count > 0`).
3. If the branch is genuinely dead, delete it rather than leaving a
   condition that can never fire.

## AVOID
- Do not "fix" `Count < 0` by flipping it to `Count <= 0` without deciding
  the intent. If the author meant "has items," the fix is `Count == 0`
  (or `!Any()`), not a tautology that is always true.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

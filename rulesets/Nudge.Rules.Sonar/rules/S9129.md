# S9129 — "Include" and "ThenInclude" chains of reference navigations should be merged into a single "Include" call

## Why
In EF Core, `.Include(a => a.B).ThenInclude(b => b.C)` over reference
(non-collection) navigations can be written as one
`.Include(a => a.B.C)`. The two-call form is pure ceremony: same query, more
noise, harder to read at a glance.

## Do this
1. Replace the `Include(...).ThenInclude(...)` chain with a single `Include`
   using the dotted navigation path: `.Include(a => a.B.C)`.
2. Keep `ThenInclude` only where it's required — after a *collection*
   navigation, where the dotted path can't express the shape.
3. Re-run the query tests to confirm the generated SQL and the loaded graph are
   unchanged.

## AVOID
- Do not "merge" by dropping one of the navigations from the query —
   eager-loading less data to satisfy the rule changes behavior; merge the
   calls, don't delete the navigation.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

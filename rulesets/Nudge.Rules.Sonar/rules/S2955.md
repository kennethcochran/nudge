# S2955 — Generic parameters not constrained to reference types should not be compared to "null"

## Why
`item == null` on an unconstrained `T` boxes value types, and for a
non-nullable struct the boxed value is never null — so the check is dead
logic masquerading as a guard. The comparison compiles for every `T` but is
only meaningful for some, which is exactly how subtle bugs survive review.

## Do this
1. If `T` is always a reference type, say so: add `where T : class` (or
   `class?`) and the comparison becomes honest.
2. Otherwise use `EqualityComparer<T>.Default.Equals(item, default)` — it
   handles reference and value types correctly with no boxing.
3. `is null` avoids the boxing but is still never true for non-nullable
   value types; prefer the comparer or the constraint.

## AVOID
- Do not silence the diagnostic with the null-forgiving operator
  (`item!`). It keeps the meaningless comparison and adds a false claim of
  non-nullness on top.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1168 — Empty arrays and collections should be returned instead of null

## Why
Returning null for "no results" forces every caller to null-check; the one
caller that forgets gets a `NullReferenceException`. An empty collection is
honest — `foreach`, LINQ, and `.Count` all just work, and "no results" needs
no special case anywhere.

## Do this
1. Return `Array.Empty<T>()`, `Enumerable.Empty<T>()`, or a cached empty
   collection instead of null at the flagged return.
2. Update the method's documentation/contract to state it never returns null.
3. Simplify the callers that were null-checking, and consider nullable
   annotations so the compiler enforces the contract going forward.

## AVOID
- Do not keep the null return and "fix" the call sites with `!` — the null is
   still produced, and every future caller inherits the trap. Return the empty
   collection at the source.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

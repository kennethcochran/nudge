# S3604 — Member initializer values should not be redundant

## Why
int _count = 0; as a field initializer, or a constructor assignment that
repeats the initializer's value — the redundancy is a future divergence
point: someone changes one and not the other, and the effective value depends
on initialization-order trivia. This rule flags initializers that restate the
default or duplicate each other.

## Do this
1. Keep one source of truth: field initializer or constructor assignment, not both; drop initializers that just restate the type default (= 0, = null, = false).
2. When constructors must differ, chain them (: this(...)) so the initialization logic lives in exactly one place.

## AVOID
- Do not move the redundant value into a const and assign it in both places — the duplication of assignment sites is the problem, not the literal.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

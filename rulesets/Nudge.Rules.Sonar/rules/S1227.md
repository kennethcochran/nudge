# S1227 — break statements should not be used except for switch cases

## Why
**This rule is deprecated and will be removed.** It was written when
`break` outside `switch` was considered harmful; modern guidance accepts
early-exit `break` as clearer than deeply nested conditionals. The rule
firing on your code is not a signal about your code — it is a signal that
the rule set is stale.

## Do this
1. Nothing. A deprecated rule's finding is not actionable; do not
   restructure working code to satisfy a rule SonarSource itself has retired.
2. If the rule fires in CI and blocks builds, the correct fix is at the
   rule-set level: remove S1227 from the active profile, not at the code level.

## AVOID
- Do not rewrite loops to avoid `break` just to silence this. Converting a
  clean early-exit into nested flags or duplicated conditions makes the code
  worse to satisfy a dead rule — that is metric gaming against a metric
  nobody defends.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`
  per-occurrence; fix the profile once instead of annotating every loop.

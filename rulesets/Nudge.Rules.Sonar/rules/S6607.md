# S6607 — The collection should be filtered before sorting by using "Where" before "OrderBy"

## Why
`.OrderBy(...).Where(...)` sorts the *entire* collection and then throws
most of it away; `.Where(...).OrderBy(...)` sorts only the survivors.
Sorting is typically O(n log n), so filtering first is strictly less work —
and for database-backed `IQueryable`s it also produces a cheaper query
plan.

## Do this
1. Move the `Where` call before the `OrderBy` / `OrderByDescending` (and
   before any `ThenBy` chain attached to it).
2. Re-check the ordering semantics: `Where` doesn't reorder, so the final
   sequence is identical — only the work shrinks.
3. If the `Where` predicate depends on the sort (it shouldn't — predicates
   see elements, not positions), restructure rather than reorder.

## AVOID
- Do not "optimize" by inserting `.AsParallel()` around the sort —
  parallelism doesn't fix doing unnecessary work, and it changes ordering
  guarantees.
- Do not merge the filter into the key selector
  (`OrderBy(x => predicate(x) ? 0 : 1)`) to keep one call; that sorts
  instead of filtering and keeps the dead elements.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

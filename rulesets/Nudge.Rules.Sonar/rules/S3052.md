# S3052 — Members should not be initialized to default values

## Why
Explicitly initializing a member to its default value
(`int x = 0;`, `string s = null;`, `bool b = false;`) is noise: fields
and locals already start at the default, so the initializer states the
obvious while suggesting the value was a deliberate choice worth
noticing. It wasn't — it's just the default.

## Do this
1. Delete the redundant initializer.
2. If the "default" value is actually meaningful to the logic (a
   deliberate starting point, not just the type default), say so in a
   comment or give it a named constant — don't rely on `= 0` to
   communicate intent.
3. Don't confuse this with initializers that set non-default values;
   those stay.

## AVOID
- Do not replace `= 0` with `= default` or `= default(int)` — same
  redundant initializer, new spelling. Delete it.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2327 — "try" statements with identical "catch" and/or "finally" blocks should be merged

## Why
Two try blocks with identical catch (or finally) bodies are one
error-handling policy written twice: a fix to the policy gets applied to one
copy and forgotten in the other. This rule flags try statements whose
handlers are duplicates.

## Do this
1. Merge: put both guarded regions in a single try with the shared handler, if they genuinely share one policy.
2. If the regions need different handling after all, that's information — differentiate the handlers for real instead of duplicating them.
3. After merging, confirm the caught exception types still match what each region can throw.

## AVOID
- Do not introduce a trivial difference between the handlers (an extra comment, a reordered statement) to make them 'not identical' — the duplication remains and you've only blinded the detector.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

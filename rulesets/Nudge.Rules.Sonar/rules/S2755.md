# S2755 — XML parsers should not be vulnerable to XXE attacks

## Why
An XML parser with DTD processing enabled resolves external entities — a
malicious document can read local files (`file:///etc/passwd`), trigger
server-side request forgery, or detonate a billion-laughs DoS. .NET's XML APIs
have historically resolved DTDs unless told not to, so the safe settings must
be applied explicitly at every parse site.

## Do this
1. Build the reader with
   `new XmlReaderSettings { DtdProcessing = DtdProcessing.Prohibit }` (use
   `Ignore` only if you must tolerate DTDs; never `Parse`).
2. Set `XmlResolver = null` on the settings / `XmlDocument` so external
   resources can never be fetched.
3. Apply the same settings at every XML parse site — search for
   `XmlReader.Create`, `new XmlDocument()`, `XDocument.Load`, `XmlSerializer`
   inputs.
4. Test with a malicious XXE payload and confirm the parse fails or ignores
   the entity instead of resolving it.

## AVOID
- Do not "fix" it by regex-stripping `<!DOCTYPE` from the input before
   parsing — malformed-XML bypasses are easy and the next parser call site
   won't have the regex. Disable DTD processing in the parser settings
   themselves.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3441 — Redundant property names should be omitted in anonymous classes

## Why
In `new { Name = person.Name }`, the `Name =` is pure repetition — C#'s
projection initializers already infer the property name from the member
access. The redundant name is a second place that must be updated on
rename, and it visually suggests the name differs from the source member
when it doesn't.

## Do this
1. Drop the explicit name: `new { person.Name, person.Age }`.
2. Keep the explicit name only where it differs from the member
   (`new { FullName = person.Name }`) — that's the case the syntax exists
   for.
3. After the change, check downstream consumers reference the same property
   names — with projection initializers they do, by construction.

## AVOID
- Do not "simplify" by renaming the source member to match instead; the
  anonymous type is the disposable side, not the domain model.
- Do not replace the anonymous type with a `ValueTuple` to dodge the rule;
  that changes the member names to `Item1`, `Item2` for every consumer.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

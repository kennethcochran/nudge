# S3440 — Variables should not be checked against the values they're about to be assigned

## Why
`if (x == 5) x = 5;` — the check is vacuous: either the assignment is redundant, or the condition was meant to compare against something else. A comparison against the imminent assigned value signals a logic error (wrong variable, wrong value) disguised as a guard.

## Do this
1. Read the surrounding logic and determine the actual intent.
2. If the assignment is unconditional, delete the check. If the check was meant to guard a *different* value or variable, fix the comparison.
3. Don't leave both in place — one of them is wrong.

## AVOID
- Do not "fix" it by assigning a different value inside the branch to make the check "meaningful" — that invents behavior to satisfy the analyzer; determine the actual intent first.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

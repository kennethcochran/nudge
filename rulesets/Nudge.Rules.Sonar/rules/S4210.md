# S4210 — Windows Forms entry points should be marked with STAThread

## Why
WinForms — and COM interop generally: clipboard, drag-and-drop, common
dialogs, OLE — requires a single-threaded apartment. Without `[STAThread]` on
`Main`, these calls fail or misbehave at runtime, often intermittently and
far from any useful error message.

## Do this
1. Add `[STAThread]` to the `Main` entry-point method.
2. Rebuild and smoke-test the UI paths that touch the clipboard, dialogs, or
   drag-and-drop.

## AVOID
- This rule is nearly mechanical: the complete fix is the attribute on
   `Main`. Do not try to set the apartment state manually on the main thread
   instead — the attribute is the supported mechanism.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

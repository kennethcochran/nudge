# S6575 — Use "TimeZoneInfo.FindSystemTimeZoneById" without converting the timezones with "TimezoneConverter"

## Why
The TimeZoneConverter NuGet package existed to map IANA to Windows time-zone
IDs on .NET Framework, where `TimeZoneInfo` only understood Windows IDs.
Modern .NET resolves IANA IDs natively on all platforms — the package is now a
dead dependency adding versioning and supply-chain surface for zero benefit.

## Do this
1. Replace `TimeZoneConverter.TZConvert.GetTimeZoneInfo(id)` with
   `TimeZoneInfo.FindSystemTimeZoneById(id)`.
2. Remove the TimeZoneConverter package reference from the project.
3. Run the time-zone-related tests on your target platforms (Linux CI counts)
   to confirm the IDs resolve.

## AVOID
- Do not wrap the `TZConvert` call in your own helper to hide it from the rule
   — the dependency is still there; remove the call and the package.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

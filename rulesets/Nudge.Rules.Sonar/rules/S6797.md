# S6797 — Blazor query parameter type should be supported

## Why
`[SupplyParameterFromQuery]` only binds a fixed set of types (primitives,
`string`, `Guid`, `DateTime`, enums, and arrays of those). A property of any
other type silently fails to bind — the parameter just stays at its default
with no error, so the component runs on data the URL never provided.

## Do this
1. Change the property to a supported type — usually `string` — and bind
   that.
2. Convert to your domain type explicitly in `OnParametersSet` /
   `OnInitialized`, handling parse failure with a clear fallback or error.
3. Test the component with the query string present, absent, and malformed.

## AVOID
- Do not "fix" it by attaching a custom `TypeConverter` and hoping the
   binder picks it up — the supported-type list is fixed and the silent
   default remains the failure mode. Bind a supported type and convert
   explicitly.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

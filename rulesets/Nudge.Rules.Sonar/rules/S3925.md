# S3925 — "ISerializable" should be implemented correctly

## Why
`ISerializable` has a strict contract: a `[Serializable]` class must provide
`GetObjectData` *and* a deserialization constructor with the exact signature
`(SerializationInfo, StreamingContext)`, and a derived class must call
`base.GetObjectData` and chain the base constructor. A half-implemented
`ISerializable` compiles fine but throws `SerializationException` at runtime
— or worse, silently drops base-class state during deserialization.

## Do this
1. Add `[Serializable]` to the class if missing.
2. Implement `GetObjectData(SerializationInfo info, StreamingContext
   context)`, calling `base.GetObjectData(info, context)` when there's a
   serializable base, and persist every field you need back with
   `info.AddValue`.
3. Add the deserialization constructor
   `protected C(SerializationInfo info, StreamingContext context) :
   base(info, context)`, reading the values back in.
4. Round-trip test: serialize and deserialize an instance and assert all
   state survives.

## AVOID
- Do not add a deserialization constructor with the wrong signature
  (public, or missing `StreamingContext`) — the formatter looks for the
  exact protected signature and will still throw.
- Do not implement `GetObjectData` without chaining the base constructor
  and base call; base-class fields silently vanish on deserialize.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

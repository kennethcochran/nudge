# S2631 — Regular expressions should not be vulnerable to Denial of Service attacks

## Why
Nested quantifiers like `(a+)+$` or `(x+x+)+y` make the regex engine try an
exponential number of backtracking paths on non-matching input — a few dozen
characters of hostile input can pin a thread at 100% CPU indefinitely. Any
regex evaluated against untrusted text (request bodies, file names, log lines)
is an attack surface.

## Do this
1. Rewrite the pattern to eliminate nested or adjacent quantifiers over
   overlapping character classes — e.g. `(a+)+` collapses to `a+`.
2. If the pattern can't be simplified safely, use `RegexOptions.NonBacktracking`
   (.NET 7+) for patterns it supports.
3. As defense in depth, pass a match timeout —
   `new Regex(pattern, RegexOptions.None, TimeSpan.FromMilliseconds(100))` —
   so pathological input fails fast instead of hanging the thread.
4. Add a regression test that feeds the known-evil input and asserts it
   completes quickly.

## AVOID
- Do not just slap on a generous timeout (seconds, not milliseconds) and keep
  the catastrophic pattern — you've converted a hang into a slow burn that
  still eats a thread per request.
- Do not "fix" it by anchoring the pattern or tweaking one character class
  cosmetically without verifying the nested quantification is actually gone —
  re-test with the evil input.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2737 — "catch" clauses should do more than rethrow

## Why
`catch (Exception ex) { throw; }` adds nothing — the exception propagates
identically without the clause. The common variant `catch { throw ex; }` is
actively harmful: rethrowing the caught variable resets the stack trace,
destroying the original call-site information you need to debug the failure.

## Do this
1. If the catch block only rethrows, delete the entire `catch` clause.
2. If the intent was logging or cleanup, put that work inside the catch (then
   rethrow with a bare `throw;`, never `throw ex;`), or use an exception
   filter (`catch (...) when (...)`).
3. Re-run the tests covering that path to confirm behavior is unchanged.

## AVOID
- Do not "fix" it by adding a no-op statement (an empty log call, a comment)
   inside the catch — a catch that exists only to exist is still dead weight.
   Remove it.
- Do not change a bare `throw;` into `throw ex;` — that resets the stack
   trace and makes the original failure harder to diagnose.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

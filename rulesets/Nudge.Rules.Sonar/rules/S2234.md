# S2234 — Arguments should be passed in the same order as the method parameters

## Why
Positional arguments in the wrong order — two strings swapped, two ints
transposed — compile fine and corrupt data silently. The type system can't
save you when the swapped arguments share a type; only the order carries the
meaning.

## Do this
1. Reorder the arguments at the call site to match the parameter list.
2. Where confusion is likely (several same-type parameters in a row), switch
   to named arguments at the call site so the pairing is explicit.
3. If the method keeps attracting transposed calls, consider whether it should
   take a small parameter object instead of a long positional list.

## AVOID
- Do not "fix" it by reordering the method's *parameters* to match the wrong
  call — the declaration is the contract; every other caller then breaks
  silently.
- Do not swap two arguments and eyeball it — re-read the parameter names at
  the declaration; transposition bugs love a second transposition.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

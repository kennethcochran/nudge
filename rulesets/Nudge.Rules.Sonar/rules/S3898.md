# S3898 — Value types should implement "IEquatable<T>"

## Why
Without `IEquatable<T>`, every `Equals` call on your struct goes through the
`object` overload and boxes the value — one allocation per comparison. In a
`Dictionary` or `HashSet` that tax is paid on every probe. Implementing
`IEquatable<T>` keeps equality type-safe and allocation-free.

## Do this
1. Implement `IEquatable<T>.Equals(T other)` comparing the fields that define
   identity.
2. Override `Equals(object)` to delegate to the typed implementation.
3. Override `GetHashCode()` consistently with the equality definition.
4. Consider adding `==` and `!=` operators for usability.

## AVOID
- Do not "fix" this by converting the struct to a class. That changes copy
  semantics, heap allocation behavior, and nullability everywhere the type
  is used — implement the interface instead.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

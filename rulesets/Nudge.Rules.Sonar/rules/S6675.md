# S6675 — "Trace.WriteLineIf" should not be used with "TraceSwitch" levels

## Why
`Trace.WriteLineIf(traceSwitch.TraceError, msg)` double-filters: the
`TraceSwitch` level property already gates, and listeners filter by level
again — so the `WriteLineIf` condition is redundant machinery around what
`Trace.TraceError(msg)` does natively. It also evaluates the message eagerly.

## Do this
1. Use the level-specific methods — `Trace.TraceError(msg)`,
   `Trace.TraceWarning(msg)`, `Trace.TraceInformation(msg)` — which consult the
   switch and the listeners correctly.
2. If you need a custom condition unrelated to levels, keep `WriteLineIf` but
   pass a real boolean condition, not a `TraceSwitch` level property.

## AVOID
- Do not "fix" it by wrapping in `if (traceSwitch.TraceError)
  Trace.WriteLine(msg)` — same double-filtering, manual edition.
- Do not cache `traceSwitch.TraceError` in a local bool to dodge the
  diagnostic — the redundancy is the problem, not the property access.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S2925 — "Thread.Sleep" should not be used in tests

## Why
`Thread.Sleep(2000)` makes tests slow and flaky — too short on a loaded CI
agent (flakes), too long everywhere else (wasted minutes across the suite). It
sleeps for wall-clock time instead of waiting for the actual condition to
become true.

## Do this
1. Wait for the condition with a timeout: poll in a loop with a short delay,
   or use your framework's eventually/wait helpers.
2. If testing async code, `await` the task instead of sleeping past it.
3. If you control the code under test, inject a signal
   (`TaskCompletionSource`, `ManualResetEventSlim`) the test can wait on
   deterministically.

## AVOID
- Do not "fix" it with `Task.Delay(2000).Wait()` or
  `.GetAwaiter().GetResult()` — that's the same fixed sleep wearing async
  clothes, and it can deadlock.
- Do not just shorten the sleep until CI stops flaking — the flakiness is
  structural; wait on the condition instead of the clock.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

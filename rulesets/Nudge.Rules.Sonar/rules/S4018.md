# S4018 — All type parameters should be used in the parameter list to enable type inference

## Why
A generic method with a type parameter that appears nowhere in its parameter
list forces callers to specify the type explicitly (`M<int>(x)`) — defeating
type inference, the main ergonomic benefit of generic methods. The unused
parameter is a sign the signature doesn't match the method's real shape.

## Do this
1. If the type parameter is genuinely unneeded, remove it and use the
   concrete type (or a non-generic signature).
2. If callers truly must specify the type (it appears only in the return
   type), consider whether the design is right — explicit specification may be
   the honest API, in which case document why.
3. Update call sites to drop type arguments that are now inferable.

## AVOID
- Do not "fix" it by adding a dummy parameter of that type just to enable
   inference — a parameter nobody uses is a lie in the signature. Remove the
   type parameter or redesign the method.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S7714 — XSLT Transformations should not be vulnerable to injection attacks

## Why
XSLT stylesheets can embed C# script blocks (`<msxsl:script>`) and call the
`document()` function to pull in external XML. Loading an attacker-controlled
stylesheet with script or the document function enabled turns the transform
into arbitrary code execution or server-side file exfiltration. The rule fires
when `XsltSettings` enables either capability for XSLT you don't fully control.

## Do this
1. Load stylesheets with the defaults — `new XslCompiledTransform().Load(path)`
   already disables script and `document()` — and leave them disabled.
2. If `document()` is genuinely needed, supply a locked-down `XmlResolver`
   that resolves only from an allowlisted directory, never from the network.
3. Only ever enable script blocks for stylesheets that live in your own source
   control, are code-reviewed, and are never assembled from user input.

## AVOID
- Do not "fix" it by switching to the obsolete `XslTransform` — it has the
  same exposure and adds deprecation debt on top.
- Do not enable `EnableScript = true` "temporarily" to get a stylesheet working
  and leave it on for stylesheets that arrive from outside your codebase.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

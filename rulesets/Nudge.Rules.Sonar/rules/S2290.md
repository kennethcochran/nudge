# S2290 — Field-like events should not be virtual

## Why
A `public virtual event` lets a derived class override the event and subtly
change add/remove semantics: subscribers added through a base-class reference
can be silently dropped by an override that doesn't chain, and the
compiler-generated backing field doesn't participate in polymorphism the way
callers expect. The extensibility point is in the wrong place.

## Do this
1. Remove `virtual` from the event declaration.
2. If derived classes need to customize notification, expose a `protected
   virtual OnXxx` raiser method instead — that is the extensibility point that
   doesn't break subscribers.
3. Rebuild and run the tests covering event subscription.

## AVOID
- Do not "fix" it by overriding the event in the derived class with
   `override` and re-implementing add/remove — that pattern is exactly what
   the rule flags as fragile. Remove `virtual` from the base event.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1135 — Track uses of "TODO" tags

## Why
`TODO` is an IOU with no due date: it rots in the codebase while the underlying problem persists, and future readers can't tell whether it's still relevant. This rule is informational — it asks that TODOs be tracked somewhere accountable, not that the tag be hidden.

## Do this
1. Read the TODO and decide: still needed, or obsolete?
2. If needed and small, do the work now. If larger, file it in the issue tracker and reference the ticket in the comment — or delete the comment if the tracker is the record.
3. If obsolete, delete the comment.

## AVOID
- Do not reword the TODO (`TODO` → `FIXME`, `HACK`, `NOTE:`) to make the tag disappear while the work remains undone.
- Do not delete the comment while silently leaving the known problem in place — track it or fix it.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

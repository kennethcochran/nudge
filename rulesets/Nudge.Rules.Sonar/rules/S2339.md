# S2339 — Public constant members should not be used

## Why
`public const` values are baked into every referencing
assembly at compile time. Change the constant later and old callers
keep using the stale value until they recompile — a versioning hazard
that's invisible in code review. `static readonly` is read from your
assembly at runtime, so updates propagate.

## Do this
1. Change `public const` to `public static readonly` (or expose it
   via a property) for any value other assemblies consume.
2. Rebuild the referencing assemblies so nothing still holds a baked-in
   copy of the old value.
3. Keep `const` only for values that are truly, forever fixed and
   internal to the assembly.

## AVOID
- Do not keep the `const` but make it private while other assemblies
  still need the value — that breaks them; the fix is `static readonly`,
  not narrower visibility.
- Do not duplicate the literal in each caller instead — that recreates
  the stale-copy problem by hand.

- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

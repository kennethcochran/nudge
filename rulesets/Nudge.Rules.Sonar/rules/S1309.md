# S1309 — Track uses of in-source issue suppressions

## Why
This is an informational tracker, not a violation with a code fix — it fires on
every `#pragma warning disable` and `[SuppressMessage]` so suppressions stay
visible. Each suppression is a claim that the analyzer is wrong, and each one
is tech debt: it hides the underlying issue from every future analysis run and
from every reviewer who trusts a green build.

## Do this
1. For each flagged suppression, fix the underlying diagnostic properly — then
   remove the suppression once the real fix lands.
2. If you genuinely believe the analyzer is wrong, prove it: write a test or a
   comment demonstrating why, get a reviewer to agree, and keep the suppression
   narrowly scoped (specific rule ID, tightest `#pragma` region).
3. Never add a *new* suppression to make a build green — that's the build lying
   about its own health.

## AVOID
- Do not move suppressions into `GlobalSuppressions.cs` or `.editorconfig`
   severity overrides to hide them from this tracker — the debt is still
   there; you've just moved it off the report.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

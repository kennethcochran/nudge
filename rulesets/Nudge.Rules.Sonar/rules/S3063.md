# S3063 — "StringBuilder" data should be used

## Why
Building a string in a `StringBuilder` and never reading the result is pure
waste — the allocation, every `Append`, and the next reader's assumption that
the value goes somewhere. Either the value was meant to be used, or the
building was meant to be deleted.

## Do this
1. Find where the built value was meant to go and use `builder.ToString()`
   there.
2. If the value is genuinely unneeded, delete the `StringBuilder` and its
   appends entirely.
3. If it's debug scaffolding, route it through the logger instead of building
   a string nobody reads.

## AVOID
- Do not assign `builder.ToString()` to a discard (`_ = builder.ToString();`)
  — the rule is satisfied and the waste remains; the discard is a confession,
  not a fix.
- Do not "use" it by logging it at a level nobody enables just to reference
  the variable — that's the discard with extra steps.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

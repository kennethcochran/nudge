# S6800 — Component parameter type should match the route parameter type constraint

## Why
In Blazor, a route like `/orders/{id:int}` binds `id` through the `int`
constraint, but if the `[Parameter] public string Id` declares `string`, the
framework's conversion and the component's expectations disagree — producing
binding failures or silently wrong values at runtime.

## Do this
1. Read the route template's constraint (`:int`, `:guid`, `:bool`, ...).
2. Change the `[Parameter]` property type to match it exactly (`int`, `Guid`,
   `bool`).
3. If the component genuinely needs a different type, change the route
   constraint instead — one of the two must give, but they must agree.

## AVOID
- Do not "align" them by removing the route constraint (`{id}` with a string
   parameter) when the constraint was load-bearing — for example
   disambiguating overloaded routes. Match the type; don't weaken the route.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S3445 — Exceptions should not be explicitly rethrown

## Why
`throw ex;` resets the stack trace to the rethrow point, destroying the
original call stack — the one piece of information you need to diagnose the
failure. Every upstream handler and log then points at your `catch` block
instead of the real throw site.

## Do this
1. Replace `throw ex;` with a bare `throw;` — it preserves the original stack
   trace.
2. If you need to add context, wrap the exception in a new one with `ex` as
   the `InnerException`.
3. Re-run the failing path and confirm the logged stack trace now reaches the
   original throw site.

## AVOID
- Do not log `ex` and then `throw ex;` "because we already logged it" — the
  rethrown trace is still truncated for every handler above you that didn't
  see your log line.
- Do not "fix" it by throwing a new exception without the inner exception —
  that discards the original stack just as thoroughly as `throw ex;`.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

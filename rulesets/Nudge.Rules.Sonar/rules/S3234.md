# S3234 — "GC.SuppressFinalize" should not be invoked for types without destructors

## Why
`GC.SuppressFinalize(this)` tells the GC to skip finalization — but if the
type has no finalizer (`~T()`), there is nothing to skip. The call is dead
code that misleads every reader into believing unmanaged cleanup exists where
it doesn't.

## Do this
1. Delete the `GC.SuppressFinalize` call.
2. Decide which reality is true: if the type really holds unmanaged
   resources, implement the full dispose pattern (finalizer + `Dispose(bool)`
   + `SuppressFinalize` inside `Dispose()`); if not, the call was pure noise
   and deleting it is the whole fix.

## AVOID
- Do not "fix" it by adding an empty finalizer (`~T() { }`) so the call "has
   something to suppress" — an empty finalizer pointlessly promotes the
   object a GC generation and hurts performance. Delete the call.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

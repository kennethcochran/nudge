# S5883 — OS commands should not be vulnerable to argument injection attacks

## Why
When a command line is assembled by string concatenation and handed to a
shell (UseShellExecute = true, cmd /c, or a single command string), a
metacharacter in user input (;, &&, |, $()) escapes the intended argument and
runs attacker-chosen commands. This rule fires when user-controlled values flow
into OS command execution as injectable arguments.

## Do this
1. Set UseShellExecute = false and pass arguments via ProcessStartInfo.ArgumentList, which hands each argument to the OS without shell parsing — no metacharacter interpretation at all.
2. If a shell is genuinely unavoidable, validate each argument against a strict allow-list (known-safe characters or a fixed set of values) before use, and fail closed on mismatch.
3. Keep the executable path fixed in code — never let input select the binary.

## AVOID
- Do not wrap the user value in hand-rolled quotes ('"' + input + '"') to silence the rule — quoting rules differ per shell and are escapable; it is the canonical cosmetic fix that stays exploitable.
- Do not blacklist a few characters (;, &) and call the input validated — allow-list instead.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

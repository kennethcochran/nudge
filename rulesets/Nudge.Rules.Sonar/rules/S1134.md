# S1134 — Track uses of "FIXME" tags

## Why
FIXME marks code that is known-broken or known-incomplete. Without tracking,
these tags rot: nobody owns them, they survive release after release, and the
broken behavior they mark ships to users indefinitely.

## Do this
1. If the fix is small, do it now and delete the tag.
2. Otherwise file a tracked work item and reference its ID next to the
   FIXME so ownership is explicit.
3. Remove the tag when the work is done — a resolved FIXME left in place is
   noise that teaches readers to ignore all of them.

## AVOID
- Do not downgrade FIXME to TODO (or reword it) to dodge the rule.
  Relabeling the debt does not pay it; it only moves it to a list nobody
  watches.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`. Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

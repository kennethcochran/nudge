# S3909 — Collections should implement the generic interface

## Why
A custom collection implementing only non-generic `IEnumerable` /
`ICollection` forces consumers through `object` — boxing for value types,
casts everywhere, no LINQ, no compile-time type safety. The generic
interfaces have existed since .NET 2.0; there's no reason to ship a new
untyped collection.

## Do this
1. Implement the generic counterpart: `IEnumerable<T>`, `ICollection<T>`,
   `IList<T>`, or `IReadOnlyList<T>`, whichever matches the collection's
   capabilities.
2. Where backward compatibility demands it, keep the non-generic members as
   explicit interface implementations delegating to the generic ones.

## AVOID
- Do not "fix" it with explicit non-generic implementations that throw
  `NotImplementedException` — you've kept the unusable surface and added a
  trap for anyone who touches it.
- Do not implement `IEnumerable<T>` but keep advertising the non-generic
  `ICollection` as the public API — consumers still get the untyped surface.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

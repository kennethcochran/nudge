# S4792 — Configuring loggers is security-sensitive

## Why
**This rule is deprecated and will be removed.** It flagged logger
configuration as security-sensitive on the theory that an attacker who
controls logging configuration can hide their tracks. In practice this is a
hotspot-style judgment call the rule cannot make — every application
configures its loggers, and the finding fires on all of them indiscriminately.

## Do this
1. Nothing, unless logger configuration actually accepts untrusted input in
   your application — in which case the issue is input validation, not the
   existence of the configuration call.
2. If the rule fires in CI on every startup path, remove S4792 from the
   active profile rather than annotating each configuration site.

## AVOID
- Do not restructure logging setup to dodge this finding. Moving
  configuration into a helper or behind indirection to silence a deprecated
  hotspot rule obscures startup code for no security benefit.
- Do not suppress per-occurrence; fix the rule profile once.

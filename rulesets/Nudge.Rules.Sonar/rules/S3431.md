# S3431 — "[ExpectedException]" should not be used

## Why
`[ExpectedException]` passes if *any* line in the test throws — including arrange and setup code — so a passing test can't tell you which operation actually threw. A test that passes for the wrong reason is worse than no test: it certifies behavior it never exercised.

## Do this
1. Remove the `[ExpectedException]` attribute.
2. Wrap the specific call under test in `Assert.Throws<ExpectedType>(() => ...)` so the expectation is scoped to that expression.
3. If the exception's message or properties matter, assert on the returned exception object.

## AVOID
- Do not replace it with a manual try/catch plus `Assert.Fail` — that's a hand-rolled, less readable `Assert.Throws`.
- Do not move the attribute onto a smaller helper method — the scoping problem (any line may throw) remains.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S907 — "goto" statement should not be used

## Why
`goto` jumps shred the visible control-flow structure — readers can't tell what
state holds at the label, and every future edit near the jump risks silently
changing which paths reach it. C# has a structured construct for every
legitimate use.

## Do this
1. Replace forward jumps out of nested blocks with early returns or extracted
   methods.
2. Replace backward jumps with `while` / `for` loops — or a small state
   machine if the flow is genuinely complex.
3. For shared cleanup on the way out, use `try/finally`; that is what it is
   for.

## AVOID
- Do not replace `goto` with a boolean flag driving a `while (true)` dispatch
  loop (`while (!done) { ... if (x) { state = 2; continue; } }`). That is goto
  with extra steps — the unstructured jump is still there, just spelled as
  loop-and-flag.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.

# S1147 — Exit methods should not be called

## Why
`Environment.Exit(code)` terminates the process immediately — `finally`
blocks don't run, `using` disposables don't dispose, buffered logs are lost.
Worse, in a library it kills the host process: callers, tests, and hosts can't
intercept it or clean up after it.

## Do this
1. Return normally: propagate a result or exit code up to `Main` and `return`
   it.
2. In libraries, throw an exception or return a failure result — never kill
   the host process from library code.
3. For fatal, unrecoverable states, log first, then let the exception
   propagate; reserve process termination for the outermost host layer.

## AVOID
- Do not "fix" it with `Environment.FailFast` — that skips even more cleanup
  (no finalizers, no error reporting) and is reserved for corrupted-state
  emergencies, not ordinary failures.
- Do not hide the `Exit` call in a helper named `Shutdown()` or `Terminate()`
  — same kill, harder to find, and the rule still applies.
- Do not suppress with `#pragma warning disable` or `[SuppressMessage]`.
  Suppression of analyzer diagnostics is forbidden by the project's AGENTS.md.
